## Главный результат: правки оркестратора чинились наполовину, три цикла подряд

`vdd-enhanced.md` §4.4 требует отдавать следующему циклу правки, внесённые оркестратором мимо
петли Developer → Reviewer, потому что они **не проходили ревью вообще**. Правило оправдалось
трижды, и каждый раз — одним и тем же способом.

| Цикл | Что заявил | Что было на самом деле | Кто нашёл |
| ---- | ---------- | ---------------------- | --------- |
| 1 | «`capability: CAPABILITY` во всех **одиннадцати** тулах» | девять; не тронуты `chain-tvl.ts` и `chain-supply.ts` — **та самая пара**, на перестановке которой дефект и демонстрировали | цикл 2, logic + slop |
| 1 | «девять докстрингов переписаны» | три модуля (`new-pairs`, `protocol-tvl`, `wallet-balances`) продолжали открываться «Registers `onchain_X`» | цикл 2, slop |
| 2 | «семнадцать файлов, не шестнадцать» — исправлено | исправлено **в одном** докстринге из трёх: `registry.ts:11` и `tool-inventory-docs.test.ts:61` остались с «sixteen» | цикл 3, slop + logic |
| 2 | «сам гейт называет **пять** тулов при пороге восемь» | **один**: число посчитано метрикой «все токены `onchain_*`», а гейт считает `namedTools()` — только зарегистрированные | цикл 3, обе линзы |

Последняя строка — обоснование, сформулированное в терминах метрики и измеренное **другой**
метрикой. Решение при этом верное (1 < 8), неверен аудиторский след.

## Самые тяжёлые находки по циклам

**Цикл 1.** Исключение `eval/checks.mjs` из гейта документов было оправдано фразой «его ключи
сверяются с реестром в `eval-capability-coverage`». Тот тест `checks` не импортирует вовсе.
Исключение держалось на предложении, а не на гейте. Заведён `eval-checks-coverage.test.ts` на обе
стороны; осиротевшая запись не ловится больше ничем — `grade()` зовётся только для тулов, которые
eval решил позвать.

**Цикл 2.** Наименьшая привилегия закрывала один канал из двух. `needs` раздаёт контекст, но не
запрещает импорт: `createBudgetStore` — публичный экспорт core. Проверено мутацией — бесплатный
`onchain_ping` строит бюджетное хранилище, открывает SQLite, **274 теста зелёные**.

**Цикл 3.** Гейт «capability объявлена один раз», написанный в цикле 2 против этого класса, сам
пропускал этот класс: регексп без флага `g` брал **первое** совпадение по файлу, поэтому любая
более ранняя строка `capability: CAPABILITY` (естественная форма — константа `CacheMeta`)
позволяла полю спеки вернуться к литералу. Воспроизведено: старый регексп читает `CAPABILITY` и
пропускает, новый читает поле спеки и падает.

## Что доказано мутацией, а не чтением

| Мутация | До правки | После |
| ------- | --------- | ----- |
| `capability: CAPABILITY` → литерал в `chain-tvl.ts` | зелено | падает, называя файл |
| ранний `capability: CAPABILITY` + литерал в спеке | **зелено** (обход) | падает |
| `onchain_ping` импортирует `createBudgetStore` | **зелено** | падает |
| символьная ссылка на fifo и `/dev/zero` в `docs/` | зависание в `open(2)` | 380 мс, пропущено |
| `cp README.md docs/out` | **зелено** (файл скрыт именем каталога) | падает, называя путь |
| переименование литерала в `eval/run.mjs` | зелено, сверка молча не запускается | падает, называя имя |
| лишний якорь `// Capability:` в `interfaces.md` | `expected 10 to be 11` | называет строку и id целиком |
