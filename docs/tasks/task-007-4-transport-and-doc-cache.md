# Task 007-4: Транспорт `fetch()` + кэш документа на экземпляр + фикстуры

## Use Case Connection

- UC-1: основной сценарий, шаг 4 (построение URL, throttle, `safeFetch`)

## RTM

**R-62** (транспорт) · **R-70** (переиспользование документа) · **R-71** (фикстуры, успешный путь)

## Task Goal

Заменить стаб `fetch('dex.volume.history')` на реальный keyless GET и не скачивать один и тот же
документ дважды за одно окно TTL.

## Changes Description

### Новые файлы

- `packages/core/test/fixtures/defillama/dexs-ethereum.json` — записанная фикстура ответа
  `/overview/dexs/ethereum?excludeTotalDataChartBreakdown=true`. **Урезанная**: полный документ —
  250 КБ и 2825 точек; в фикстуре достаточно ~120 точек, покрывающих окно теста, плюс агрегаты и
  эхо-поле `chain`. Карточки `protocols` из фикстуры **вырезать целиком** — мы их не читаем, а
  хранить 151 карточку третьей стороны в репозитории незачем.
- `packages/core/test/fixtures/defillama/dexs-empty-chain.json` — ответ вида `litecoin`:
  HTTP 200, `total24h: 0`, `change_1d: null`, **узкий набор ключей** (замеренная форма, не выдуманная).

### Изменения в существующих файлах

#### `packages/core/src/adapters/defillama/index.ts`

**Аргументы** — `extractDexVolumeArgs(args, chains): { chain: ChainInfo; days: number; includeSeries: boolean }`:

- `chain` резолвится через `chains.tryResolve`; отказ, если `vendors.defillama` пуст **или** сеть
  не в `DEFILLAMA_DEX_CHAINS` (тот же предикат, что `chainSupport` — вызвать его, не переписывать).
- `days` — целое `1…1825`; `includeSeries` — boolean. Значения приходят уже провалидированные zod'ом
  на входе тула, но адаптер обязан отказывать самостоятельно: он публичен внутри пакета.

**URL:**

```
https://api.llama.fi/overview/dexs/${encodeURIComponent(vendorName)}
  ?excludeTotalDataChartBreakdown=true            // всегда — иначе +18 МБ разбивки
  [&excludeTotalDataChart=true]                   // когда includeSeries === false
```

`vendorName` — `chain.vendors['defillama']` (**отображаемое имя**: `OP Mainnet`, `Hyperliquid L1`).
Именно оно возвращается вендором в эхо-поле `chain` и перечислено в `allChains`. Путь у вендора
name-толерантен (`op-mainnet`/`optimism`/`OP Mainnet` дают один документ), но мы отправляем ровно то
имя, с которым потом сверяемся, — иначе сверка проверяет собственную догадку.

**Кэш документа — по образцу `fetchChainsCatalog` в этом же файле:**

- `Map<vendorName, { at: number; body: Promise<unknown> }>` **на экземпляр адаптера**, никогда не
  модульный синглтон (§8).
- Окно = TTL capability (**3600 с**), чтобы кэш документа не мог отдать данные старше, чем отдал бы
  кэш движка.
- Хранится **промис**, а не значение: конкурентные вызовы разделяют один запрос вместо гонки.
- `body.catch(...)` вычищает запись, только если она всё ещё текущая, — неудача не запоминается на час.
- Возвращается `{ body, fetchedAt }`, где `fetchedAt` — время **загрузки документа**. Прокинуть его в
  `normalize()` через приватный тип результата (урок vdd-multi cycle 6, M-1: два окна подряд не
  складываются в одно, и возраст обязан быть возрастом данных).

**Ограничение размера:** передать `safeFetch(..., { maxResponseBytes })` явным значением для этого
пути. Дефолт 10 МБ избыточен для документа, который в норме 250 КБ; **2 МБ** оставляет ×8 запаса и
превращает «вендор внезапно вернул глобальный документ» в громкий отказ вместо тихой загрузки.

## Test Cases

### Unit-тесты (`packages/core/test/defillama-dex-volume.test.ts`, новый)

1. **TC-UNIT-01** — URL содержит `excludeTotalDataChartBreakdown=true`; при `includeSeries: false`
   содержит **и** `excludeTotalDataChart=true`.
2. **TC-UNIT-02** — сеть с пробелом в имени (`OP Mainnet`) url-энкодится (`OP%20Mainnet`).
3. **TC-UNIT-03** — заголовка авторизации нет вовсе: инжектированный `fetchImpl` проверяет, что
   `init.headers` пуст (keyless — и это должно остаться доказанным, а не подразумеваемым).
4. **TC-UNIT-04** (**R-70**) — два вызова с **разными** `days` по одной сети внутри окна дают
   **один** вызов `fetchImpl`.
5. **TC-UNIT-05** — два вызова по **разным** сетям дают **два** вызова `fetchImpl` (кэш документа
   ключуется по сети, а не «последний документ»).
6. **TC-UNIT-06** — конкурентные `Promise.all` по одной сети дают один вызов `fetchImpl`.
7. **TC-UNIT-07** — отклонённый запрос вычищается: после неудачи следующий вызов снова идёт в сеть.
8. **TC-UNIT-08** — HTTP 500 (незнакомая сеть у вендора) → адаптер бросает с указанием статуса.
9. **TC-UNIT-09** (**AC-6**, вторая половина) — вызов по непокрытой сети не доходит до `fetchImpl`
   (счётчик = 0).

### Регрессия

- `pnpm test`; отдельно `defillama.contract.test.ts` — `chain.tvl` и `protocol.tvl` используют тот же
  `throttle`/`safeFetch` и тот же экземпляр адаптера.
