# Задача 014.32: тул `onchain_pool_info` и сверка инвентарей

## Связь со сценариями
- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Отгрузить тул для способности `pool.info`, принимающий адрес пула и возвращающий адреса токенов,
резервы и уровень комиссии. Свести манифест способностей с набором тулов гейтом.

**Why.** Решение владельца: направление 1 закрытия L-15. Оно разблокирует WI-56 — резолв символа в
адрес контракта, которого не хватило в анализе berachain.

### Вход и выход

Вход — сеть из реестра и адрес пула. Адрес проверяется по формату адреса сети и хостом не является:
гейт задачи 014-22 распространяется и на эту схему.

Выход — адреса токенов, резервы, уровень комиссии.

### Уровень комиссии

Пул без метода, отдающего комиссию, отвечает типизированным отказом. Источник комиссии для
berachain требует курированного RPC-хоста, согласия на который владелец ещё не давал.

**Следствие:** до согласия задача отгружает адреса токенов и резервы, а уровень комиссии отвечает
объявленным отказом. Это записано в плане как незакрытое обязательство.

### Сверка инвентарей

Гейт проверяет: манифест не объявляет способности, которую не резолвит ни один тул. Инвентари
`docs/` и кода приводятся в согласие.

## Тест-кейсы

### Сквозные тесты
1. **TC-E2E-01:** вызов по адресу известного пула возвращает адреса токенов и резервы
2. **TC-E2E-02:** пул без метода комиссии отвечает типизированным отказом

### Модульные тесты
1. **TC-UNIT-01:** манифест не объявляет способности без резолвящего тула (AC-29)
2. **TC-UNIT-02:** схема ввода не принимает хост, URL или эндпоинт (AC-11)
3. **TC-UNIT-03:** адрес неверного формата отвергается до исходящего вызова

### Регрессионные тесты
- Снимок `tools/list` меняется на один тул; правка обоснована в коммите
- Число тулов в тестах инвентаря не зашито

выражается отказом, а не нулём.
