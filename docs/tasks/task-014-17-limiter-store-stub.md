# Задача 014.17: `LimiterStore` и ключ `(providerId, scopeKey)` `[STUB]`

## Связь со сценариями
- UC-2 — две сессии делят вендорскую квоту

<!-- contract:goal -->

## Цель задачи

Объявить интерфейс хранилища корзин и ключ `(providerId, scopeKey)`, где `scopeKey` объявляет
провайдер. Сигнатура `throttle` сохраняется.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `packages/core/src/net/limiter-store.ts` — интерфейс и внутрипроцессный стаб
- `packages/core/test/limiter-scope-key.test.ts` — тесты ключа

### Изменения в существующих файлах

**Файл `packages/core/src/net/rate-limit.ts`:**
- Принять `LimiterStore` в `ThrottleDeps`
- Сигнатуру `throttle(providerId, config, weight?, deadlineAtMs?)` не менять
- Три класса отказов сохранить: `RateLimitRejectedError`, `DeadlineWouldExceedError` и успех

**Файл `packages/core/src/providers.config.ts`:**
- Провайдер объявляет `scopeKey`; умолчание — отсутствие, то есть одна корзина на провайдера
- `rpc-evm` объявляет `scopeKey` = сеть

### Почему единица расщепления — не хост

`rpc-evm` вызывает лимитер в `rpc-evm/index.ts:181`, до чтения `chain.rpcHosts` и до цикла по
эндпоинтам. В точке вызова hostname неизвестен, а сеть известна.

`coingecko` выбирает ровно один хост на инсталляцию (`coingecko/index.ts:139`), так что два его
зарегистрированных хоста никогда не живут одновременно: расщепление по хосту там не наблюдаемо.

### Почему умолчание — одна корзина

Трафик всех сетей сегодня расходует общий бюджет вызовов через одну корзину `'rpc-evm'`. Умолчание
сохраняет действующее поведение для 12 провайдеров, не объявивших расщепления.
