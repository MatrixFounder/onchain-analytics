## 3. Что мешает — 12 пробелов, по убыванию тяжести

1. **Блокирующий: в движке нет типа «произвольная таблица».** `grep -rn 'z.record|passthrough()|z.unknown()|z.any()'` по `packages/core/src` и `packages/mcp-server/src` даёт **ноль** попаданий; барьер типов экспортирует ровно 9 закрытых канонических схем. Результат чужого SQL положить некуда. → `types/index.ts:4-13`
2. **Форма выхода тула фиксирована объектом.** `registerTool(..., { outputSchema: XSchema.shape })` требует `z.object` со статически известной формой — вернуть голый массив строк нельзя, строки обязаны быть вложены в объект. → `tools/chain-tvl.ts:76-77`
3. **Нет машинерии асинхронных задач.** Dune — это execute → poll status → results, а `safeFetch` строго одношаговый, 15 с на хоп, ни одного poll-цикла в репозитории; `ProviderAdapter.fetch` — одиночный `Promise<unknown>` без токена отмены. → `net/safe-fetch.ts:32`, `adapters/types.ts:26`
4. **Зарегистрированный rate limit враждебен poll-циклу.** `{capacity: 2, refillPerSec: 0.1}` = 1 токен/10 с; 6-й токен превышает `MAX_WAIT_MS = 30_000` и бросает. Poll-цикл умрёт примерно на пятом опросе. → `providers.config.ts:116`, `net/rate-limit.ts:32`
5. **Кап размера ответа не работает на той форме, которую отдаёт Dune.** При отсутствующем `Content-Length` (chunked) проверка делает ранний `return` вовсе без ограничения. Это **уже известно и заведено** как R-47 в бэклоге — не новая находка. → `net/safe-fetch.ts:147-154`, `docs/BACKLOG.md:19`
6. **Кэш ограничен числом записей, а не байтами.** `LRUCache({ max: 500 })` без `maxSize`/`sizeCalculation`; персистентный слой кладёт весь результат в одну колонку `value_json TEXT`. 500 канонических токенов и 500 многомегабайтных таблиц — разные вещи. → `cache/lru.ts:8`, `:28`, `cache/ddl.ts:60`
7. **`costOf` на уровне реестра — мёртвый код.** `CapabilityRegistry.resolve()` его не вызывает; единственный реальный потребитель — приватный гейт внутри `nansen.fetch()`. Значит, преполётной проверки цены нет, и каждый провайдер обязан дублировать бюджетную логику у себя. → `adapters/registry.ts:174-338`
8. **`_meta.budget` захардкожен на один провайдер.** `provider: 'nansen'` — строковый литерал в типе, и `getUsage('nansen', ...)` в теле. Второй кредитный провайдер не сможет отчитаться о расходе именно там, где мы обещаем мониторинг. → `tools/budget-meta.ts:9`, `:38`
9. **Стаб Dune объявляет себя бесплатным.** `costOf: () => ({ credits: 0 })` — прямая инверсия fail-closed правила R-37, по которому неизвестная capability обязана давать `Number.POSITIVE_INFINITY`. Пока `costOf` не читается реестром, это спящая мина, а не активный баг. → `dune/index.ts:28`, ср. `nansen/cost-of.ts:71`
10. **Ключ кэша не различает два разных SQL**, если сам SQL (или query id + параметры) не попал в `args`. И тогда текст SQL становится частью sha256-ключа и `JSON.stringify` — без какого-либо ограничения длины, в отличие от сознательно обрезаемого ввода сети. → `net/args-hash.ts:44-47`, ср. `chain/errors.ts:37-40`
11. **Нет ни одной capability query-образной формы.** Таблица маршрутов — 17 сущностных capability; `CapabilityDescriptor.id` — открытая строка (добавить дёшево), но каждый потребитель ниже по течению (TTL, матрица покрытия, схема выхода тула) предполагает ровно одну фиксированную каноническую сущность. → `providers.config.ts:23-76`, `adapters/types.ts:9-12`
12. **Работа не заведена.** `grep -i dune docs/BACKLOG.md docs/KNOWN_ISSUES.md` — пусто, а `open-questions.md:101` фиксирует, что после ухода `token.risk` к Nansen «точный query id / SQL для `token.holders` не для кого авторить». Единственная capability, которую резервирует стаб, — сирота.

## 5. Ограничения, которые связывают дизайн (не рекомендации)

- **Пять standing constraints владельца** (`ARCHITECTURE.md:137-160`) — прямо помечены «These are owner
  decisions… They bind every future change». Из них бьют по этому дизайну: автономный цикл живёт
  только в n8n (значит расписание/ожидание — не в MCP-сервере); кэш только локальный;
  `chain` — открытая строка, не enum; **никаких ложных обещаний универсальности**.
- **Прецедент против проксирования вендорского MCP.** Проект уже **отказался** проксировать
  официальный MCP Nansen, потому что «several of its tools return markdown text, which is unusable
  for canonical zod normalization» (`docs/architectures/system-architecture.md:630-634`).
  Это прямо релевантно развилке по Dune MCP: решение «просто подключить官 MCP» противоречит
  действующему прецеденту, и отступление от него нужно обосновывать явно.
- **D4/D5 анти-коррупционный слой** (`ADR-001:71`, `:91`): вендорский DTO не имеет права дойти до
  вызывающего; всё, что отдают тулы и хранит кэш, — в канонических типах. Произвольная таблица
  из чужого SQL — это лобовое столкновение с D5, и его надо разрешить осознанно.
- **D10** (`ADR-001:159`): секреты не логируются и не попадают в ключи кэша.
- **D11** (`ADR-001:167`): не бить по живым платным API в CI — записанные ответы, ноль трат.
- **R-37 fail-closed pricing** (`nansen/cost-of.ts:71`): неизвестная цена = бесконечность, не ноль.
- **Токен-цена схемы** (`tools/smart-money-flows.ts:23-29`): закрытые enum'ы сетей выпилены, потому
  что стоили ~8.7k токенов схемы **в каждом** запросе. Широкая схема параметров SQL-тула
  вернёт эту цену обратно.
- **Dune Sim** (`ROADMAP.md:241`) — записанный запрет: sunset 01.08.2026 (через 5 дней после даты
  аудита). В область входит только Query/Execution API на `api.dune.com`; зарегистрированный хост
  это уже отражает.

## 6. Реальные дефекты вашего кода, найденные попутно

Это не артефакты исследования — это то, что стоит поправить независимо от решения по Dune:

1. **Стаб не выполняет собственное обещание.** Докстринг `dune/index.ts:4-13` говорит, что стаб
   существует ради «внятной причины недоступности» вместо общего «адаптер не зарегистрирован».
   Но при переданной сети первым срабатывает coverage-гейт (`registry.ts:213-226`), и вызывающий
   получает `CapabilityNotCoveredOnChainError`, а не обещанную причину. Обещание доставляется
   только на пути без сети.
2. **`costOf: () => ({ credits: 0 })` у кредитного вендора** — спящая инверсия R-37 (§3, п.9).
3. **`budget-meta.ts` захардкожен на `'nansen'`** — второй платный провайдер станет невидимым в
   `_meta` (§3, п.8). Отказ расширять тип был осознанным («speculative»), но с приходом второго
   кредитного провайдера основание исчезает.
4. **Dune нигде не заведён как работа** — ни в `BACKLOG.md`, ни в `KNOWN_ISSUES.md`, при том что
   `ROADMAP.md:99` числит «Dune Query API (free 2,500cr/мес)» среди бесплатных адаптеров M1,
   а `ROADMAP.md:83` переносит его в M2. Расхождение роадмапа с реальностью не отслеживается.
5. **`.mcp.json` с plaintext JWT n8n** — проверено: файл **не** отслеживается git и покрыт
   `.gitignore:53` (`git check-ignore` подтверждает). Утечки нет; отмечено, чтобы это не всплыло
   как «находка» позже.

## 8. Итог аудита

Движок **готов принять слой сложных запросов лучше, чем можно было ожидать**: бюджет-стор уже
провайдер-агностичен, dune уже классифицирован как платный, хост уже в allowlist, ключ уже в
env-схеме, доктрина обрезки недоверенного текста уже написана, eval-гарнесс уже умеет проверять
новый источник данными.

Настоящий блокер ровно один и он архитектурный, а не механический: **канонические типы закрыты, а
результат чужого запроса — произвольная таблица.** Это столкновение с D5, и его нельзя обойти
аккуратной реализацией — его надо разрешить решением. Дизайн-развилка и предлагаемое решение —
в `report.md` §6 («Дизайн врезки»), где выбран гибрид с разделением по признаку «тратит ли вызов
кредиты автономно».
