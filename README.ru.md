# onchain-intel

Движок ончейн-аналитики, выставленный наружу как **MCP-сервер**: адаптеры провайдеров (CoinGecko,
DexScreener, DeFiLlama, EVM/Solana RPC, Nansen, …) → нормализация в единую каноническую схему →
двухуровневый кеш + бюджет-гард по кредитам → 8 инструментов, которые вызывает ваш агент.

**English version:** [README.md](README.md)

> Все примеры ниже выполнены против собранного сервера. Ответы настоящие, обрезаны только по длине.
> Три платных инструмента показаны по записанным фикстурам — живьём при написании они не вызывались.

## Что это даёт

**8 MCP-инструментов.** Одна проверка живости, четыре бесплатных инструмента данных и три платных
alpha-инструмента на Nansen.

**Две сети:** `ethereum` и `solana`. Каждый инструмент принимает `chain` явно.

**Канонический вывод.** DTO провайдеров наружу не протекают — каждый инструмент возвращает
версионированный доменный объект, проверенный zod. Смена провайдера не меняет контракт вашего агента.

**Денежная безопасность.** Nansen — единственный платный провайдер. Каждый платный вызов оценивается
по статической таблице цен и атомарно резервируется в суточном леджере **до** обращения к сети.
Вызов не может превысить ни остаток у вендора, ни ваш собственный потолок.

**Работает вообще без ключей.** Пустой `.env` — валидная конфигурация: бесплатные инструменты
работают, платные честно отказывают, а не отдают молча пустоту.

## Установка и сборка

```bash
corepack enable pnpm
pnpm install --frozen-lockfile
pnpm build
```

Сборка даёт `packages/mcp-server/dist/index.js` — это и есть сервер.

Убедитесь, что артефакт запускается, прежде чем подключать его к агенту:

```bash
pnpm --filter @onchain-intel/mcp-server run smoke:dist
# smoke-dist: PASS: onchain_ping OK over dist/index.js (version 0.1.0)
```

## Конфигурация

Создайте `.env` в корне проекта и закройте права:

```bash
cp .env.example .env && chmod 600 .env
```

**Все ключи опциональны.** Пустой `.env` поднимает рабочий сервер. Ключи читаются внутри того
вызова, которому нужны, — никогда при загрузке модуля, никогда не логируются и никогда не входят в
кеш-ключ.

| Ключ                              | Для чего                                 | По умолчанию                             |
| --------------------------------- | ---------------------------------------- | ---------------------------------------- |
| `NANSEN_API_KEY`                  | три платных инструмента                  | не задан → они отвечают `isError`        |
| `NANSEN_DAILY_CREDIT_CAP`         | самоналагаемый потолок расхода           | выводится, см. ниже                      |
| `NANSEN_VELOCITY_CREDITS_PER_MIN` | тормоз по скорости расхода               | выводится, см. ниже                      |
| `NANSEN_BUDGET_WARN_RATIO`        | порог предупреждения в stderr            | `0.8`                                    |
| `COINGECKO_API_KEY`               | повышенные лимиты CoinGecko (demo)       | keyless работает                         |
| `COINGECKO_PRO_API_KEY`           | Pro-хост CoinGecko                       | —                                        |
| `ONCHAIN_PG_URL`                  | история снапшотов (read-only DSN)        | история берётся из бесплатного источника |
| `DATA_DIR`                        | каталог кеша и леджера бюджета           | `~/.onchain-intel`                       |
| `LOG_LEVEL`                       | зарезервирован, пока ни на что не влияет | —                                        |

`DUNE_API_KEY` зарезервирован: адаптер — заглушка и сообщает о недоступности даже с заданным ключом.

**Эндпоинты, хосты, rate-limits и TTL намеренно НЕ настраиваются через env.** Они объявлены в
`packages/core/src/providers.config.ts`, потому что переопределяемый через env URL был бы дырой в
SSRF-allowlist.

## Подключение к Claude Code

Добавьте `.mcp.json` в корень проекта (файл в gitignore — в нём могут лежать секреты других серверов):

```json
{
  "mcpServers": {
    "onchain-intel": {
      "command": "node",
      "args": ["packages/mcp-server/dist/index.js"]
    }
  }
}
```

Блок `env` не нужен: сервер сам грузит `.env` из своей рабочей директории.

Перезапустите Claude Code и проверьте, что инструменты видны:

```
/mcp
```

Под `onchain-intel` должно быть **8 инструментов**.

Самая дешёвая проверка — без сети и без ключей:

```

Какой TVL у Uniswap в сети ethereum?
```

### onchain_entity_label (платный)

Метки сущностей и адресов. **Три ценовых тарифа**, выбираются переданными аргументами:

| Аргументы                  | Стоимость  | Что делает                           |
| -------------------------- | ---------- | ------------------------------------ |
| только `query`             | **0 кр**   | поиск по сущностям и токенам         |
| `tokenAddress` (± `query`) | **5 кр**   | добавляет метки из числа держателей  |
| `exhaustive: true`         | **100 кр** | полные профайлерные метки для адреса |

Нужен хотя бы один из `query` / `tokenAddress`. Для `exhaustive: true` дополнительно обязателен
`tokenAddress`, и он **никогда** не включается автоматически — это стоимость целого баланса на
free-плане.

Вход — бесплатный тариф:

```json
{ "chain": "ethereum", "query": "wintermute" }
```

Вход — эскалация за 100 кр, только явно:

```json
{ "chain": "ethereum", "tokenAddress": "0xA0b8…eB48", "exhaustive": true }
```

## Формат ответа

Каждый инструмент возвращает стандартные для MCP `content` + `structuredContent`, плюс соседнее
поле `_meta`, которое не меняет схему вывода.

```jsonc
"_meta": {
  "cache": { "status": "miss", "provider": "defillama", "capability": "protocol.tvl" }
}
```

На попадании в кеш добавляется возраст записи:

```jsonc
"_meta": {
  "cache": { "status": "hit", "ageMs": 2, "provider": "defillama", "capability": "protocol.tvl" }
}
```

Платные инструменты добавляют `budget` — **только при промахе кеша**, потому что попадание не тратит
ничего:

```jsonc
"_meta": {
  "cache": { "status": "miss", "provider": "nansen", "capability": "smart-money.flows" },
  "budget": { "provider": "nansen", "creditsUsedToday": 16 }
}
```

Отсутствие `budget` на попадании — не упущение, а признак: именно так отличается бесплатный ответ от
оплаченного.

## Бюджет-гард по кредитам

Вызовы Nansen тратят настоящие деньги, поэтому движок не даёт им идти бесконтрольно.

**Перед каждым платным вызовом:**

1. точная цена берётся из статической таблицы — никогда не оценка, а неизвестная цена фейлится
   закрыто (бесконечность), а не подставляет ноль;
2. живая проверка `/account` (0 кредитов) даёт реальный остаток у вендора;
3. стоимость **атомарно резервируется** в леджере SQLite одной транзакцией;
4. и только после этого уходит HTTP-запрос.

После вызова фактическое списание вендора сверяется с резервацией, и леджер сходится к тому, что
действительно было выставлено.

### `NANSEN_DAILY_CREDIT_CAP` — три состояния

| Значение                  | Поведение                                                  |
| ------------------------- | ---------------------------------------------------------- |
| не задан (по умолчанию)   | выводится: `max(30, 25% от баланса на начало UTC-суток)`   |
| целое положительное число | ваш явный потолок                                          |
| `off`                     | самоограничение снято — связывает только остаток у вендора |

Выводимое значение означает, что защита работает **из коробки**. Она масштабируется вместе с
тарифом: баланс 100 даёт потолок 30, баланс 10 000 — 2500. `0` намеренно отвергается: он в одной
опечатке от молчаливого снятия денежной защиты и по смыслу должен означать «не тратить вовсе».

Отказ громкий и называет, какая именно граница сработала:

```
nansen budget gate refused: self-imposed cap (derived): need 10, allows 30 …
```

### `NANSEN_VELOCITY_CREDITS_PER_MIN` — тормоз по скорости

Дневной потолок ограничивает расход **за сутки** — это предел ущерба, но не тормоз: троттлинг
пропускает порядка 50 кредитов в секунду, поэтому большой потолок мог быть съеден за минуту
разогнавшимся циклом. Потолок при этом держался, но у человека не оставалось шанса заметить.
Второй лимит ограничивает **скорость**
([SEC-1](docs/issues/sec-1-nansen-daily-cap-does-not-bound-a-burst-no-velocity-guard.md),
исправлено).

| Значение              | Поведение                                                             |
| --------------------- | --------------------------------------------------------------------- |
| не задано (по умолч.) | выводится: `max(100, действующий потолок / 20)` кредитов на окно 60 с |
| положительное целое   | ваш явный лимит на минуту                                             |
| `off`                 | тормоза нет — связывают только дневной потолок и остаток у вендора    |

Делитель 20 означает, что на исчерпание дневного бюджета уйдёт минимум ~20 минут непрерывного
расхода. Пол в 100 — цена самого дорогого одиночного вызова (`entity.labels` в тире `exhaustive`):
лимит ниже стоимости одного вызова сделал бы эту способность невозможной, а не ограниченной по
скорости. Там, где пол превышает разрешённое дневным потолком, первым связывает дневной — оба
гарда складываются, и побеждает более строгий.

Проверка и резервирование идут **в той же транзакции**, что и дневная бронь, по таблице
`usage_window` в `DATA_DIR`: две сессии Claude Code на одной машине не могут каждая пройти свою
проверку окна, а перезапуск процесса не сбрасывает счётчик.

Отказ называет, какой именно лимит сработал, — потому что реакции у них противоположные:

```
nansen budget gate refused: velocity limit (derived): 125 credits per 60s, need 10 —
the DAILY budget is not exhausted; retry after the window rolls over, or set
NANSEN_VELOCITY_CREDITS_PER_MIN to raise it, or off to disable it.
```

**Известное ограничение:** окно фиксированное (tumbling), а не скользящее, поэтому всплеск на
границе двух окон может достичь 2× лимита. Цели «дать человеку время заметить» это не отменяет.

### `NANSEN_MAX_CALLS_PER_MIN` — лимит, который видит бесплатный вызов

Оба лимита выше считают **кредиты**, а тир `entity.labels` с текстовым запросом стоит **ноль**
кредитов. Для вызова ценой 0 условие `used + 0 > ceiling` ложно всю жизнь любого бакета при любом
потолке — то есть никакой гейт, считающий кредиты, не может его отказать, как низко его ни ставь.
Это не дефект потолка, это смысл слова «в кредитах». Лечится другой единицей измерения
([Q-3](docs/issues/q-3-nansen-zero-credit-entity-labels-tier-is-unrefusable-by-the-gate.md),
исправлено).

| Значение              | Поведение                                              |
| --------------------- | ------------------------------------------------------ |
| не задано (по умолч.) | 60 вызовов на окно 60 с                                |
| положительное целое   | ваш явный лимит                                        |
| `off`                 | вызовы не ограничены — работают только лимиты кредитов |

**Фиксированное значение по умолчанию, а не выводимое** — асимметрия с двумя кредитными лимитами
намеренная. Кредитные выводятся, потому что балансы `free` и `Pro` различаются на порядки. Вызов
же есть вызов на любом тарифе: ни лимиты вендора, ни давление на рост строк кеша не масштабируются
балансом — выводить не из чего. 60 в минуту — это один вызов в секунду непрерывно, заметно выше
любой интерактивной сессии и примерно в 5 раз ниже того, что пропустил бы один троттлинг.

Побочно это ограничивает и рост кеша: при 60 вызовах в минуту и TTL 3600 с строки этой способности
выходят на стационарные ~3600 вместо неограниченного роста.

**Вызов не возвращается.** Сверка корректирует кредиты; счётчик вызовов только растёт. Обращение к
вендору состоялось, и «возврат» позволил бы череде дешёвых-и-возвращённых вызовов пройти мимо
лимита, который существует ровно ради этого трафика.

Отказ говорит об этом прямо — потому что кредитная ручка здесь не поможет:

```
nansen budget gate refused: call rate limit (default): 60 calls per 60s — this bound counts
CALLS, not credits, so it applies to zero-credit tiers too and raising a credit ceiling will
not move it.
```

### Гейт происхождения (provenance)

`docs/provenance.json` фиксирует sha256 golden-теста и всех живьём записанных фикстур вендора.
`pnpm test` проверяет рабочее дерево, `.githooks/pre-commit` — то, что реально **застейджено**.
Правка запиненного файла без переоснования в том же коммите красит оба
([RF-2](docs/issues/rf-2-m2-evidence-records-drifted-from-the-shipped-commit.md), исправлено).

Хук включается один раз на клон — git-хуки локальны и не могут приехать включёнными:

```sh
git config core.hooksPath .githooks
```

Переоснование — осознанное действие, в том же коммите, что и правка, чтобы рецензент видел обе
половины:

```sh
node scripts/verify-provenance.mjs --update
```

## Поведение без API-ключей

Отсутствие ключей деградирует **явно**. Три платных инструмента возвращают MCP-ошибку с указанием
недостающего ключа; на остальной движок это не влияет:

```json
{
  "content": [
    {
      "type": "text",
      "text": "capability unavailable: smart-money.flows on ethereum — tried: nansen (needs NANSEN_API_KEY)"
    }
  ],
  "isError": true
}
```

**Значение** ключа не попадает ни в одну ошибку, лог или кеш-ключ.

Это осознанный выбор вместо тихого отката на бесплатного провайдера: бесплатного эквивалента с тем
же смыслом данных не существует, а молчаливая подмена была бы хуже громкой ошибки.

## Кеширование

Два слоя, одна политика: LRU в памяти перед SQLite в `DATA_DIR`. Кеш-ключ —
`(провайдер, способность, нормализованные аргументы)`; **API-ключи в него не входят**, поэтому
ротация ключа не инвалидирует кеш.

| Способность         | TTL   | Почему так                                   |
| ------------------- | ----- | -------------------------------------------- |
| `pairs.new`         | 30с   | свежесть — весь смысл                        |
| `token.price`       | 60с   | движется непрерывно                          |
| `wallet.balances.*` | 60с   | движется непрерывно                          |
| `protocol.tvl`      | 300с  | медленный агрегат                            |
| `smart-money.flows` | 300с  | содержит скользящее часовое окно             |
| `token.risk`        | 1800с | скоры обновляются примерно раз в сутки, 6 кр |
| `token.metadata`    | 3600с | меняется редко                               |
| `entity.labels`     | 3600с | метки меняются днями, до 100 кр за промах    |

**Отрицательное кеширование.** Если вендор ответил успешно, но ответ не удалось нормализовать, этот
вердикт запоминается на 60 секунд — повтор упадёт так же, но уже бесплатно. Кешируются только
детерминированные сбои; ошибки транспорта, 429 и 5xx — нет, потому что они вполне могут пройти со
следующей попытки.

## Решение проблем

**Инструменты не появились в Claude Code.** Сначала выполните `pnpm build` — `.mcp.json` указывает
на `dist/index.js`, которого до сборки не существует. После правки `.mcp.json` перезапустите
Claude Code.

**Платный инструмент отвечает `needs NANSEN_API_KEY`.** Сервер читает `.env` из **своей рабочей
директории**. Под Claude Code это корень проекта — значит, `.env` должен лежать именно там.

**Платный инструмент отказал по бюджету.** Так и задумано — значит, гард работает. Посмотрите
`_meta.budget.creditsUsedToday` и либо дождитесь смены UTC-суток, либо поднимите
`NANSEN_DAILY_CREDIT_CAP`.

**Две машины, один аккаунт Nansen.** У каждой установки свой леджер в своём `DATA_DIR`, поэтому
самоналагаемый потолок считается по каждой установке отдельно. Остаток у вендора при этом связывает
обе.

**Всё выглядит устаревшим.** `DATA_DIR` по умолчанию — `~/.onchain-intel`. Удаление этого каталога
сбрасывает кеш, а вместе с ним и леджер расхода: суточный потолок начнёт считаться с нуля.
