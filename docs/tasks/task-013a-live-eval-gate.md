## 1. Описание проблемы

Два разных отказа требуют двух разных инструментов, и один из них отсутствовал.

**«Мы сломали»** ловит сьют: 1651 тест, все на фикстурах — это осознанно, R-21 запрещает сеть в CI.
Фикстура сверяет наш код со **вчерашним снимком вендора**.

**«Они сломали»** не ловил никто. У этого класса нет нашего коммита, на который можно сработать.
Замер: `token.holders` на приёмке TASK-008 (живой зонд 2026-07-28) отдавал **50 строк**; на
2026-08-10 отдаёт **HTTP 403 на всех пяти** курируемых сетях, объявляющих способность. Маршрут в
нашем коде за это время не менялся. До 12 суток способность была мертва при полностью зелёном сьюте
— заведено как [L-6](issues/l-6-token-holders-advertised-everywhere-blockscout-403-everywhere.md).

`packages/mcp-server/eval/` этот класс видит и **видел**: его отчёт называл расхождение своими
словами. Не хватало не механизма, а того, чтобы его запускали, и того, чтобы добавить в него случай
было нельзя забыть.

## 2. Что сделано

1. **Атомарные случаи** — `eval/cases/<case>.mjs`, по файлу на случай: запрос (`args`), ожидание
   (`catches`) и проверка (`check`) лежат вместе. Загрузчик `eval/cases/index.mjs` находит их
   обходом каталога.
2. **`capabilities.mjs` и `checks.mjs` стали адаптерами** над каталогом: ось способностей и карта
   проверок по тулу выводятся, а не пишутся руками.
3. **Гейт** — `scripts/eval-gate.mjs` (`pnpm gate`): делит отказы на **неподтверждённые** (блокируют),
   **известные** (заведены в реестр, не блокируют, но называются на каждом прогоне) и **устаревшие
   подтверждения** (блокируют).
4. **Журнал** — `eval/ledger.jsonl`, пополняемый, по строке на прогон: `ranAt`, задача, git sha,
   counts, вердикт, ключи строк.
5. **Правило** в `CLAUDE.md` § Working discipline: прогнать гейт до объявления задачи сданной.

## 3. Решения, принятые в ходе работы

| #      | Решение                                                                       | Основание                                                                                                                                                                                                     |
| ------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R1** | Гейт, не расписание. Ежедневного прогона нет                                  | Решение владельца. Прогон нужен там, где от ответа что-то зависит — на сдаче задачи, а не по календарю                                                                                                        |
| **R2** | Только локально. Ни launchd/cron, ни CI, ни n8n                               | Решение владельца: автоматизация допустима только в контролируемой песочнице n8n, а host OS не трогаем. CI признан YAGNI. **Отменяет более раннюю редакцию этой задачи**, где были launchd-агент и n8n-вебхук |
| **R3** | Подтверждение отказов не влияет на `eval/run.mjs` и его код выхода            | `pnpm eval` остаётся релизным гейтом; гейт, зеленеющий при открытом дефекте, хуже отсутствующего                                                                                                              |
| **R4** | Подтверждённый отказ называется на каждом прогоне                             | L-2: «залечено — не значит спрятано»                                                                                                                                                                          |
| **R5** | Устаревшее подтверждение **блокирует**                                        | Иначе список только растёт и превращается в повязку на глаза; снятие стоит одной строки JSON                                                                                                                  |
| **R6** | Имя тула в случае не пишется — выводится через `toolFor()` из инвентаря       | R-117: имя тула порождается сборкой; рукописная копия переживёт переименование, которое инвентарь бы поймал                                                                                                   |
| **R7** | Один тул на две способности — коллизия отвергается, если проверки различаются | Dash обслуживает два селектора одним тулом. Молчаливое «последний выиграл» дало бы случаю проверку, которую он не объявлял                                                                                    |

## 4. Приёмка

| #      | Критерий                                                        | Как проверяется                                                        |
| ------ | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **A1** | Обе оси выводятся из каталога и совпадают с прежними литералами | 10 способностей, 11 тулов, те же списки, что до рефакторинга           |
| **A2** | Сьют пакета зелёный                                             | `pnpm --filter @onchain-intel/mcp-server test`                         |
| **A3** | Гейт не блокирует на текущем дереве                             | `pnpm gate --dry-run --from <артефакт>` → `pass`, пять известных строк |
| **A4** | Неподтверждённый отказ блокирует                                | Прогон с урезанным `acknowledged.json` → `BLOCKED`, exit 1, имя строки |
| **A5** | Устаревшее подтверждение блокирует                              | Прогон с лишней записью → `BLOCKED`, exit 1, причина названа           |
| **A6** | `pnpm eval` остаётся красным при открытом L-6                   | `node eval/run.mjs; echo $?` → `1`                                     |
| **A7** | Живой прогон гейта пишет строку в журнал                        | `pnpm gate --task 013a`, затем непустой `eval/ledger.jsonl`            |
