# Задача 013-5 — Контракт исходов: три состояния участника, четыре ветки, дедлайн-предусловие

**Требования:** [R-164], [R-176] · **Эпики:** E-1, E-4 · **Критерии приёмки:** AC-27, AC-37, AC-41,
AC-48 · **Фаза:** 5 из 10 · **Зависимости:** 013-4

## Use Case Connection

- **UC-12** — `pg-history` недоступен, `platform-explorer` отвечает непустым рядом. Успех плюс
  `missingSources`. Провал: вызов падает целиком или сигнал теряется молча.
- **UC-13** — оба участника недоступны. Явная ошибка. Провал: тихий пустой успех.
- **UC-14** — оба опрошены, окно реально пустое. Пустой успех. Провал: пустой ряд трактуется как
  отказ.
- **UC-19** — единственный опрошенный ответил пусто, второй не спрошен. `CapabilityUnavailableError`.
  Провал: «истории нет» вместо «источник не спрашивали».
- **UC-21** — участник опрошен и упал с HTTP 500. Успех из второго плюс `missingSources`. Провал:
  упавший участник не попадает ни в одну ветку.
- **UC-22** — участник побеждён дедлайном любой из двух дверей. `CapabilityDeadlineExceededError`.
  Провал: частичный слитый успех, отменяющий OD-4 незамеченно.

<!-- contract:goal -->

## Цель задачи

Дать слитому обходу терминальный контракт исходов, различающий три состояния участника, и сохранить
дедлайн предусловием этого контракта, а не пятой веткой.

<!-- contract:changes -->

## Описание изменений

### Три состояния участника

- **«Ответил»** — вернул нормализованный результат: из кеша (`registry.ts:779-793`) или с сети
  (`:840`). Удовлетворил политику или нет — вопрос ортогональный, состояние то же.
- **«Не спрошен»** — пропущен до `fetch()` по НЕ-дедлайн-причине: нет адаптера (`:727`), не подходит
  `chainSupport` (`:743`), `isAvailable() = {ok:false}` (`:748`), действующая отрицательная запись
  кеша (`:773`).
- **«Спрошен, не ответил»** — `fetch()`/`normalize()` бросили (`:834`, `:880`), кроме
  `DeadlineExceededError`.

### Четыре ветки после цикла

- **(a)** все участники ответили → слитый успех, в том числе пустой.
- **(b)** хотя бы один ответил непусто и хотя бы один недостающий → успех из ответивших плюс
  `missingSources`.
- **(c)** ни один ответивший не дал точек и есть недостающий → `CapabilityUnavailableError` с
  полным `tried`, никогда пустой успех.
- **(d)** не ответил никто — названный частный случай (c), выделен ради UC-13.

### `missingSources`

Причина берётся из готовой записи `tried[]` для пяти путей (`:727`, `:748`, `:773`, `:835`, `:881`)
— той же формы. Пропуск по `chainSupport` (`:743`) — исключение: `tried[]` намеренно не несёт для
него записи, поэтому `missingSources` синтезирует свою причину. На обоих боевых маршрутах этот путь
недостижим, но форма поля обязана его учитывать.

### Дедлайн — предусловие

- `deadlineHit`, выставленный пре-чеком (`:716-724`) или пойманным `DeadlineExceededError` (`:829`),
  отменяет все четыре ветки: вызов завершается `CapabilityDeadlineExceededError` независимо от того,
  сколько участников уже ответили.
- Третья точка того же класса — истёкший на входе `requestedDeadlineAtMs` (`:528-530`, `tried: []`),
  до обхода и до любого ветвления.
- **Терминальный дизъюнкт по часам сохраняется неизменным** (`:944`:
  `deadlineHit || Date.now() >= effectiveDeadlineAtMs`). Он покрывает все двенадцать адаптеров,
  тогда как распутывание типов (WI-36) починило два. Реализация не имеет права его удалить.
- `DeadlineWouldExceedError` (насыщенный бакет лимитера) `deadlineHit` не выставляет. Такой участник
  — «спрошен, не ответил», и распределяется ветками (b)/(c) общим правилом.
- Ветка (a), доставленная после `effectiveDeadlineAtMs` без единого побеждённого участника, несёт
  `deadlineOverrunMs` — поздний, но полный ответ, отличный от предусловия.

### `attempted`

- Участник, отданный из кеша, не входит ни в `attempted`, ни в `missingSources`.
- Участник «спрошен, не ответил» входит в оба одновременно: запись в `attempted` делается до входа в
  `fetch()` (`:797`).
- «Не спрошен» отсутствует в `attempted` целиком.

### Фазы

- **Фаза 1.** Классификация участников собирается в цикле; терминальный код возвращает ветку (a)
  всегда. Тесты (b)/(c)/(d) и дедлайна пишутся сразу и красные.
- **Фаза 2.** Ветвление, `missingSources`, предусловие, мутационный прогон дизъюнкта.

## Тест-кейсы

### Новый файл `packages/core/test/registry.merge-outcomes.test.ts` (виртуальные часы)

- **TC-INT-01** — ветка (a): оба ответили, окно пустое → пустой успех, `missingSources` отсутствует
  (UC-14).
- **TC-INT-02** — ветка (b), участник «не спрошен»: `isAvailable() = {ok:false}` → успех из первого,
  `missingSources` называет второго с причиной (UC-12).
- **TC-INT-03** — ветка (b), участник «спрошен, не ответил»: `fetch()` бросает HTTP 500 → успех из
  второго, `missingSources` называет первого (UC-21). Fails when упавший участник не попадает ни в
  одну ветку.
- **TC-INT-04** — ветка (c): единственный опрошенный ответил пусто, второй не спрошен →
  `CapabilityUnavailableError`, `tried` называет обоих (UC-19, AC-41).
- **TC-INT-05** — ветка (d): не ответил никто → `CapabilityUnavailableError` (UC-13).
- **TC-INT-06** — дверь 1: `effectiveDeadlineAtMs` позади к моменту опроса второго →
  `CapabilityDeadlineExceededError`, не ветка (b) (UC-22, AC-48).
- **TC-INT-07** — дверь 2: `fetch()` второго оборван пойманным `DeadlineExceededError` → тот же
  класс ошибки, тот же отказ от частичного ответа.
- **TC-INT-08** — дверь 3: `requestedDeadlineAtMs` истёк на входе → тот же класс, `tried: []`.
- **TC-INT-09** — `DeadlineWouldExceedError` при непустом ответе второго → ветка (b), а не
  предусловие.
- **TC-INT-10** — `DeadlineWouldExceedError` при пустых ответах всех опрошенных → ветка (c).
- **TC-INT-11** — ветка (a) после потолка без побеждённых участников → успех с `deadlineOverrunMs`.
- **TC-INT-12** — `attempted` слитого вызова с обоими реально опрошенными: `['platform-explorer',
'pg-history']` в порядке опроса (AC-37).
- **TC-INT-13** — участник из кеша: отсутствует и в `attempted`, и в `missingSources`.
- **TC-INT-14** — участник «спрошен, не ответил»: присутствует в обоих массивах одновременно.
- **TC-INT-15** — пропуск по `chainSupport`: `missingSources` несёт синтезированную причину, а
  `tried[]` записи не получает.

## Критерии приёмки

- [ ] Три состояния участника различены в коде, а не только в комментарии
- [ ] Четыре ветки исполнены отдельными тестами, включая композицию «один ответил непусто, другой
      опрошен и упал»
- [ ] Дедлайн-предусловие покрывает обе двери плюс вход, и ни один из трёх случаев не даёт частичный
      ответ
- [ ] Терминальный дизъюнкт по часам сохранён; мутационный прогон исполнен и записан
- [ ] `DeadlineWouldExceedError` распределяется ветками (b)/(c), оба направления проверены
- [ ] `attempted` и `missingSources` проверены на трёх составах раздельно
- [ ] Полный набор гейтов §0.2 плана зелёный; снимок `tools-list.snapshot.json` без диффа

## Вне области этой задачи

- Дедуп, ранг и кеш — `013-4`.
- Поле `missingSources` в ответе тула — `013-7`.
- Любое ослабление OD-4: частичный ответ при побеждённом дедлайном участнике не вводится ни в одной
  форме.
