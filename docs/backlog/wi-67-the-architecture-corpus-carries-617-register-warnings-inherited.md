# WI-67 — корпус архитектуры несёт 617 предупреждений регистра, унаследованных

**Что.** Прогон `scan_register.py` по одиннадцати файлам корпуса даёт **617** предупреждений:
**602 унаследованных и 15, написанных фазой T-015**.

**Исправление записи от 2026-09-02.** Первая редакция этой записи объясняла разрыв 617 против 602
ошибкой счёта в ревью и утверждала, что вклад T-015 нулевой. Оба утверждения неверны, и оба
опровергнуты одним замером — прогоном по дереву `main`:

```bash
git worktree add --detach <wt> main
# для каждого файла корпуса: scan_register.py <wt>/<файл>
```

| Дерево                             | Предупреждений |
| :--------------------------------- | -------------: |
| `main` (до вехи)                   |            602 |
| `HEAD` (веха T-015)                |            617 |
| разница                            |            +15 |

Ревью назвало **602**, и `main` даёт ровно 602: ревью считало верно. Пятнадцать сверх того написаны
самой фазой T-015 — все правилом `sentence_length`, все на строках, добавленных ветвью вехи:
`data-model.md` +6, `deployment.md` +5, `system-architecture.md` +4. Разбивка по правилам это
подтверждает: остальные шесть правил не сдвинулись ни на единицу.

Пятнадцать предложений — не наследство и подпадают под обязательство фазы, а не под эту запись.
Владельца им назначает приёмка вехи (015-32), которая этот разрыв и обнаружила.

**Распределение указывает, с чего начинать.** Три четверти всех срабатываний — одно правило
(`sentence_length`, 467 из 617), и почти половина всего объёма — один файл
(`system-architecture.md`, 278). Работа не равномерна по корпусу и не равномерна по правилам.

**Происхождение.** Из 617 унаследованы **602**; остальные **15** написаны фазой T-015 и в предмет
этой записи не входят. Правки задачи 015-31 к обеим величинам не добавили: счётчики трёх
затронутых ею файлов до и после совпали (53/85/26).

**Почему «унаследовано» перестаёт быть объяснением.** Второй год подряд одно и то же слово
переносит работу через веху. Оно объясняет, откуда предупреждения взялись, и не объясняет, почему
их всё ещё столько же. Запись существует, чтобы у переноса появилась дата и объём, а не только
причина.

**Почему запись, а не правка.** Правка 617 предупреждений — работа объёмом с отдельный этап. Её
попадание внутрь T-015 сделало бы приёмку вехи зависимой от неё, а сама веха к регистру корпуса
отношения не имеет.

**Что не входит.** База предупреждений этой задачей не правится (TC-DOC-07 задачи 015-31): в
четырёх файлах изменены только шесть названных замечаний.
