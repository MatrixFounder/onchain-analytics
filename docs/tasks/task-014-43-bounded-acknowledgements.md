# Задача 014.43: подтверждение живого гейта получает множество, границу и срок

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Сделать перемежающийся вендорский отказ выразимым в `eval/acknowledged.json`, не ослабив ни одну из
проверок, ради которых файл существует.

**Why.** [RF-10](../issues/rf-10-the-gate-acknowledgement-is-a-per-row-boolean-so-an-intermittent-vendor-failure-can-never-be-acknowledged.md):
запись утверждала постоянство — «этот ряд падает», — и отвергала перемежающийся отказ с обеих
сторон. Прогон, где ряд падает, объявлял его незаведённым; прогон, где проходит, объявлял
подтверждение протухшим. Заблокировать могли оба, удовлетворить оба нельзя было ничем. Все вендорские
отказы этого проекта перемежающиеся. Правило проекта «заблокированный гейт — задача не сдана»
превращалось в «ни одна задача не может быть сдана», начиная с 014-31.

**Решения владельца.**

- **OD-014-43-1.** Запись описывает множество рядов и границу на число одновременно упавших
  (вариант «в»). Отвергнуты: сохранить булев признак по ряду (работает только для ряда, падающего
  всегда) и добавить признак «мигает» без потолка (запись перестаёт что-либо утверждать — расширение,
  запрещённое памятью M6).
- **OD-014-43-2.** Признак протухания — срок пересмотра, а не история прогонов. Обоснование: история
  смещена ровно в сторону этого дефекта, потому что зелёный ряд значит «кеш был тёплым», и K зелёных
  прогонов за вечер не K независимых проб. Гейт остаётся функцией одного прогона и одного файла.

**Зависимости.** Нет. Задача трогает один скрипт и один файл данных.

## Тест-кейсы

### Интеграционные тесты

1. **TC-INT-01:** падающая сеть кочует внутри границы — гейт проходит в обе стороны; это та самая
   пара прогонов, которую старый механизм блокировал дважды
2. **TC-INT-02:** на один упавший ряд больше границы — блокирует
3. **TC-INT-03:** полностью зелёное множество не блокирует и доживает до срока
4. **TC-INT-04:** упавший ряд, не покрытый ни одной записью, блокирует — это сигнал
5. **TC-INT-05:** названный ряд исчез из матрицы — блокирует (форма RF-5)
6. **TC-INT-06:** срок пересмотра прошёл — блокирует и называет запись
7. **TC-INT-07:** пять форм испорченного файла блокируют, включая срок дальше 90 дней и границу,
   равную размеру множества
8. **TC-INT-08:** две записи на один ряд — неоднозначное владение, а не объединение
9. **TC-INT-09:** `rate-limited` печатается как НЕ ПРОВЕРЕНО и не считается восстановлением

### Контроль

- Чистое дерево при пустом файле подтверждений даёт `pass`; испорченная запись даёт блок

## Примечания

**Почему граница равна числу упавших при заведении, а не размеру множества минус один.** Второй
вариант выглядит естественнее и слаб: под ним L-12 мог бы деградировать с двух сетей до четырёх
незаметно. Первый делает расширение записи актом измерения — ровно тем же, чем было её заведение.

**Почему запись из одного ряда невозможна.** Граница 1 над одним рядом непревосходима, то есть
навсегда закрывает этот ряд от гейта. Сообщение об отказе прямо говорит, что делать: назвать сети, на
которых способность ОБСЛУЖИВАЕТСЯ, а не только упавшую. Это же превращает подтверждение из «эта
клетка мигает» в утверждение о способности.
