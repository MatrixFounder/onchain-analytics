# Задача 014.41: воркфлоу `onchain-retention`

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Спроектировать один воркфлоу n8n по имени `onchain-retention`, выполняющий три задания очистки, и
получить на каждый прогон каждого задания строку в `onchain.retention_runs`.

**Why исполнитель — n8n, а не серверный процесс.** Постоянное ограничение 1 держит автономный цикл
на n8n бессрочно (ARCHITECTURE §1.2 пункт 1). Сетевой профиль мог бы нести планировщик; владелец
решил его не добавлять (решение 2026-08-13, закрывает `OQ-T014-DEP-2`).

## Описание изменений

### Новые файлы

- `n8n-workflows/exported/onchain-retention.json` — экспорт воркфлоу через
  `./n8n-workflows/export.sh`

Серверный процесс планировщика не получает: файлов в `packages/` эта задача не добавляет.

### Три задания

| Задание                  | Цель                    | Действие                                | Окно по умолчанию                                |
| :----------------------- | :---------------------- | :-------------------------------------- | :----------------------------------------------- |
| `diagnostics.purge`      | `onchain.diagnostics`   | удаляет строки старше окна              | 90 дней; пол 90 дней, максимум — окно NORMALIZED |
| `request_trace.raw_null` | `onchain.request_trace` | ставит `tried_json` в NULL за окном RAW | 90 дней; пол 90 дней, максимум — окно NORMALIZED |
| `request_trace.purge`    | `onchain.request_trace` | удаляет строки за окном NORMALIZED      | 365 дней; пол 365 дней, максимум 730 дней        |

Имена заданий воспроизводят §10.6 дословно и попадают в колонку `job` таблицы `retention_runs`
(`data-model.md` §4.5.9).

### Строка на каждый прогон

Каждое задание в том же проходе пишет строку в `onchain.retention_runs`: `id`, `job`,
`target_table`, `period_from`, `period_to`, `rows_affected`, `started_at`, `finished_at`, `outcome`,
`detail_json`. Уникальный ключ дедупликации — `(job, period_from, period_to, started_at)`.

Прогон, удаливший ноль строк, всё равно пишет свою строку с `rows_affected = 0` и `outcome = 'ok'`.

**Why нулевой прогон тоже пишет строку.** «Нечего удалять» и «задание не запускалось» — разные
факты, и различает их только записанная строка (DB-SCHEMA §4, §4.5.9).

**Why каждое задание пишет строку внутри своего прохода.** Строка, записанная отдельным поздним
проходом, не может назвать период, который удаление покрыло.

Каждый проход пишет также одну строку `retention.cleanup` в `onchain.diagnostics`; этот воркфлоу —
её единственный писатель (§4.5.8, §10.6.1).

### Окно вне диапазона

Окно вне диапазона §10.3.1 отвергается: задание не удаляет ничего и пишет строку `retention_runs` с
`outcome = 'failed'`, называя отвергнутую настройку в `detail_json`. Отказ доходит до Telegram через
`errorWorkflow`.

**Why отказ, а не подрезка.** Подрезанное окно удаляет строки, которые оператор просил сохранить, и
таблица записала бы подрезанный период как запрошенный.

### Форма воркфлоу

| Элемент         | Значение                                                                       |
| :-------------- | :----------------------------------------------------------------------------- |
| Триггер         | Schedule, ежедневно                                                            |
| Параметр-нода   | Set-нода с тремя окнами §10.3.1, паттерн Normalize Input                       |
| Креденшел       | Postgres-креденшел state-роли `onchain_engine_state` (§10.5), не «Supabase DB» |
| Писатели        | по одной Postgres-ноде на задание, за каждой — вставка в `retention_runs`      |
| `errorWorkflow` | `onchain-error-alert`                                                          |
| Экспорт         | `./n8n-workflows/export.sh` → `n8n-workflows/exported/onchain-retention.json`  |
| Стикер          | обязательная Overview-заметка (CLAUDE.n8n.md)                                  |

**Why окна живут в параметр-ноде.** Один узел владеет контрактом конфигурации, и смена окна не
правит ноду с запросом (CLAUDE.n8n.md, §10.6.1).

**Why окна не ключи окружения.** Задания исполняются в n8n, а n8n не читает `.env` серверного
процесса; `$env` на этом инстансе заблокирован (§10.3.1, CLAUDE.n8n.md).

**Why отдельный креденшел.** Действующий «Supabase DB» аутентифицируется как роль снапшоттера, у
которой нет прав на двенадцать таблиц движка, поэтому установка добавляет второй Postgres-креденшел
(§10.5).

Значения времени — epoch-ms UTC, `id` — ULID, порождаемый в Code-ноде (DB-SCHEMA §1.2, §1.3).
Вставка в `retention_runs` связывает данные параметром запроса и не интерполирует их в SQL
(CLAUDE.n8n.md).

### Установка требует явного согласия владельца

Архитектура предлагает воркфлоу; она его не создаёт и не активирует. Инстанс общий, и создавать на
нём допускается только `onchain-*` воркфлоу этого проекта (CLAUDE.n8n.md, §10.6.1). Установка —
шаг 7 порядка §10.4.2, выполняемый после согласия владельца.

**Why согласие отдельным шагом.** Активация пишущего воркфлоу на общем инстансе — операция над
чужой средой, и её нельзя вывести из принятой задачи.

4. **TC-WF-04:** окно вне диапазона

## Примечания

`retention_runs` не очищается: таблица растёт на несколько строк в день, а задание, которое чистило
бы её, писало бы в неё же (§4.5.9).

Воркфлоу обслуживает ось хранилища Postgres: на оси SQLite задания ретенции не устанавливаются
(задача 014-38, `deployment.md` §10.1.1). Профиль `local` остаётся без изменений.

Максимум 730 дней применён, а не измерен: объёма запросов HTTP пока нет. §4.5.8 обязуется измерить
число строк первого месяца, и этот замер выводит число заново.

Задача зависит от 014-35 и 014-27. Миграция 014-35 создаёт `onchain.retention_runs` и
`onchain.diagnostics` и выдаёт state-роли права на них; 014-27 закрепляет словарь событий, в
котором объявлено `retention.cleanup`. Задача 014-02 объявляет интерфейсы доступа и не создаёт ни
одной таблицы, поэтому в зависимостях её здесь нет.

Установка воркфлоу — единственный шаг T-014, исполняемый на общем инстансе n8n. Он остаётся
незакрытым, пока владелец не дал согласия, и это состояние отличается от невыполненной работы.
