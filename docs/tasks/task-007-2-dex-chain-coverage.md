# Task 007-2: Покрытие DEX-объёмов из живого списка вендора

## Use Case Connection

- UC-2: агент выясняет, на каких сетях вопрос вообще имеет смысл
- UC-3: оператор обновляет список сетей после дрейфа вендора

## RTM

**R-63** (покрытие выводится из списка вендора, а не из наличия `vendors.defillama`)

## Task Goal

Заменить стаб `chainSupport(…, 'dex.volume.history') === false` на предикат, выведенный из
**собственного списка вендора**, и сделать список воспроизводимым build-артефактом.

## Почему это отдельная задача, а не строка в 007-1

`vendors.defillama` заполнен у **всех 458** сетей реестра — он выведен из TVL-каталога `/v2/chains`.
DEX-объёмы вендор отдаёт по **287** сетям (`allChains` живого ответа), из которых в нашем реестре
есть **274**. Предикат `chain.vendors.defillama != null` переобещал бы capability на **184 сетях** —
дословно дефект **H-1** из ревью TASK-006 («покрытие расширили, транспорт нет»).

## Changes Description

### Новые файлы

- `docs/onchain-analytics/raw/defillama-dexs-allchains-2026-07-27.json` — записанное сырое
  доказательство: поле `allChains` живого ответа + метаданные записи (URL, дата, HTTP-код).
  Провенанс по §7.4 — не «список, который я где-то видел».
- `packages/core/scripts/gen-defillama-dex-chains.ts` — dev-скрипт. Ничто под `src/` его не
  импортирует; он читает закоммиченный raw и пишет закоммиченный `.ts`. Контракт — тот же, что у
  `scripts/gen-nansen-coverage.ts`.
- `packages/core/src/adapters/defillama/dex-chains.ts` — **сгенерированный** модуль:
  `export const DEFILLAMA_DEX_CHAINS: readonly string[]` (вендорские **имена**, не наши слаги) с
  шапкой «GENERATED … do not edit by hand».

### Изменения в существующих файлах

#### `packages/core/src/adapters/defillama/index.ts`

- `chainSupport(chain, capability)`:
  - `capability === 'dex.volume.history'` → `chain.vendors['defillama'] != null &&
DEX_CHAIN_SET.has(chain.vendors['defillama'])`, где `DEX_CHAIN_SET` — `Set`, построенный **один
    раз на модуль** из массива (не `Array.includes` на каждый вызов: предикат зовётся для каждой из
    458 строк реестра на каждый `onchain_list_chains`).
  - иначе → прежнее `chain.vendors['defillama'] != null`.

### Требования к генератору

- **Отказ вместо экранирования** (как `safeToken` в `gen-nansen-coverage.ts`): вендорское имя вне
  `/^[A-Za-z0-9][A-Za-z0-9 ._-]*$/` роняет генератор с указанием значения. Имена содержат пробелы
  (`OP Mainnet`, `Hyperliquid L1`), поэтому пробел в классе разрешён — кавычка, обратный слэш и
  перевод строки **нет**: они закрыли бы строковый литерал в эмитируемом `src/`-модуле.
- **Отказ на подозрительно коротком списке**: меньше 50 имён — падение, а не пустое покрытие.
- **Детерминизм**: сортировка перед эмитом; повторный запуск на том же входе даёт побайтово тот же файл.
- **Печатает расхождение**: сколько имён вендора отсутствует в реестре (ожидаемо 13) — не молча.

## Test Cases

### Unit-тесты (`packages/core/test/defillama-dex-coverage.test.ts`, новый)

1. **TC-UNIT-01** — `chainSupport(ethereum, 'dex.volume.history') === true`.
2. **TC-UNIT-02** — сеть, чьё `vendors.defillama` отсутствует в `DEFILLAMA_DEX_CHAINS`
   (например `zcash`), даёт `false` для `dex.volume.history` и **`true`** для `chain.tvl`.
   Один объект, два ответа — это и есть суть задачи.
3. **TC-UNIT-03** (**AC-6**) — `CapabilityRegistry.resolve('dex.volume.history', <непокрытая сеть>, …)`
   отвергается `CapabilityNotCoveredOnChainError`, а инжектированный `fetchImpl`-счётчик вызван
   **0 раз**. Тест доказывает, что гейт стоит **до** сети, а не после.
4. **TC-UNIT-04** — размер покрытия равен мощности пересечения реестра и списка вендора; число
   вычисляется в тесте из тех же двух источников, а **не** зашивается литералом 274 (иначе
   очередная синхронизация реестра уронит тест по причине, не имеющей отношения к дефекту).

### Unit-тесты генератора (`packages/core/test/registry-generator.test.ts` — расширить)

5. **TC-UNIT-05** (**AC-5**) — генератор на синтетическом входе детерминирован (два запуска → тот же
   вывод).
6. **TC-UNIT-06** (**AC-5**) — имя с кавычкой / переводом строки роняет генератор.
7. **TC-UNIT-07** — вход из 3 имён роняет генератор (защита от пустого покрытия).

### Регрессия

- Полный `pnpm test`; отдельно `coverage.test.ts` и `chain-discoverability.test.ts` — они читают
  матрицу покрытия и первыми заметят переобещание.

## Acceptance Criteria

- [ ] `DEFILLAMA_DEX_CHAINS` сгенерирован из закоммиченного raw, шапка «GENERATED» на месте
- [ ] Предикат различает `dex.volume.history` и TVL-capability
- [ ] Непокрытая сеть отвергается **без** сетевого вызова
- [ ] Генератор детерминирован и отказывает на подозрительном входе
- [ ] Число покрытых сетей выведено, а не зашито литералом
- [ ] `pnpm test` зелёный целиком

## Notes

Свежесть списка — **ответственность оператора**, ровно как у реестра сетей (§4.2.1): рантайм ничего
не тянет на старте, иначе рушится оффлайн-гейт и детерминизм CI. Сеть, появившаяся у вендора,
становится доступной после прогона генератора и коммита снимка — никогда автоматически.
