# Задача 014.36: восемь таблиц в `CACHE_DDL` `[LOGIC]`

## Связь со сценариями
- UC-1 — n8n вызывает способность по сети
- UC-3 — оператор запускает локально

<!-- contract:goal -->

## Цель задачи

Объявить восемь таблиц `data-model.md` §4.5 в строке `CACHE_DDL` файла
`packages/core/src/cache/ddl.ts` формой `CREATE TABLE IF NOT EXISTS`. Одно объявление обслуживает
профили `local` и `network-sqlite`.

**Why задача заведена отдельно.** §4.4 пункт 1 называет объявление в SQLite отдельной аддитивной
миграцией — одна на каждый движок хранения, без переноса данных между ними. Редакция 1 плана
описала восемь таблиц только в файле миграции Postgres.

### Форма объявления

Только `CREATE TABLE IF NOT EXISTS`. Ни одного `ALTER` над существующей таблицей и ни одного
backfill (§4.4 пункт 1, постусловие).

**Why форма ограничена.** `CACHE_DDL` выполняется через `db.exec(CACHE_DDL)` на каждом открытии
`SqliteCacheStore`. Оператор, который не идемпотентен, отказал бы на втором открытии.

**Why аддитивный путь `ALTER` здесь не нужен.** Он существует для `usage_window`
(`packages/core/src/cache/ddl.ts:133`,
`ALTER TABLE usage_window ADD COLUMN calls_made INTEGER NOT NULL DEFAULT 0`), потому
что та таблица уже есть на инсталляциях. Восьми таблиц нет ни на одной, поэтому колонку добавлять не
к чему.

### Канон, обязательный к соблюдению

- Типы только `TEXT`, `INTEGER`, `REAL`; время — epoch-ms UTC в `INTEGER`
- Идентификаторы генерирует приложение: ULID как `TEXT`
- Семь ULID-ключей §4.5 объявляются `TEXT PRIMARY KEY NOT NULL`; слово `NOT NULL` не опускается
- JSON хранится как `TEXT`
- `provider_buckets.scope_key` — `TEXT NOT NULL DEFAULT ''`, без допуска NULL
- `provider_buckets.tokens` — `REAL`, значение может быть отрицательным
- Значение `id` строки `phase0-unlimited` — литеральная ULID, одна и та же с миграцией задачи 014-35

**Why `NOT NULL` пишется рядом с `PRIMARY KEY`.** §4.5.2a: SQLite допускает `NULL` в колонке
`TEXT PRIMARY KEY`, Postgres — нет. Без этого слова тест, считающий объявленные обязательные
колонки, находит на оси SQLite на одну меньше, чем на оси Postgres, для одной и той же таблицы.

**Why `scope_key` не допускает NULL.** SQLite принимает NULL в колонке первичного ключа, Postgres
отвергает. Допускающая NULL колонка заставила бы один диалект дедуплицировать строку, а другой —
отказать в ней (§4.5.6).

**Why отрицательное значение корзины не обрезается по нулю.** Следующий вызывающий считает своё
ожидание из этого отрицательного остатка. Обрезанная строка выдала бы всем ожидающим одно нулевое
ожидание (§4.5.6).

**Why литерал профиля общий с задачей 014-35.** Два движка, засеявших профиль независимо, дадут два
идентификатора для одной сущности, и `access_profile_id` токена повиснет на одном из хостов (§4.5.3).

### Что объявление в SQLite делает исполнимым в CI

Тесты отзыва токена и неизменяемости журнала аудита исполнимы без процесса Postgres. Это следствие
того, что одна строка DDL и одна реализация хранилища обслуживают оба диалекта (§4.5.1). R-21 канона
запрещает сеть в CI, поэтому живая база в прогоне сьюты недоступна.

**Why таблицы идентичности объявлены в SQLite, хотя на stdio остаются пустыми.** Обоснование
§4.5.1 воспроизводится дословно: одна строка DDL и одна реализация хранилища служат обоим диалектам,
и тогда тест отзыва или тест журнала на добавление идёт против SQLite, без процесса Postgres в CI.

**Профиль `network-sqlite` эти таблицы заполняет.** Он поднимает транспорт HTTP, поэтому
аутентифицирует каждый запрос по таблицам SQLite. Это профиль, который отлаживает транспорт без
сервера Postgres (§4.5.1).

**Токен, выпущенный в хранилище stdio-процесса, недействующ.** Транспорт stdio не требует токена и
не проверяет его (`docs/TASK.md:451`). Оператор не должен читать такую строку как защиту транспорта
(§4.5.1).

### Внешние ключи

`provider_buckets.provider`, `api_tokens.user_id`, `api_tokens.access_profile_id`,
`access_audit.actor_user_id` и `request_trace.vendor_provider` объявляются с `REFERENCES`.
`diagnostics.trace_id` объявляется без `REFERENCES` (§4.5.8).

**Why `trace_id` остаётся без ссылки.** Строка диагностики пишется в момент события, а строка следа
— один раз, по завершении. Событие `limiter.degraded` возникает в середине запроса; при
`PRAGMA foreign_keys=ON` такая вставка отказала бы, и процесс потерял бы диагностику о деградации
лимитера (§4.5.8).

## Тест-кейсы

### Модульные тесты

1. **TC-UNIT-01:** восемь таблиц и десять индексов появляются на свежей базе
   - Входные данные: новый файл `cache.sqlite3`, открытый `SqliteCacheStore`
   - Ожидаемый результат: `sqlite_master` содержит все восемнадцать объектов
2. **TC-UNIT-02:** объявление идемпотентно
   - Входные данные: то же соединение, открытое повторно
   - Ожидаемый результат: `db.exec(CACHE_DDL)` завершается без ошибки
3. **TC-UNIT-03:** журнал аудита не изменяется задним числом
   - Входные данные: `UPDATE` и `DELETE` по существующей строке `access_audit`
   - Ожидаемый результат: оба оператора отвергнуты триггером `RAISE(ABORT)`
4. **TC-UNIT-04:** отзыв токена читается как отзыв
   - Входные данные: строка `api_tokens` со `status = 'revoked'` и `revoked_at IS NULL`, затем та же
     строка с обоими значениями
   - Ожидаемый результат: первая отвергнута ограничением `CHECK`; вторая читается по `token_hash` со
     статусом `revoked`
5. **TC-UNIT-05:** внешний ключ лимитера соблюдается
   - Входные данные: `INSERT` в `provider_buckets` с неизвестным `provider`
   - Ожидаемый результат: отказ по внешнему ключу при `PRAGMA foreign_keys=ON`
6. **TC-UNIT-06:** строка профиля не дублируется
   - Входные данные: два открытия одного файла базы
   - Ожидаемый результат: одна строка `access_profiles` с `name = 'phase0-unlimited'`
7. **TC-UNIT-07:** режим лимита и его величина объявляются вместе
   - Входные данные: строка с `credits_mode = 'metered'` и `credits_balance_raw IS NULL`
   - Ожидаемый результат: строка отвергнута ограничением `CHECK`
8. **TC-UNIT-08:** форма объявления соблюдена
   - Входные данные: текст `CACHE_DDL`
   - Ожидаемый результат: для каждой из восьми таблиц есть `CREATE TABLE IF NOT EXISTS`, ни один
     `ALTER TABLE` не адресует эти восемь, и семь ULID-ключей несут `TEXT PRIMARY KEY NOT NULL`

### Регрессионные тесты

- `pnpm test`, `pnpm typecheck`, `pnpm build`; прогон не требует ни сети, ни Postgres
- Существующие тесты кеша и бюджета остаются зелёными: четыре таблицы §4.2 не меняются

## Примечания

Задача покрывает только объявление таблиц. Реализация хранилищ поверх них — задачи 014-06 и 014-07;
запись следа и диагностики — задачи 014-27, 014-29 и 014-30.

Диалектные различия операторов записи в эту задачу не входят. Замена `LEAST` на `MIN` в операторе
лимитера и обёртка `db.transaction(fn).immediate()` относятся к задачам 014-17 и 014-18 (§4.5.6).
