# Задача 014.12: порядок проверок на входе и аутентификация до маршрутизации `[LOGIC]`

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Закрепить порядок проверок входящего запроса и отклонять запрос без валидного токена до
маршрутизации способности.

<!-- contract:changes -->

## Описание изменений

### Изменения в существующих файлах

**Файл `packages/mcp-server/src/transport/http.ts`:**

- Шаги 1–3 выполняются в собственном слушателе, до `transport.handleRequest`

### Порядок и постусловия

| Шаг | Проверка                                  | Постусловие                                               |
| :-- | :---------------------------------------- | :-------------------------------------------------------- |
| 1   | периметр: `Host` и `Origin`               | запрос вне периметра не породил чтения хранилища токенов  |
| 2   | аутентификация: bearer из `Authorization` | запрос без валидного токена не дошёл до реестра и до кеша |
| 3   | допуск сессии                             | число живых сессий не превысило объявленного потолка      |
| 4   | транспорт: `handleRequest`                | проверки заголовков и типа содержимого выполнены SDK      |
| 5   | слой тулов                                | способность разрешена реестром                            |

**Why периметр раньше токена.** Запрос из-за периметра не должен вызывать чтения хранилища токенов.

**Why аутентификация раньше маршрутизации.** Неаутентифицированный путь не должен порождать
исходящих вендорских вызовов и чтений кеша. Проверка после маршрутизации оставляет обе возможности.

### Переутверждение AC-1 и AC-2 на аутентифицированном пути

**Файл `packages/mcp-server/test/e2e.http.test.ts`:**

- Провести AC-1 и AC-2 заново, с валидным токеном в запросе

Тесты этого файла написаны задачей 014-09 и описывают путь без проверки токена. После текущей задачи
такого пути нет. Обязательство задачи — переутвердить оба критерия на действующем пути.

**Why переутверждение названо обязательством.** Тест, описывающий снятый путь, остаётся зелёным и
перестаёт что-либо утверждать о работающем сервере. AC-1 требует совпадения ответов по HTTP и stdio,
и совпадение проверяется на том пути, по которому запрос теперь идёт.

**Why это не правка снимка.** Меняется сетевой тест: запрос получает токен. Файл `e2e.stdio.test.ts`
и снимок `tools/list` остаются без правок, как требует AC-2.

### Запуск сетевого профиля

Запуск профиля развёртывания «сетевой» без выпущенного токена невозможен. Процесс останавливается на
старте с названным классом отказа.

## Тест-кейсы

### Сквозные тесты

1. **TC-E2E-01:** запрос без токена не порождает исходящего вызова и чтения кеша
   - Входные данные: счётчики на `fetchImpl` и на `CacheStore`
   - Ожидаемый результат: оба счётчика — ноль (AC-3)
2. **TC-E2E-02:** запрос вне периметра не породил чтения хранилища токенов
3. **TC-E2E-03:** аутентифицированный вызов по HTTP отвечает тем же, что вызов по stdio
   - Входные данные: `onchain_ping` и `onchain_list_chains` с равными аргументами и валидным токеном
   - Ожидаемый результат: ответы совпадают (AC-1)

### Модульные тесты

1. **TC-UNIT-01:** невалидный bearer даёт 401 с заголовком `WWW-Authenticate: Bearer`
2. **TC-UNIT-02:** отозванный токен даёт тот же отказ
3. **TC-UNIT-03:** запуск сетевого профиля без токена останавливает процесс (AC-24)

### Регрессионные тесты

- stdio-путь аутентификации не приобретает: `e2e.stdio.test.ts` зелёный

## Критерии приёмки

- [ ] AC-3: счётчики `fetchImpl` и `CacheStore` — ноль на неаутентифицированном запросе
- [ ] Порядок шагов 1–5 закреплён тестом на каждое постусловие
- [ ] Запуск сетевого профиля без токена невозможен
- [ ] stdio не приобрёл обязательной аутентификации
- [ ] AC-1 и AC-2 переутверждены на аутентифицированном пути

## Примечания

RISK-1 спецификации — хук принципала после кеша. Эта задача ставит границу до реестра; сам принципал
доводится до места будущего списания задачами 014-14 и 014-15.

Задача 014-09 остаётся предусловием: она создаёт `e2e.http.test.ts`, чьи проверки здесь проводятся
заново с токеном.
