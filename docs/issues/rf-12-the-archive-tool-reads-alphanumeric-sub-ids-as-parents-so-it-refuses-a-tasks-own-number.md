# RF-12 — инструмент архивации читает буквенно-цифровой под-ID как родительский архив, поэтому отказывает задаче в её собственном номере

## Симптом

Архивация TASK-014 по протоколу `skill-archive-task` (шаг 3) отказала:

```
$ python3 .agent/tools/task_id_tool.py "t014-http-transport-auth-perimeter-profiles-shared-limiter" \
    --proposed-id "014" --no-correction
{ "filename": null, "used_id": null, "status": "conflict",
  "message": "ID 014 is occupied. Suggested alternative: 015" }
```

Родительского архива `docs/tasks/task-014-<slug>.md` не существовало, `docs/plans/plan-014-*.md`
не существовало. Конфликта не было.

## Причина

`SUBTASK_FILENAME_RE` (`.agent/tools/task_id_tool.py:76`) требует **чисто числовой** сегмент под-ID:

```python
SUBTASK_FILENAME_RE = re.compile(r'^task-(\d{3,})-(\d+)-.+\.md$')
```

`get_parent_archive_ids()` (`:138`) считает родительским всё, что этому шаблону не соответствует.
Планировщик T-014 завёл пять под-задач с буквенно-цифровым под-ID — `task-014-32a`…`task-014-32e`
(вставки в этап 32 после ревью границы фазы). Каждая из пяти классифицируется как **родительский
архив номера 014**, и номер объявляется занятым.

## Почему это SEV-2, а не косметика

Инструмент не просто отказал — он **предложил `015`**. Следование подсказке заархивировало бы
T-014 под номером **следующей вехи дорожной карты**, и `docs/plans/plan-015-*` встал бы в пару к
чужой задаче. Это ровно класс **ARC-1**, против которого написан шаг 4 протокола («ID приходит из
документа, а не из каталога»), — с той разницей, что здесь его порождает сам инструмент, а не
ручной пересчёт. Защитил только флаг `--no-correction`: с `--allow-correction` переименование
прошло бы молча и с кодом 0.

## Почему однострочной правки нет

Поведение **закреплено тестом** — `.agent/tools/test_task_id_tool.py:185`
`test_slug_starting_with_a_letter_digit_segment_reads_as_a_parent`: `task-012-3d-viewer.md`
обязан читаться как родитель. Расширение шаблона до `(\d+[a-z]*)` этот тест ломает и перекрашивает
`3d-viewer` в под-задачу. Собственный докстринг функции называет ограничение честно: по одному
имени файла родитель со слагом-с-цифры неотличим от под-задачи.

То есть это столкновение двух соглашений, а не опечатка. Разрешать его должен владелец фреймворка.

## Варианты (не выбраны)

1. **Соглашение планировщика: под-ID только числовой.** Дешевле всего и убирает неоднозначность в
   источнике; цена — переименование уже сданных `014-32a`…`32e` и правка цитат на них в
   `plan-014`, ревью и коммитах. Отвергает проблему, а не решает: следующий планировщик снова
   вставит `44a`, потому что вставка в середину нумерации — естественный ход.
2. **Различать по содержимому, а не по имени.** Родительский TASK несёт якорь
   `<!-- contract:meta -->` и строку `| ID | TASK-NNN |`; под-задача не несёт ни того, ни другого.
   Замерено на этом корпусе: у пяти файлов `014-32*` — ноль вхождений `contract:meta`, у
   `task-013` и `task-014` — по одному. **Не полно:** у `task-005-m2-alpha-paid.md` тоже ноль
   (архив старше якоря), поэтому правилу нужен запасной признак и прогон по всему корпусу
   фреймворка, а не по одному проекту.
3. **Расширить шаблон под-ID и переписать пин.** Самое малое изменение кода; цена — принять, что
   родитель со слагом вида `3d-…` станет невидим. Требует замера: есть ли такие в 1127 артефактах
   пяти проектов, на которых фреймворк держит совместимость.

## Обход, применённый сейчас

Архивация проведена по **Option B** протокола (ручная генерация имени) после проверки, что
родительского архива 014 и `plan-014-*` не существует. Результат:
`docs/tasks/task-014-t014-http-transport-auth-perimeter-profiles-shared-limiter.md` +
`docs/plans/plan-014-…md`, `rebase_links.py` — 4 и 54 переписанных ссылки, 0 требующих разбора.
