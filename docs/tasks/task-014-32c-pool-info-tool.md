# Задача 014.32c: логика `onchain_pool_info` и сверка инвентарей

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Снять заглушку `onchain_pool_info`: по адресу пула вернуть адреса обоих токенов, резервы и уровень
комиссии. Свести манифест способностей с набором тулов гейтом.

**Why.** Решение владельца: направление 1 закрытия
[L-15](../issues/l-15-pool-info-is-advertised-by-the-capability-manifest-and-no-tool-serves-it.md).
Оно разблокирует WI-56 — резолв символа в адрес контракта, которого не хватило в анализе berachain.

**Зависимости.** Задачи 014-32a и 014-32b. 32a задаёт число сетей, 32b — форму тула и его схемы.
Дополнительно 014-22: гейт на аргументы, порождающие хост, обходит опубликованную схему этого тула.

### Вход и выход

Схема ввода отгружена задачей 014-32b. Выход — `chain`, `resolved`, `pool`, `source`, `fetchedAt`.

**Ненайденный пул выражается через `resolved: false`, и `pool` там равен `null`.**

**Why.** Вендор отвечает HTTP 200 с телом `"pairs":null` (замер 2026-08-18 на
`0x0000000000000000000000000000000000000001` по `ethereum`). Пустой `Pool`, отрендеренный как успех,
читался бы как пул без токенов и без ликвидности — класс отказа L-10.

**Резервы лоссовые, и контракт это называет.** `liquidity.base` и `liquidity.quote` приходят
JSON-числами, уже округлёнными вендором. `reserveBase` и `reserveQuote` объявлены `number | null` и
играют роль проекции, как `emissionBtc` рядом с `emissionRaw`.

### Уровень комиссии

Пул без метода, отдающего комиссию, отвечает типизированным отказом. Вывод — один `eth_call` метода
`fee()`, селектор `0xddca3f43`.

**Файл `packages/core/src/adapters/rpc-evm/index.ts` — владелец вывода:**

- `eth_call` становится третьим методом адаптера, рядом с `eth_gasPrice` и `eth_getBalance`
- Владелец назван архитектурой, а не выбран здесь: `docs/architectures/interfaces.md:720`,
  `` 1. `eth_call` becomes a third method on `rpc-evm`. The adapter calls `eth_gasPrice` ``

**Why это названо отдельным пунктом списка.** `eth_call` не встречается ни в одном файле под
`packages/` — метода нет, его создаёт эта задача. Без строки в списке изменений и без теста,
который падает при непостроенном выводе, задача сдаётся со всеми галочками, а `feeTierBps` остаётся
`null` на всех сетях: критерий «отсутствие комиссии выражено типизированным отказом» удовлетворяется
безусловным отказом.

**Сети, на которых поле выводимо.** Замер 2026-08-18: курированный `rpcHosts` есть у 19 сетей,
DexScreener обслуживает 65, пересечение — 16. Семейства `evm` среди них — 15.

`ethereum`, `arbitrum`, `base`, `bsc`, `polygon`, `avalanche`, `op-mainnet`, `mantle`, `cronos`,
`monad`, `ink`, `katana`, `plasma`, `flare`, `robinhood-chain`.

**Berachain остаётся без хоста.** Согласия владельца на курированный берачейновский RPC-хост нет.
До согласия задача отгружает на этой сети адреса токенов и резервы, а уровень комиссии отвечает
объявленным отказом.

### Сверка инвентарей

Гейт сравнивает ключи `capabilityManifests` с объединением `capability` и `servedCapabilities` по
`toolSpecs`. Постусловие: **каждый ключ манифеста либо обслуживается тулом, либо назван в
объявленном списке с причиной** (`docs/architectures/interfaces.md:810`,
`by a registered tool, or named in a declared list with a reason.`).

**Замер на дереве до T-014:** 26 ключей манифеста, 20 тулов, семь ключей не обслуживает никто —
`pool.info`, `token.metadata`, `privacy.shielded_pool`, `platform.identities`, `platform.documents`,
`platform.contracts`, `platform.credits`.

**Файл `docs/architectures/interfaces.md`:**

- Строка 813 — `**Seven manifest keys are served by no tool today**` — датированный замер
  (`measured 2026-08-13`), поэтому по R-23.6 текст сохраняется, а рядом ставится состояние после
  задачи: **шесть** ключей без тула, каждый со строкой объявленного списка, при 27 ключах и 22 тулах
- Строка 817 — `R-21.1 removes one of the seven. R-21.3 covers the other six` — база R-21.3;
  остаётся верной, правки не требует

**Почему шесть, а не один.** `pool.info` уходит из семёрки, потому что его обслуживает тул этой
задачи. Остальные шесть тула не получают — они получают строку объявленного списка с причиной, то
есть по-прежнему «served by no tool». Число ключей без тула после задачи — шесть.

**Why это в списке изменений.** Оба предложения задача цитирует как свой вход, и оба они описывают
дерево до неё. Утверждение «сегодня их семь» в настоящем времени переживает коммит, который делает
его ложным, — тот же класс, что и числа выше.

**Шесть оставшихся закрывает R-21.3, и это объём этой задачи**
(`docs/architectures/interfaces.md:817`,
`R-21.1 removes one of the seven. R-21.3 covers the other six: each gets a tool or a declared row`).
Каждый получает строку объявленного списка с причиной; причина пишется по существу, а не
механически.

## Тест-кейсы

### Сквозные тесты

1. **TC-E2E-01:** вызов по адресу известного пула возвращает адреса обоих токенов и резервы
2. **TC-E2E-02:** пул без метода комиссии отвечает типизированным отказом
   2a. **TC-E2E-02a:** пул **с** методом комиссии на сети с курируемым RPC-хостом возвращает
   `feeTierBps` числом; падает, если вывод не построен и отказ отдаётся безусловно
3. **TC-E2E-03:** адрес без пула на этой сети отвечает `resolved: false` и `pool: null`

### Модульные тесты

1. **TC-UNIT-01:** AC-29 — манифест не объявляет способности без резолвящего тула и без строки
   объявленного списка
2. **TC-UNIT-02:** `chainSupport` возвращает `true` для `pool.info` на сети без `nativeSymbol`
3. **TC-UNIT-03:** `chainSupport` возвращает `false` для `pairs.active` на сети без `nativeSymbol`
4. **TC-UNIT-04:** `extractFetchArgs` строит запрос `pool.info` на сети без `nativeSymbol`; падает
   при откате одного из двух экземпляров условия
5. **TC-UNIT-05:** адрес неверного формата отвергается до исходящего вызова

### Регрессионные тесты

- Снимок `tools/list` не меняется: форма отгружена задачей 014-32b
- Число тулов в тестах инвентаря не зашито
