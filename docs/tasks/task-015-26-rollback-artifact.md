# Задача 015.26: [VM · аддитивно] артефакт отката по перечню таблиц, вне обоих контейнеров

## Связь со сценариями

- UC-6 — таблицы движка переезжают в выделенный контейнер Postgres на dev-VM, шаг 10, первая
  половина

<!-- contract:goal -->

## Цель задачи

Снять дамп таблиц движка старого контейнера и положить его вне обоих контейнеров, чтобы удаление
задачи 015-27 имело путь отката.

**Why до удаления, а не после.** Задача 015-27 — единственная необратимая операция этапа. Артефакт,
снятый после неё, снимать было бы уже не с чего.

**Why файл, а не оставленные таблицы.** R-8.15 отвергает заморозку таблиц на месте: путь отката —
файл. Оставленные таблицы противоречили бы R-8.8, который требует, чтобы в старом контейнере не
осталось ни одной из них.

## Описание изменений

### Изменения в существующих файлах

**Файл `docs/onchain-analytics/PROD-RUNBOOK.md`:**

- Дописать в раздел о выделенном контейнере шаг снятия артефакта отката
- Записать команду с полным перечнем таблиц, путь размещения файла и срок хранения числом дней
- Записать размер файла и его контрольную сумму как признак существования артефакта
- Записать отклонение от буквы AC-47 одной строкой: критерий называет двенадцать таблиц и
  `--schema=onchain`, исполняется перечень из тринадцати `--table`, основание — MAJOR-7 раунда 1

### Отклонение от буквы AC-47 записывается

Критерий приёмки и архитектура называют объём артефакта по-разному, и исполняется одна редакция.

| Редакция                                      | Что говорит                                              |
| :-------------------------------------------- | :------------------------------------------------------- |
| Текст AC-47 (`docs/TASK.md:720`)              | `pg_dump --schema=onchain`, **двенадцать** таблиц        |
| Архитектура (`deployment.md` §10.9.6, `:948`) | `--schema=onchain --format=custom`                       |
| Исполняется                                   | тринадцать `--table` поимённо, `--schema` не применяется |

**Why исполняется третья редакция.** `--schema=onchain` захватывает снапшоттерские `assets`,
`metrics`, `snapshots`, живущие в той же схеме и к переезду не относящиеся (R-8.3) — это находка
MAJOR-7 раунда 1 ревью архитектуры. Число «двенадцать» в тексте критерия — счёт таблиц T-014, до
появления `client_usage`; перечень удаляемого задачей 015-27 состоит из тринадцати имён, и артефакт
обязан покрывать его целиком.

**Why отклонение записано, а не исполнено молча.** Две редакции одного требования, из которых
исполняется одна, — это решение, а не деталь; та же форма записи применена в задаче 015-23 к
отклонению от буквы R-8.14 и в записи `WI-62` — к R-8.10. Спецификация этой задачей не правится:
принятый текст критерия остаётся как есть, а расхождение с ним объявлено здесь и повторено строкой
рантбука.

**Что проверяется вместо буквы.** Приёмка идёт по существу критерия — артефакт СУЩЕСТВУЕТ вне обоих
контейнеров до удаления — и по перечню имён, равному перечню операторов `DROP` задачи 015-27
(TC-OPS-03), а не по числу двенадцать и не по наличию `--schema`.

### Артефакт содержит ДВЕНАДЦАТЬ таблиц при тринадцати названных, и это ожидаемо

Решение `MAJOR-F` раунда 2 держит `client_usage` только на новом контейнере: миграция
`004_t015_billing.sql` к `supabase-db` не применяется (`docs/architectures/deployment.md` §10.9.4,
§10.9.7). Старый контейнер тринадцатой таблицы не несёт никогда, поэтому дамп со старой стороны
физически содержит двенадцать.

**Измерено на dev-VM 2026-08-26.** `pg_dump` с `--table` на несуществующую таблицу рядом с
существующей завершает работу **кодом 0** и выдаёт дамп без неё — ни ошибки, ни предупреждения.
Проверено командой
`pg_dump -U supabase_admin -d postgres --schema-only --table=onchain.providers --table=onchain.client_usage`.

**Почему перечень всё же остаётся из тринадцати имён.** `TC-OPS-03` существует ради равенства двух
множеств — команды дампа и операторов `DROP` задачи 015-27. Убрать имя из одного перечня значит
разрушить это равенство и вернуть дефект `m-5` раунда 1, ради закрытия которого множества и
сводились. Тринадцатое имя остаётся оборонительным: если таблица там всё же окажется, она попадёт
и в дамп, и в удаление.

**Что из этого следует для приёмки.** Расхождение «названо тринадцать, восстановлено двенадцать»
допустимо **ровно для одного имени** — `client_usage`. Любое другое отсутствующее имя есть молчаливая
потеря, которую код возврата `pg_dump` не покажет. `TC-OPS-04` обязан сверять перечень
`pg_restore --list` с ожидаемым множеством поимённо, а не по числу строк, и называть недостающее.

### Объём дампа — перечень таблиц, не схема (MAJOR-7 раунда 1)

Проектная команда §10.9.6 ограничивает дамп схемой:
`docs/architectures/deployment.md:948` — подстрока `--schema=onchain --format=custom`. Схема
`onchain` — общая: в ней же живут три таблицы снапшоттера, и `--schema=onchain` захватывает контур,
к переезду не относящийся (R-8.3). Это находка MAJOR-7 раунда 1.

Дамп поэтому перечисляет таблицы поимённо:

```bash
ssh vm 'docker exec -i <old-container> pg_dump -U postgres -d postgres --format=custom \
  --table=onchain.users --table=onchain.access_profiles --table=onchain.api_tokens \
  --table=onchain.access_audit --table=onchain.provider_buckets --table=onchain.request_trace \
  --table=onchain.diagnostics --table=onchain.retention_runs --table=onchain.providers \
  --table=onchain.cache_entries --table=onchain.usage --table=onchain.usage_window \
  --table=onchain.client_usage' \
  > wi62-rollback-<date>.dump
```

**Why тринадцать имён, а не двенадцать и не одиннадцать.** Перечень артефакта совпадает с перечнем
удаляемого — по имени, а не по ожидаемому числу строк:

| Множество                          | Число | Основание                                  |
| :--------------------------------- | :---- | :----------------------------------------- |
| таблицы движка на новом контейнере | 13    | R-8.2, задача 015-21                       |
| таблицы движка в старом контейнере | 12    | `client_usage` там не заводилась (MAJOR-F) |
| таблицы, чьи строки переносились   | 11    | без `provider_buckets` (R-8.11)            |
| операторы `DROP` задачи 015-27     | 13    | перечень задачи 015-27                     |
| таблицы в артефакте отката         | 13    | тот же перечень имён                       |

**Why `client_usage` названа, хотя её в старом контейнере быть не должно.** Посылка «не
заводилась» держится предусловием MAJOR-F, а не замером: dev-VM была недоступна на момент
планирования. `pg_dump` по отсутствующей таблице отказывает, и этот отказ — наблюдаемый признак
того, что посылка неверна: он останавливает этап до необратимой операции. Перечень из двенадцати
имён того же признака не даёт.

**Why `provider_buckets` входит в дамп, хотя её строки не переносились.** Удаление её тоже
стирает. Артефакт, не покрывающий одну из удаляемых таблиц, откатывает не то состояние, которое
было.

**Why снапшоттерские таблицы не входят.** `assets`, `metrics`, `snapshots` остаются в старом
контейнере и не удаляются (R-8.3, AC-18). Их присутствие в дампе сделало бы восстановление из него
источником второй копии живых данных снапшоттера.

### Размещение и срок хранения

| Свойство      | Значение                                                |
| :------------ | :------------------------------------------------------ |
| место         | машина оператора, вне файловых систем обоих контейнеров |
| срок хранения | 30 дней от даты снятия                                  |
| репозиторий   | файл в него не попадает                                 |

**Срок хранения — 30 дней; применено, не измерено.** Величина назначена: замера, из которого её
можно было бы вывести, нет. Требование называет её `N дней` (R-8.15), а `N` приёмкой не проверяется
— поэтому число названо здесь. Владелец может назначить другое, и тогда правится эта строка.

**Why файл не попадает в репозиторий.** Дамп несёт `api_tokens.token_hash` и строки `users`.
Хранилище держит дайджест, а не токен (`docs/architectures/security.md:1075` — подстрока
`digest only`), но дайджест — это всё ещё материал аутентификации, а перец к нему живёт в `.env`
сервера. Репозиторий и общие каталоги для него не место.

**Why контрольная сумма записывается вместе с путём.** AC-47 требует, чтобы артефакт СУЩЕСТВОВАЛ до
удаления. Запись «дамп снят» без размера и суммы не отличает снятый дамп от пустого файла.

## Тест-кейсы

### Замеры на dev-VM

1. **TC-OPS-01 (AC-47):** артефакт существует вне обоих контейнеров
   - Входные данные: путь файла на машине оператора
   - Ожидаемый результат: файл существует, размер больше нуля; путь не принадлежит файловой системе
     ни одного из контейнеров
2. **TC-OPS-02 (MAJOR-7):** дамп ограничен перечнем таблиц движка
   - Входные данные: `pg_restore --list` по снятому файлу
   - Ожидаемый результат: перечень содержит таблицы движка, найденные в старом контейнере;
     `assets`, `metrics`, `snapshots` в нём отсутствуют
3. **TC-OPS-03:** перечень команды совпадает с перечнем `DROP` задачи 015-27
   - Входные данные: имена `--table` команды и имена операторов `DROP TABLE` файла 015-27
   - Ожидаемый результат: множества имён равны; `provider_buckets` и `client_usage` есть в обоих
   - Падает при мутации: имя удалено из одного перечня
4. **TC-OPS-04:** дамп восстановим, и его состав назван поимённо
   - Входные данные: восстановление файла в пустую временную базу; `pg_restore --list` по файлу
   - Ожидаемый результат: перечень восстановленных имён равен двенадцати таблицам миграции 002;
     единственное допустимое отсутствие — `client_usage` (`MAJOR-F`); любое другое недостающее имя
     есть отказ. Число строк по каждой таблице совпадает с числом, снятым verify-гейтом задачи
     015-24 на старом контейнере
   - Падает при мутации: имя убрано из команды дампа — `pg_dump` по-прежнему выходит кодом 0,
     и только сверка перечня показывает потерю
5. **TC-OPS-05:** старый контейнер не изменён снятием дампа
   - Входные данные: число строк по таблицам движка до и после команды
   - Ожидаемый результат: пары чисел совпадают
6. **TC-OPS-06:** срок хранения назван числом
   - Входные данные: раздел runbook
   - Ожидаемый результат: указано число дней и дата снятия; формулировки `N дней` в записи нет
7. **TC-OPS-06a:** отклонение от буквы AC-47 записано
   - Входные данные: раздел runbook и этот файл задачи
   - Ожидаемый результат: названы обе редакции — «двенадцать таблиц, `--schema=onchain`» и
     исполненная «тринадцать `--table`» — и основание отклонения
   - Падает при мутации: записана только исполненная команда, редакция критерия не названа
8. **TC-OPS-07:** файл не попал в репозиторий
   - Входные данные: `git status --porcelain` и перечень отслеживаемых файлов
   - Ожидаемый результат: файла дампа среди них нет

## Примечания

Этап: **Этап 6. Переезд таблиц движка на выделенный контейнер (dev-VM)**. Проход: **ops**.
Зависимость: 015-25 (писатель переключён, аутентификация выпущенным токеном проверена).

**Предусловие исполнения.** dev-VM обязана быть доступной. На момент планирования `ssh vm` отвечал
таймаутом устойчиво, и числа строк в таблицах старого контейнера не измерены. Числа для TC-OPS-04
берутся из verify-отчёта задачи 015-24, снятого в момент переезда.

Задача 015-27 удаляет таблицы в старом контейнере и требует явного подтверждения владельца по skill
`vm-deploy`. Существование этого артефакта — одно из трёх её предусловий.

Проектная координата: `docs/architectures/deployment.md:944` —
`#### 10.9.6. Rollback artifact, before any deletion (R-8.15, AC-47)`.

Требования: R-8.15, MAJOR-7 раунда 1 ревью архитектуры.
