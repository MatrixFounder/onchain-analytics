# Directory: packages/core/src/adapters/nansen/

## Purpose

The tenth `providers.config.ts` adapter — `nansen` — and the FIRST paid one (ARCHITECTURE.md §3.2
"Десятый адаптер", M2/TASK-005, R-29/R-30). Backs three canonical M2 capabilities
(`smart-money.flows`, `entity.labels`, `token.risk`) over REST `api.nansen.ai`. Auth is a single
custom header, literally `apiKey: <NANSEN_API_KEY>` — **not** the generic Web credentials header +
its token-prefix scheme some other Nansen surfaces use (task 005-3 M-4 reviewer finding: getting
this wrong fails EVERY resync, a silent total lockout — this whole directory is grepped for that
wrong scheme's two literal words in every task's acceptance, which is why this file spells the
right one out instead — see budget-gate.ts's own `refreshAccount()` for the actual header). Never
the official Nansen MCP server (out of scope, see ARCHITECTURE.md §3.2 for why). This is a
brand-new directory (first commit, task 005-1) — bootstrap `.AGENTS.md` per this project's
new-directory memory policy.

**Real from task 005-5 (R-38/R-39) — the final composition, wired around the SAME `fetch()` body
above (§3.2 OQ-2 — never a second, bypassable call site):**

- The switch statement that used to live directly in `fetch()`'s body was factored out, unchanged,
  into a module-private `performSubCalls(cap, args, endpointDeps)` — returns both the "raw
  hand-off" shape `normalize()` expects (unchanged) AND a flat `subResponses:
NansenEndpointResult[]` (every sub-call's `{body, creditsUsedHeader}`, in call order) —
  `reconcile()`'s own input, since the typed `result` nests those fields under different names per
  capability.
- `fetch(cap, args)` now composes three layers around it, from the outside in:
  `singleflight(deriveArgsHash(cap, args), async () => {...})` (`singleflight.ts`, always active) →
  — inside, when `deps.budgetStore` was supplied at construction — `gate.ensureBudget(cap, args)`
  (`budget-gate.ts`, task 005-3, now genuinely called) → `performSubCalls()` → `reconcile()`
  (`reconcile.ts`) exactly once → return the raw result. A throw anywhere between `ensureBudget()`
  resolving and `reconcile()` completing (a sub-call's transport failure, `402`, or any other
  rejection) is caught by ONE `try/catch`: `accountState.markUnreconciled()` then rethrow — the
  reservation stays as the conservative fact, the NEXT `ensureBudget()` entry is forced to resync
  `/account` (system-architecture.md §3.2 "Post-call reconciliation + transport-failure/402
  resync"). A gate refusal (`NansenBudgetExceededError`, thrown by `ensureBudget()` itself) is
  OUTSIDE that `try/catch` — no reservation was ever made, so `markUnreconciled()` does not apply;
  the throw surfaces exactly like a network failure to `CapabilityRegistry.resolve()`'s own
  existing `try/catch` (`registry.ts`, ZERO edits) → `CapabilityUnavailableError` → `isError: true`.

### endpoints.ts, normalize.ts (new, task 005-4, R-29/R-31/R-32/R-33/R-45)

- `endpoints.ts` — one thin function per endpoint (`postSmartMoneyNetflow`/`postTgmHolders`/
  `postTgmIndicators`/`postTgmTokenInformation`/`postSearchGeneral`/`postSearchEntityName`/
  `postProfilerAddressLabels`), each `Promise<{body: unknown; creditsUsedHeader: string | null}>` —

  non-`ok`→plain `Error`, response body bounded via `stringifyTruncated()`) → `response.json()`.

### singleflight.ts, reconcile.ts (new, task 005-5, R-38/R-39)

- `singleflight.ts` — `createSingleflight(): <T>(key: string, fn: () => Promise<T>) => Promise<T>`,
  a factory over its own closed-over `Map<string, Promise<unknown>>` (one instance per adapter
  instance, never a module singleton). A `key` with an in-flight (not-yet-settled) entry returns
  that SAME promise instead of calling `fn()` again — the entry is written synchronously, before
  `singleflight()` returns, so two calls issued back-to-back with no `await` between them (the
  literal precondition every "coalescing" test case relies on) both observe it. The entry is
  deleted in a `finally`, on EITHER outcome, so a rejected call never leaves a permanently-stuck
  entry behind and a call arriving after settlement is a genuinely fresh attempt. Not exported from
  `index.ts`/the package — `index.ts`'s own `fetch()` is its only caller, keyed by the existing
  `net/args-hash.ts`'s `deriveArgsHash(capability, args)` (no new hashing primitive).
- `reconcile.ts` — `reconcile({subResponses, reservedTotal, bucket, budgetStore, accountState})`.
  Sums `subResponses[].creditsUsedHeader` (`Number()` + `Number.isFinite` guard per entry) into
  `actualTotal`, writes `actualTotal - reservedTotal` as ONE signed adjustment via
  `budgetStore`'s own additive-upsert write path, against the passed-in `bucket` — never a bucket
  recomputed from `Date.now()` at reconcile time (would misfile a cross-midnight call's adjustment
  into the WRONG day's row). A missing (`null`) OR unparseable header on ANY ONE `subResponse`
  degrades the WHOLE call's adjustment to `0` (never a partial sum — a partial sum systematically
  UNDER-reports real spend, worse than a conservative zero) + `accountState.markUnreconciled()` +
  exactly one stderr line. **This function is called EXACTLY ONCE per logical `fetch()`, always
  after every sub-call already succeeded** — this is the fix for a real, review-caught defect
  (C-1): reconciling per-sub-response instead would sum `(5-10) + (5-10) = 0` for a genuinely-spent
  10cr composite call (`smart-money.flows`/`token.risk`), silently canceling the counter on every
  paid call to those two capabilities. `nansen.reconcile.test.ts`'s TC-UNIT-01 asserts
  `getUsage === 10` (not `0`) directly against this defect.

`JSON.stringify` for the table's keys, which double-quotes — the committed file is single-quoted

a real vendor price change in reformatting noise; the generator now emits Prettier-conformant
single-quoted source directly, proven byte-idempotent across repeated bare re-runs (`md5` stable,
NO `prettier --write` needed in between). (2) The `150` premium-labels surcharge `cost-of.ts` uses
was a hand-maintained literal that could drift silently against the spec; it is now ALSO generated
(`cost-table.ts`'s `NANSEN_PREMIUM_LABELS_COST`, sourced from the spec's own
`x-credit-cost-variants['premium_labels=true']` on `/tgm/holders`), so a future vendor change to
either number shows up as an ordinary `cost-table.ts` diff, never silently.
