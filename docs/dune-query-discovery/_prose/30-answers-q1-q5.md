## Q1. Как агент программно находит существующий запрос/дашборд под NL-вопрос

**Ответ:** Официальной бесплатной программной поверхности для полнотекстового поиска ЧУЖИХ запросов не существует. Полный перечень поверхностей, как он реконструируется из данных:

| # | Поверхность | Офиц. | Free | Что реально ищет |
|---|---|---|---|---|
| 1 | Официальный Dune MCP, Discovery: `searchDocs`, `searchTables`, `listBlockchains`, `searchTablesByContractAddress`, `getTableSize` | да | не установлено | таблицы и доки; **тула поиска чужих запросов НЕТ** |
| 2 | `POST /v1/datasets/search` | да | не установлено | ТАБЛИЦЫ (единственный search в OpenAPI), не запросы |
| 3 | `GET /v1/queries` | да | нет (гейт, см. Q3) | список СВОИХ запросов |
| 4 | `GET /v1/query/{queryId}` | да | нет (гейт, см. Q3) | чтение объекта запроса по известному id, не поиск |
| 5 | `GET /v1/dashboards/by-slug/{owner_handle}/{slug}` | да | **unverified** | единственный документированный мост «человеческий URL дашборда → query_id»; требует знать slug заранее |
| 6 | UI-фильтры `code:"from dex.trades"`, `author:`, `tags:` (docs/web-app/search) | да | — | существуют **только в UI**, API-поверхности нет ⇒ для headless-агента непригодны |
| 7 | Внутренний search веб-приложения `core-api.dune.com` | нет | — | **не зондировался в этом прогоне вообще** |
| 8 | Внешний индекс `site:dune.com/queries` | нет | — | не профилировался и не реджектился |

Ключевой вывод: маршрут «NL-вопрос → готовый чужой запрос» на документированных официальных бесплатных поверхностях **не закрывается**. Закрывается другой маршрут — «NL-вопрос → нужные ТАБЛИЦЫ → собственный SQL».

**Доказательство:** orchestrator-crosscheck.md §1 (состав Discovery-тулов официального MCP; тула поиска чужих запросов нет). OpenAPI Dune: единственный search — `POST /v1/datasets/search`; `GET /v1/queries` — список своих. docs/web-app/search — фильтры `code:`/`author:`/`tags:` заявлены как UI-функция. По `core-api.dune.com` — «в scratchpad ни одного обращения, не зондировался».

**Confidence:** medium — сводная таблица «поверхность → офиц. → free» нигде в прогоне не собрана (КРИТИК помечает это как пробел); поверхность 7 не проверялась ни разу; плановый гейт для `dashboards/by-slug` первоисточником не установлен.

**Что делаем мы:** capability «найти чужой запрос под вопрос» не объявляем — в матрице покрытия фиксируем как отсутствующую бесплатную поверхность (это scope-решение, не пропуск). Discovery строим на `searchTables`/`datasets/search` + генерация собственного SQL. Отдельным follow-up — зондаж `core-api.dune.com` и живая проверка плана для `dashboards/by-slug`; до их закрытия обе строки идут как `unverified`.

## Q2. Исполнение ЧУЖОГО публичного запроса: план, цена, `POST /execute` vs `GET /results`

**Ответ:** Чужой публичный запрос читается, но не исполняется.

- `GET /v1/query/{id}/results` работает для любого публичного запроса, **не триггерит исполнение**, тарифицируется по размеру выгруженного результата — на Free это 20 кредитов/МБ (класс «Data Export»).
- `POST /v1/query/{id}/execute` имеет задокументированный отказ **403 «Not allowed to execute query… not enough permissions»** — то есть право на запуск чужого запроса гейтится не планом, а правами владения.
- Разница по существу: `execute` запускает новое вычисление (списание за compute, формула не публикуется — см. Q4) и требует прав; `results` читает последний закэшированный результат (списание за объём выгрузки) и требует лишь публичности. Контур асинхронности execute→poll→results у нас уже описан.
- Через MPP этот класс недоступен вовсе: `POST /v1/query/{query_id}/execute`, `GET /v1/query/{query_id}/results` и `/results/csv` идут **без** `x-payment-info` — 43 из 47 операций вне MPP. Keyless-путь чужие сохранённые запросы не исполняет и не читает.
- Не установлено: минимальный заряд за чтение результата и класс rate-limit для `/query/{id}/results` — этот эндпоинт не перечислен ни в low-, ни в high-таблице лимитов.

**Доказательство:** api-reference/executions/endpoint/get-query-result:17 — дословно «must either be public or a query you have ownership of». overview/billing, класс «Data Export» — Free 20 кредитов/МБ. Документированный 403 «Not allowed to execute query… not enough permissions» у `POST /v1/query/{id}/execute`. api-reference/overview/rate-limits — `/query/{id}/results` в таблицах low/high отсутствует. https://api.dune.com/openapi.json — отсутствие `x-payment-info` у `/v1/query/{query_id}/execute` и `/v1/query/{query_id}/results`. ARCHITECTURE.md:69-74 — наш контур execute→poll→results.

**Confidence:** medium — доковая часть закрыта дословными цитатами, но живого подтверждения на Free нет ни одного: ключа в прогоне не было, вызовов по этому маршруту не делалось; стоимость чтения и класс лимита не документированы.

**Что делаем мы:** маршрут «чужой публичный запрос» реализуем **только** через `GET /v1/query/{id}/results`, `POST /execute` по чужому query_id в код не заводим вообще (документированный 403 = гарантированный отказ, а не деградация). Токен-бакет (`packages/core/src/net/rate-limit.ts:102-140`) для этого эндпоинта настраиваем по консервативному low-классу 15 rpm, раз собственный класс не объявлен. Первое, что делаем при появлении Free-ключа: одна живая проба `results` по известному публичному query_id — до неё цена и класс идут `unverified`.

## Q3. Создание/форк запроса через API на бесплатном плане

**Ответ:** Нет, и это же перекрывает чтение SQL чужого запроса. Первоисточник при этом сам себе противоречит в том, КАКОЙ план требуется:

- «To access Query endpoints, an Analyst plan or higher is required» — queries/endpoint/create:15 и queries/endpoint/read:17.
- «Queries Endpoint — Available on Plus and Enterprise plans» — overview/billing:65-67.
- Analyst против Plus — противоречие не разрешено, связывающий план **unverified**. Для нашего решения это неважно (оба выше Free), но важно для оценки стоимости апгрейда.

Обходы:
1. **`POST /v1/sql/execute`** — freeform SQL без сохранённого запроса, `x-required-scope: Read` (скоуп ключа, не план), планового гейта в доке нет; Data API включён во все планы, включая Free с 2 500 кредитами/мес. Дополнительно этот же эндпоинт — единственный, доступный keyless через MPP: живой челлендж резервирует $4.00 при том, что OpenAPI обещает «Reserves $5.00» (дефект доки).
2. **`select * from query_<id>`** (Query Views, с пробросом параметров) — переиспользование чужого сохранённого запроса как таблицы из собственного freeform SQL, без форка. В прогоне ушло ниже линии и **не профилировалось** ⇒ unverified.
3. Оговорка к обходу 1: флаг `isFreeformAllowed` в объекте запроса намекает на аккаунт-гейт freeform SQL — не проверен.

MPP как обход создания/форка не годится: `/v1/queries*` идут без `x-payment-info`.

**Доказательство:** queries/endpoint/create:15, queries/endpoint/read:17 (дословно «Analyst plan or higher»); overview/billing:65-67 (дословно «Plus and Enterprise plans»). https://api.dune.com/openapi.json — `POST /v1/sql/execute`, `x-required-scope: Read`, `x-payment-info` = «Reserves $5.00; actual cost based on execution compute.»; живой 402-челлендж 2026-07-27T16:06Z: amount=4000000 (инвариантно к телу SQL, 4 прогона). https://docs.dune.com/docs/agents/mpp — «no API keys, no user account, and no credit card required».

**Confidence:** medium — вывод «нет» стоит на доке, которая противоречит сама себе по плану; живой проверки не было; главный обход (Query Views) не профилирован; `isFreeformAllowed` не проверен.

**Что делаем мы:** capability «создать/форкнуть запрос» не реализуем. Штатный путь — `POST /v1/sql/execute` с нашим собственным SQL. Немедленный follow-up с приоритетом 1: живая проверка `select * from query_<id>` на Free-ключе — это единственный кандидат, который даёт переиспользование community-работы легально и без апгрейда плана. Одновременно закладываем контур ограничения модель-сгенерированного SQL (allowlist таблиц, запрет DDL/upload, кап на объём результата) — он становится обязательным ровно в момент, когда ответом становится `/sql/execute`; сейчас его нет.

## Q4. Экономика free-tier и формула «сколько агентских вопросов в месяц»

**Ответ:** Все публичные константы известны; центральный множитель формулы вендором **сознательно не публикуется**, поэтому число вопросов/мес из доки не выводится.

Что списывается и по каким тарифам (Free):
- Пул: **2 500 кредитов/мес**; докупка — **$5.00/100** кредитов.
- Выгрузка результата (Data Export): **20 кредитов/МБ**.
- Запись: **3 кредита/ГБ**. Storage: **100 МБ**. Webhooks: **1**.
- Rate limits: **15 rpm** (low) + **40 rpm** (high), комбинированно **55**. Класс для `/query/{id}/results` не объявлен.
- Исполнение (compute): цена **unverified**. Дословно: «we don't share a single, per-query formula because credit usage depends on real-time factors».

Формула: `N = 2 500 / (C_exec + 20 × S_МБ)`, где `C_exec` — кредиты за исполнение (**unverified**), `S_МБ` — размер результата. Один член формулы принципиально недоступен из документации ⇒ **N не вычисляется**. Числовой потолок я намеренно не считаю: пересчёт запрещён правилом чисел.

Единственные измерители фактического расхода: поле `execution_cost_credits` в `GET /v1/execution/{id}/status` и дельта `POST /v1/usage`. Ни один в прогоне не снят — ключа не было.

Рычаги и поведение на исчерпании: `max_credits_per_request` / `ignore_max_credits_per_request` названы, но не профилированы; поведение при исчерпании (**402** + тумблер extra-credit limit) ушло ниже линии ⇒ unverified.

Альтернативная кривая MPP (для сравнения планов, из ДОБИВОК): MPP = **$1.00/МБ** ≡ Free `20 кредитов/МБ × $5.00/100` = **$1.00/МБ (1.00×)**; Analyst `10 × $1.875/100` = **$0.1875/МБ** ⇒ MPP дороже в **5.33×**; Plus `2 × $1.596/100` = **$0.03192/МБ** ⇒ в **31.3×**. Резервы живых челленджей: execute **$4.00**, results и results/csv по **$1024.00**, status **$0.00** (сырые amount: 4000000 / 1024000000 / 0). Цифра «amount 10710 ≈ $0.0107/запрос» из КРИТИКА — **unverified**, живой пробой не воспроизводится.

**Доказательство:** resources/credits-billing/how-credits-work — 2 500 кредитов/мес, $5.00/100. overview/billing — 20 кредитов/МБ (Data Export), 3 кредита/ГБ, storage 100 МБ, webhooks 1. overview/rate-limits — 15 rpm low, 40 rpm high, комбинированно 55; `/query/{id}/results` не перечислен. Дословный отказ Dune публиковать формулу — там же, в кредитной доке. https://api.dune.com/openapi.json (HTTP 200, 200 145 B) — x-payment-info по 4 операциям. Живые 402-челленджи api.dune.com 2026-07-27T16:06Z (`WWW-Authenticate: Payment`, `method="tempo"`, `intent="session"`): 4000000 / 1024000000 / 1024000000 / 0. Валюта — Tempo mainnet RPC https://rpc.tempo.xyz: `eth_chainId=0x1079` (4217), на `0x20c000000000000000000000b9537d11c60e8b50` `symbol()='USDC.e'`, `decimals()=6`; `suggestedDeposit=10000000` = $10.00, совпадает с `maxDeposit:"10"` в доке.

**Confidence:** low по итоговому N (вендор отказывается публиковать центральный множитель — это не наш пробел, а закрытая величина); high по перечисленным опубликованным константам.

**Что делаем мы:** бюджет в кредитах планировать априори нельзя — переходим на измерение по факту. (1) После каждого исполнения читаем `execution_cost_credits` из `GET /v1/execution/{id}/status` и пишем в существующий провайдер-агностичный леджер `packages/core/src/cache/budget-store.ts:46-93` (ключ `provider: string`); сверка — дельтой `POST /v1/usage`. (2) `max_credits_per_request` выставляем жёстким капом на вызов, `ignore_max_credits_per_request` запрещаем. (3) `dune` добавляем в `PAID_PROVIDER_IDS` (`packages/core/src/cache/sqlite-store.ts:48`). (4) Параметризуем `packages/mcp-server/src/tools/budget-meta.ts:9` и `:38` — они жёстко зашиты на литерал `'nansen'`, второй кредитный провайдер в `_meta` иначе не появится. (5) MPP-доллары в кредитный леджер **не** заводим: MPP не отдаёт `credits_used` вообще, единица учёта — USDC.e, факт-списание приходит в `Payment-Receipt`, и один вызов для guard'а невидим; вдобавок резерв $1024.00 за results на два порядка выше `suggestedDeposit` $10.00 и упрётся в депозит. MPP-путь — только после расширения budget-guard до двух единиц учёта, с горячим кошельком вне общего `.env`-контура (`.gitignore:53`) и обязательным `session.close()` в `finally`.

## Q5. Чек-лист проверки корректности чужого запроса

**Ответ:** Чек-лист распадается на два уровня, потому что его первый шаг на Free невыполним.

**Блокирующая оговорка.** «Прочитать SQL чужого запроса» через API на Free невозможно: `GET /v1/query/{id}` гейтится тем же Query-endpoints-гейтом (queries/endpoint/read:17), а через UI это скрапинг, запрещённый фильтром §5 брифа. Значит на Free доступна только чёрно-ящиковая проверка результата.

**Уровень A — работает на Free (чёрный ящик, результат):**
1. Взять число через `GET /v1/query/{id}/results` (не запускает исполнение, см. Q2).
2. Независимая сверка вне Dune — этот шаг в прогоне отработан живьём и является самой надёжной частью чек-листа: keyless DuckDB по AWS Public Blockchain Data (btc/blocks 2026-07-26 = **146 блоков / 758 094 tx за 3.3 с**), точечная сверка с mempool.space (h=959763, `tx_count` **4590**, совпадение точное), и вторая ось — Blockchair `circulation` **20 062 011.67 BTC** против расчётной эмиссии, Δ **32.08 BTC** = **0.00016%**.
3. Правило вердикта: составное утверждение считается подтверждённым, только если подтверждены все материальные под-утверждения; расхождение по любой оси — отказ, а не усреднение.

**Уровень B — требует Analyst/Plus (белый ящик, SQL):**
4. Владение и видимость: поля `is_private`, `owner` объекта запроса.
5. Параметры: поле `params`; **как читать дефолты параметров, не читая SQL, — в прогоне не зафиксировано** (открытый пункт).
6. Таблицы: отличить curated-модель Spellbook от сырой таблицы и от чужого upload. Инструмент есть — дерево Spellbook выкачано, **14 805 путей**, **34 bitcoin-модели**, годится как статический allowlist. **Сам критерий различения в чужом SQL в прогоне не зафиксирован** (открытый пункт).
7. Свежесть: **какое поле даёт свежесть последнего исполнения — не зафиксировано** (открытый пункт). Смежно: `GET /v1/execution/{id}/status` документирован как статус-эндпоинт и в MPP тарифицируется как «Free status polling» (amount 0).

**Доказательство:** queries/endpoint/read:17 (гейт на чтение). Поля `is_private` / `params` / `owner` — объект запроса Dune. Spellbook-дерево прогона: 14 805 путей, 34 bitcoin-модели. verification_log.txt: AWS Public Blockchain Data через keyless DuckDB, btc/blocks 2026-07-26 = 146 блоков / 758 094 tx за 3.3 с; h=959763 `tx_count` 4590 совпал с mempool.space точно. Профиль Blockchair: `circulation` = 20 062 011.67 BTC против расчётной эмиссии, Δ 32.08 BTC = 0.00016%. https://api.dune.com/openapi.json — `GET /v1/execution/{id}/status`, x-payment-info «Free status polling.», живой amount=0.

**Confidence:** medium — сверочная нога (шаг 2) доказана живыми пробами по двум независимым осям, но три пункта уровня B (поле свежести, различение Spellbook/raw, дефолты параметров) в прогоне не разрешены, а шаг 4-7 целиком недоступны на Free.

**Что делаем мы:** внедряем чек-лист как двухуровневый гейт: ни одно число из чужого запроса не попадает в продовый ответ без пройденного уровня A. Уровень A строим на бесплатных источниках, уже проверенных живьём: AWS Public Blockchain Data через DuckDB как первичный, mempool.space как точечный. **Blockchair в горячий путь не ставим** — его keyless-режим опровергнут: после 2 успешных запросов приходит HTTP 430 на весь IP и держится дольше окна наблюдения; годится только как кэшируемый фоновый источник с длинным TTL и негативным кэшем на 430. Список путей Spellbook (14 805) кладём статическим артефактом-allowlist'ом в репозиторий и используем и для уровня B, и для ограничения модель-сгенерированного SQL из Q3. Три открытых пункта уровня B оформляем как follow-up с явным `unverified`, а не закрываем догадкой.
