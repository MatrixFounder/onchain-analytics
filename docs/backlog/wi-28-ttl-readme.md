# WI-28 — Колонки TTL и кредитов в двух README не сверяются с кодом

> Origin: T-011, состязательный цикл 2 (линза slop), 2026-08-02.

**Сигнал.** T-011 добавил в `README.md` и `README.ru.md` по пять новых секций и по пять строк в
таблицу «Tool reference». Строки несут не только имя тула, но и **TTL** и **стоимость в кредитах**.

Гейт `tool-inventory-docs.test.ts` требует от README полноты **только по именам тулов**. Значения
TTL и кредитов теперь пересказаны в двух файлах на двух языках и не сверяются ни с
`packages/core/src/cache/ttl.ts`, ни между собой.

**Что проверено на сегодня.** Расхождений нет: обе таблицы совпадают друг с другом, и колонка TTL
совпадает с `ttl.ts` (60/60/30/300/300/3600/3600/600/300/1800/3600). Число «458 сетей» тоже сходится
с `registry.data.json`. То есть это не дефект сейчас, а незакрытый класс.

**Почему это стоит закрыть.** Ровно этот класс — факт о тулах, пересказанный в README и не
сверяемый ничем — прожил в этих двух файлах четыре сданные задачи (восемь имён из тринадцати,
с TASK-006). Механика для сверки уже есть: `docs-counts.test.ts` умеет извлекать утверждение из
документа и сравнивать с кодом (см. блочную сверку «тул ↔ capability»).

**Как чинить.** Извлекать TTL-колонку из обоих README и сравнивать с `ttl.ts` тем же приёмом;
заодно сравнить две языковые версии между собой построчно.
