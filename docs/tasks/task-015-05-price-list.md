# Задача 015.05: прайс-лист — компилируемые данные, ключ `capability ?? tool`, значение `TEXT`

## Связь со сценариями

- UC-8 — прайс-лист версионируется независимо от уже списанных строк
- UC-1 — списание на границе тула читает цену прайс-листа

<!-- contract:goal -->

## Цель задачи

Объявить прайс-лист компилируемым модулем так, чтобы резерв читал цену из памяти до `resolve()`.

**Why модуль, а не таблица.** `data-model.md` §4.6.2 относит прайс-лист к классу манифеста
способностей: офлайн-гейт, детерминизм CI и читаемость диффа. Таблица добавила бы миграцию и
обращение к базе на пути резерва.

**Why задача идёт до писателей леджера.** Цену читают резервы обеих осей хранилища (015-06, 015-07).
Один источник цены до двух писателей дешевле, чем согласование двух источников после.

## Описание изменений

### Новые файлы

**Файл `packages/mcp-server/src/billing/price-list.ts`:**

- Объявить `DEFAULT_PRICE_RAW` со значением `'1'` (R-4.6;
  `docs/architectures/data-model.md:1972` — `export const DEFAULT_PRICE_RAW = '1'`)
- Объявить `PRICE_LIST` типом `Readonly<Record<string, string>>` через `Object.freeze`
- Объявить функцию поиска цены; её параметры — статическая способность, имя тула и перечень цен
- Перечень цен по умолчанию — `PRICE_LIST`; параметр объявлен ради теста, а не ради конфигурации

**Why пакет `mcp-server`.** `data-model.md` §4.6 держит `client_usage` в этом пакете: строка несёт
`principal_id` и `access_profile_id`. Цена читается на том же пути и живёт рядом с ним.

**Файл `packages/mcp-server/test/price-list.test.ts`:**

- Тест-кейсы TC-UNIT-01 … TC-UNIT-06 ниже

### Ключ поиска — `capability ?? tool`

| Что объявляет тул       | Ключ поиска           |
| :---------------------- | :-------------------- |
| статическую способность | значение `capability` |
| `capability === null`   | имя тула на проводе   |

`docs/architectures/data-model.md:1981` — подстрока `The lookup key is`.

**Why статическая способность, а не разрешённая.** Резерв стоит до `resolve()` (R-2.1), а
`resolvedCapability` известна только после возврата обработчика. На момент поиска цены существует
одно из двух значений.

**Why имя тула — законный ключ, а не запасной путь.** Два тула резолвят способность к `null`:
`packages/mcp-server/src/tools/registry.ts:473` — `answer synchronously and resolve no capability`.
Для них имя тула — единственная координата, которой цена может принадлежать.

**Отсутствующий ключ разрешается в `DEFAULT_PRICE_RAW`.** Перечень фазы 0 пуст (R-4.4), и умолчание
тарифицирует все тулы одинаково без единой строки в перечне.

### Форма значения — `TEXT`

Цена — строка десятичных цифр, никогда `number`.

**Why строка.** `DB-SCHEMA-CONCEPT` §1 п.7 называет кредиты поимённо как случай, требующий строки:
целые сверх 2^53 теряют точность в `number`. Ту же форму уже несёт
`access_profiles.credits_balance_raw`, поэтому резерв сравнивает две строки, а не строку и число.

**Why сравнение цены и баланса не входит в эту задачу.** Арифметика баланса принадлежит оси
хранилища и живёт в задачах 015-06 и 015-07. Здесь цена только читается.

### Цена — значение, а не идентификатор

Модуль отдаёт строку цены. Резерв копирует её в `client_usage.price_raw`
(`docs/architectures/data-model.md:1756` — `price_raw          TEXT NOT NULL`).

**Why копия, а не ссылка на строку прайс-листа.** Ссылка позже разрешилась бы другим числом, и
запись `settled` изменила бы цену задним числом (R-4.2, R-4.3, AC-8, AC-9).

**Модуль не экспортирует функции, разрешающей цену уже записанной строки.** Отсутствие такой функции
и есть механизм AC-9: перечитывать нечем.

### Модуль не несёт поля версии

**Why.** Версию прайс-листа никто не читает независимо от `price_raw` самой строки. Второе поле было
бы вторым источником того же факта (`docs/architectures/data-model.md:1997` —
`**Why this module carries no version field.**`).

## Тест-кейсы

### Модульные тесты

1. **TC-UNIT-01:** отсутствующий ключ разрешается в умолчание
   - Входные данные: пустой перечень цен, способность `'token.holders'`, тул `'onchain_token_holders'`
   - Ожидаемый результат: возвращено `'1'`; значение равно `DEFAULT_PRICE_RAW`
   - Падает при мутации: умолчание заменено на `'0'`
2. **TC-UNIT-02:** объявленная способность выигрывает у имени тула
   - Входные данные: перечень `{ 'token.holders': '5', onchain_token_holders: '7' }`
   - Ожидаемый результат: возвращено `'5'`
3. **TC-UNIT-03:** тул без статической способности ищется по имени на проводе
   - Входные данные: способность `null`, тул `'onchain_ping'`, перечень `{ onchain_ping: '3' }`
   - Ожидаемый результат: возвращено `'3'`
4. **TC-UNIT-04 (AC-43):** два тула с разными ценами разрешаются каждый в свою
   - Входные данные: перечень `{ 'token.holders': '5', 'chain.transactions': '2' }`
   - Ожидаемый результат: `'5'` и `'2'`; правки модуля поиска не потребовалось
5. **TC-UNIT-05 (AC-9):** смена перечня не меняет ранее прочитанную цену
   - Входные данные: цена по перечню v1 копируется в объект-строку леджера; тот же ключ читается по
     перечню v2 с другим значением
   - Ожидаемый результат: копия в объекте равна цене v1; чтение по v2 равно цене v2
   - Падает при мутации: функция возвращает ссылку на перечень вместо значения
6. **TC-UNIT-06:** перечень экспортов не содержит поля версии
   - Входные данные: `Object.keys(module)` и `Object.isFrozen(PRICE_LIST)`
   - Ожидаемый результат: перечень экспортов — `DEFAULT_PRICE_RAW`, `PRICE_LIST` и функция поиска;
     `PRICE_LIST` заморожен

## Критерии приёмки

- [ ] AC-8 — строка `settled` хранит применённую цену, не идентификатор прайс-листа: модуль отдаёт
      значение, и функции разрешения цены записанной строки не существует
- [ ] AC-9 — правка прайс-листа после записи строки не меняет цену этой строки (TC-UNIT-05)
- [ ] AC-43 — два тула с разными ценами резервируют верно (TC-UNIT-04)
- [ ] Умолчание `DEFAULT_PRICE_RAW` равно `'1'`
- [ ] Ключ поиска — статическая способность тула, при её отсутствии — имя тула на проводе
- [ ] Значение объявлено как `string`; `number` в модуле не появляется
- [ ] Модуль не несёт поля версии; тест фиксирует отсутствие второго источника той же цены

## Примечания

Этап 1 (схема, форма леджера и прайс-лист), проход `impl`. Зависимостей нет.

Перечень `PRICE_LIST` фазы 0 остаётся пустым (R-4.4). Требование выполняет механизм, а не число:
цена берётся строкой перечня, когда строка появится, и умолчанием, пока её нет.

Запись значения в `client_usage.price_raw` принадлежит задачам 015-06 (ось SQLite) и 015-07 (ось
Postgres). Чтение цены на границе тула принадлежит задаче 015-09.

Тот же вывод ключа `capability ?? tool` переиспользует окно реплея (015-08, `ttlFor`,
`packages/core/src/cache/ttl.ts:40` — `export function ttlFor(capability: string): number`). Задача
015-05 объявляет ключ; 015-08 применяет его к другой таблице.
