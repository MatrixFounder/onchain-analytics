# Задача 015.12: объявленный суточный потолок как форма — поле, десять строк, гейт старта `[STUB]`

## Связь со сценариями

- UC-3 — счётчик вызовов Blockscout переводит `entity.labels` на платный Nansen
- UC-4 — счётчик вызовов Blockscout жёстко отказывает на `token.holders`

<!-- contract:goal -->

## Цель задачи

Объявить поле `dailyCallCeiling` на `AdapterRegistration`, заполнить его на десяти бесплатных
регистрациях и закрыть отсутствие значения отказом старта процесса.

**Why форма раньше читателя.** Читателя поля вводят задачи 015-13…015-15. Поле, добавленное после
гейта, было бы выбрано под форму уже написанного гейта, а не под перечень провайдеров.

**Why тотальность обеспечивает гейт старта, а не тип.** `AdapterRegistration` — плоский интерфейс
без дискриминации по `tier` (`packages/core/src/adapters/types.ts:162` —
`export interface AdapterRegistration {`), массив один
(`packages/core/src/providers.config.ts:215` — `export const adapterRegistrations`). Обязательное
поле в типе потребовало бы значения и от двух платных регистраций, чего `data-model.md` §4.6.3
прямо не допускает.

## Описание изменений

### Изменения в существующих файлах

**Файл `packages/core/src/adapters/types.ts`:**

- Добавить в `AdapterRegistration` поле `dailyCallCeiling?: number | 'none';` рядом с `tier`
  (`packages/core/src/adapters/types.ts:190` — `tier: AdapterTier;`) и `trust`
  (`packages/core/src/adapters/types.ts:201` — `trust: AdapterTrust;`)
- Дополнить `assertValidAdapterRegistrations`
  (`packages/core/src/adapters/types.ts:232` —
  `export function assertValidAdapterRegistrations(registrations: AdapterRegistration[]): void {`)
  двумя проверками:
  - `tier === 'free' && dailyCallCeiling === undefined` — отказ старта с именем провайдера
  - числовое значение вне `Number.isInteger(v) && v > 0` — отказ старта с именем провайдера и с
    предъявленным значением

**Why поле объявлено со знаком `?`, а не обязательным (MINOR-1 раунда 2).** `data-model.md`
§4.6.3 требует двух несовместимых вещей от одного объявления: тотальности над `tier: 'free'` и
отсутствия поля на `tier: 'paid'`. Обязательное поле делает «провайдер без потолка» невыразимым
типом, и тест AC-33 был бы обязан подделывать значение приведением. Опциональное поле плюс правило
старта дают ту же тотальность и оставляют случай выразимым.

**Why проверка диапазона стоит рядом с проверкой присутствия (MINOR-2 раунда 2).** Значение `0`
для blockscout переворачивает смысл: гейт отклоняет первый же вызов, и маршрут `entity.labels`
уходит фолбэком на платный nansen. Env-переопределение того же числа уже валидируется как
положительное целое (задача 015-16); объявленное значение до этой задачи не проверялось ничем.

**Файл `packages/core/src/providers.config.ts`:**

- Добавить `dailyCallCeiling: 625` в регистрацию `blockscout`
  (`packages/core/src/providers.config.ts:359` — `tier: 'free',`) с пометкой происхождения
  «оценка `ADR-003` D6, не замер»
- Добавить `dailyCallCeiling: 'none'` с однострочной причиной в девять остальных бесплатных
  регистраций: `coingecko` (`:221`), `dexscreener` (`:230`), `defillama` (`:267`), `rpc-evm`
  (`:358`), `rpc-solana` (`:367`), `dash-platform` (`:378`), `platform-explorer` (`:387`),
  `pg-history` (`:439`), `blockchain-info` (`:504`)
- Двум платным регистрациям — `dune` (`:281` — `tier: 'paid',`) и `nansen` (`:477` —
  `tier: 'paid',`) — поля не добавлять
- Привести в соответствие комментарий об отсутствии учёта расхода
  (`packages/core/src/providers.config.ts:338` — ``Still open and deliberately NOT solved here:
nothing ACCOUNTS for the spend. `costOf` is 0,``, `:339` — ``there is no `usage` row and no
budget gate``, `:341` — `at which point it becomes its own task with a measurement attached.`)

### Десять объявлений и их причины

| Провайдер           | `dailyCallCeiling`          | Основание причины                                         |
| :------------------ | :-------------------------- | :-------------------------------------------------------- |
| `blockscout`        | `625` — оценка `ADR-003` D6 | вывод `100_000 / 160` из цены самого дорогого маршрута    |
| `pg-history`        | `'none'`                    | собственный Postgres — вендорского счёта нет              |
| `rpc-evm`           | `'none'`                    | курируемые RPC-хосты — источником служит сама сеть        |
| `rpc-solana`        | `'none'`                    | курируемый RPC-хост — источником служит сама сеть         |
| `dash-platform`     | `'none'`                    | живого транспорта нет — интерфейс и фикстурный контракт   |
| `coingecko`         | `'none'`                    | документированный предел минутный, его держит `rateLimit` |
| `dexscreener`       | `'none'`                    | бесключевой каталог; предела уровня аккаунта не найдено   |
| `defillama`         | `'none'`                    | бесключевой каталог; предела уровня аккаунта не найдено   |
| `platform-explorer` | `'none'`                    | предела не найдено; не измерялся — вне области T-015      |
| `blockchain-info`   | `'none'`                    | бесключевой каталог; предела уровня аккаунта не найдено   |

**Why девять причин не равносильны.** Три структурны: за вызовом нет вендорского счёта вовсе
(`pg-history`, `rpc-evm`, `rpc-solana`). Одна недействительна сегодня (`dash-platform` без живого
транспорта). Пять — отсутствие свидетельства, а не свидетельство отсутствия. `'none'` записывает
сегодняшнее свидетельство и не утверждает, что предела нет.

**Why комментарий `:338-341` правится (MINOR-6 раунда 2).** После этой задачи он утверждает
отсутствие того, что задача вводит: колонку `usage.calls_made` и гейт. Обязательство
неизменности распространено `open-questions.md` § «AC-42 vs. `dailyCallCeiling`» только на
`refillPerSec` и его пометку, поэтому правка комментария ему не противоречит.

### Граница AC-42

- `rateLimit: { capacity: 5, refillPerSec: 2 }`
  (`packages/core/src/providers.config.ts:342`) остаётся неизменным по значению
- Пометка «не измеренный потолок и не цитировать как измеренный»
  (`packages/core/src/providers.config.ts:332` — `` `refillPerSec: 2` is chosen defensively — it is
NOT a measured ceiling and must not be cited ``) остаётся неизменной по значению

**Why расхождение записано, а не решено здесь.** AC-42 читается как «диф `providers.config.ts`
пуст», а десять новых строк — сами по себе диф этого файла. Архитектура записала расхождение
вопросом владельца (`open-questions.md` § «AC-42 vs. `dailyCallCeiling`»). Задача следует прочтению
архитектуры и предмет AC-42 не переопределяет.

## Примечания

Гейт старта исполняется на входе процесса
(`packages/mcp-server/src/index.ts:46` — `assertValidAdapterRegistrations(adapterRegistrations);`),
до конструирования любого store и registry. Отказ там называет провайдера и падает при старте, а не
на первом запросе, идущем через этот адаптер.

Читателя поля вводит задача 015-13 (`createCallGate`), исполнение в адаптере — задача 015-15.
Настройка порога ключом окружения — задача 015-16.

Число `625` — оценка, а не замер. Живого доведения вендора до отказа этот этап не делает (решение
владельца 2026-08-25 по OQ-6). Пометка происхождения обязательна: без неё следующая правка
процитирует оценку как измерение.

Задача правит `providers.config.ts` и потому попадает в область просмотра диффа задачи 015-32
(AC-42). Просмотр подтверждает неизменность двух названных мест, а не пустоту диффа.
