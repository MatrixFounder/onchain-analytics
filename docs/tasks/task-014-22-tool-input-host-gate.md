# Задача 014.22: гейт на аргументы, порождающие хост `[LOGIC]`

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Ввести гейт, требующий, чтобы ни одна схема ввода тула не принимала хост, URL или RPC-эндпоинт.
Ревизовать под него схемы ввода всех тулов, перечисленных реестром.

**Why.** `ADR-003` D2: вендорские ключи клиента не принимаются, и по той же причине не принимается
адрес назначения. Аргумент, из которого выводится хост, превращает движок в открытый прокси на
периметре нашей сети.

### Устройство гейта

Гейт обходит реестр тулов и разбирает zod-схему каждого. Он падает на поле, чьё имя или формат
указывает на хост, URL или эндпоинт. Число тулов в гейте не зашито: он читает реестр.

**Why число не зашито.** Зашитое число расходится с реестром на первом добавленном туле, и
расхождение читается как «гейт прошёл». Тот же довод — в AC-7 и AC-11.

### Что остаётся разрешённым

`chain` остаётся ключом реестра сетей. Он выбирает запись из курированного реестра, а не задаёт
адрес.

**Why это не дыра.** Реестр сетей — наш файл в репозитории. Значение вне реестра отвергается до
любого исходящего вызова.

## Примечания

Гейт распространяется и на схемы, добавленные позже, включая тул `pool.info` задачи 014-32. Адрес
пула — не хост: он проверяется по формату адреса сети, а не превращается в эндпоинт.

Число схем в тексте задачи не называется. Задача 014-32 добавляет тул, и зашитое число разошлось бы с
реестром на нём. Предмет ревизии задаёт реестр тулов, а не литерал в описании.
