# WI-33 — Зависание `task-reviewer` на 600 с осталось без объяснения

> Отщеплено при закрытии [[wi-29-600-bash]]. Это **не** дубликат: у WI-29 механизм доказан и
> починен, здесь механизма нет.

**Сигнал.** В прогоне `/vdd` по T-011 (2026-08-02) два субагента остановились на 600 с:
`critic-security` в цикле 3 и **`task-reviewer` в цикле 1**. Оба случая снимались перезапуском.

**Что установлено при закрытии WI-29.** Для `critic-security` причина найдена и закрыта: read-only
роль, скилл требует сканер, а контракт execution-evidence отсутствовал на пути `/vdd` →
`vdd-adversarial`. Для `task-reviewer` та же гипотеза **не подходит**:

- `System/Agents/03_task_reviewer_prompt.md` не предписывает запуск ни одного скрипта;
- оба его TIER-1 скилла (`skill-requirements-analysis`, `skill-task-review-checklist`) — тоже;
- греп по `python3` во всех одиннадцати ролях без Bash не даёт ничего, адресованного этой роли.

То есть наблюдаемая половина сигнала объяснена, вторая — нет.

**Почему это стоит держать открытым.** В закрытую запись рецидивы не попадают. Этот довод записан
в теле WI-29 против того, чтобы относить оба случая к уже закрытой WI-7 — и он применим к самой
WI-29 в отношении второго случая.

**Направление 1 — ПОДТВЕРЖДЕНО в инструкциях (состязательный цикл, 2026-08-03).**
Гипотеза «TIER-0 `skill-session-state` предписывает скрипт роли без Bash» проверена и подтверждена
четырьмя фактами:

1. `.agent/skills/skill-session-state/SKILL.md` §3 требует: «**WHENEVER** … you **MUST** immediately
   follow it with a call to the `update_state.py` script», и приводит команду `python3 …`.
2. `skill-safe-commands` перечисляет эту команду как безопасную к запуску.
3. `03_task_reviewer_prompt.md` §2 грузит этот скилл как ALWAYS ACTIVE.
4. `.claude/agents/task-reviewer.md` объявляет роли `tools: Read, Grep, Glob`.

Это механизм из `skill-parallel-orchestration` §2.4 — тот же, что доказан для `critic-security`,
с другим инструментом.

**Почему запись всё равно остаётся открытой.** Подтверждено *присутствие противоречия в
инструкциях*, а не *воспроизведение зависания*.

Правка во фреймворк уже внесена: в §3 добавлена развилка «а можешь ли ты вообще исполнять», трём
враппер-ревьюерам дописана строка про read-only. Прогона, показавшего бы, что `task-reviewer`
больше не останавливается, пока не было. Пока такого прогона нет, запись остаётся открытой.

**Что при проверке НЕ подтвердилось.** Вторая половина той же находки снята: «промпт велит роли
записать файл `docs/reviews/task-{ID}-review.md`, а Write у неё нет». Каждый
`.claude/agents/*-reviewer.md` уже переопределяет это: «Do NOT write … yourself — the orchestrator
persists if needed». Правка не требовалась.

**Остаётся непроверенным.** Зависание могло быть не связано с инструментами вовсе (длинный вход,
обрыв на стороне рантайма) — тогда это вопрос устойчивости, смежный с закрытой WI-7 (resume), но не
тождественный ей. Два объяснения не исключают друг друга.

**Acceptance.** Прогон `/vdd` **после** внесённой правки, в котором `task-reviewer` отрабатывает без
остановки, с указанием числа подтвердивших прогонов. Либо, если остановка повторится, —
воспроизведение с диагностикой, называющей шаг, на котором она происходит.

**Related.** [[wi-29-600-bash]] — соседний случай из того же прогона, механизм доказан и закрыт.
[[wi-7-subagent-stall-resilience]] — про устойчивость к обрыву (resume), не про предотвращение
зависания; ссылаться на неё как на запись, покрывающую этот случай, некорректно.
