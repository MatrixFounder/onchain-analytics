# Задача 014.11: входящий периметр `[LOGIC]`

## Связь со сценариями

- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Настроить входящий периметр опциями транспорта SDK: разрешённые хосты и источники, защита от
DNS-rebinding, привязка к loopback по умолчанию, запрет CORS по умолчанию, отсутствие TLS в движке.

<!-- contract:changes -->

## Описание изменений

### Изменения в существующих файлах

**Файл `packages/mcp-server/src/transport/http.ts`:**

- Задать `allowedHosts` из ключа `ONCHAIN_ALLOWED_HOSTS`, класс «загрузочная» (R-29.3)
- Задать `allowedOrigins` из ключа `ONCHAIN_ALLOWED_ORIGINS`, того же класса
- Включить `enableDnsRebindingProtection`
- Привязка по умолчанию — loopback
- CORS по умолчанию запрещён

### Новые файлы

- `packages/mcp-server/test/env-no-tls-material.gate.test.ts` — гейт над объявленными ключами схемы

**Why гейт, а не отказ разбора.** `EnvSchema` намеренно не `.strict()`
(`packages/mcp-server/src/env.ts:30`), поэтому незнакомый ключ отбрасывается, а не отвергается. Тест
«схема не принимает путь к сертификату» на такой схеме верен для любого выдуманного имени. Он
останется зелёным и тогда, когда ключ под сертификат в схему добавят, — то есть в том случае, ради
которого критерий написан (`security.md` §7.5.4).

**Why движок не терминирует TLS.** Терминация — предмет обратного прокси. Сертификат в схеме
окружения означает, что процесс их читает, и переносит на движок обязанность продления и хранения
приватного ключа.

### Одно значение, два читателя

Периметр проверяется дважды: в собственном слушателе процесса и внутри `handleRequest` транспорта
(`…/webStandardStreamableHttp.js` строка 144). Оба читателя берут одно значение, провалидированное
из `.env`.

**Why одно значение.** Две копии списка расходятся; два читателя одного значения разойтись не могут.

## Тест-кейсы

### Сквозные тесты

1. **TC-E2E-01:** запрос с чужим `Host` отвергается транспортом до тула (AC-23)
2. **TC-E2E-02:** запрос с чужим `Origin` отвергается там же (AC-23)

### Модульные тесты

1. **TC-UNIT-01:** сервер без явной настройки не принимает соединение с не-loopback-адреса (AC-34)
2. **TC-UNIT-02:** ответ не несёт `Access-Control-Allow-Origin`, пока источник не разрешён (AC-35)
3. **TC-UNIT-03:** ни один объявленный ключ схемы не называет сертификат или приватный ключ
   - Входные данные: имена ключей `EnvSchema`, прочитанные из схемы; подстроки `cert`, `key`, `pem`,
     `pfx`; число ключей не зашито (замер 2026-08-12: двенадцать)
   - Ожидаемый результат: совпадений нет; гейт красный на внесённом ключе `TLS_CERT_PATH` (AC-36)
4. **TC-UNIT-04:** входящая защита от DNS-rebinding включена на транспорте (AC-37)

### Регрессионные тесты

- Прогон HTTP-сьюты с разрешённым хостом: успешный путь не задет

## Критерии приёмки

- [ ] AC-23: чужой `Host` и чужой `Origin` отвергаются до тула
- [ ] AC-34: умолчание — loopback
- [ ] AC-35: CORS по умолчанию запрещён
- [ ] AC-36: ни один объявленный ключ схемы не называет сертификат или приватный ключ

## Примечания

Периметр проверяется перед токеном. Обоснование порядка и постусловие «запрос вне периметра не
породил чтения хранилища токенов» — задача 014-12.
