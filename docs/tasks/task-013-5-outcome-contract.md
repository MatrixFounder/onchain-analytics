# Задача 013-5 — Контракт исходов: три состояния участника, четыре ветки, дедлайн-предусловие

**Требования:** [R-164], [R-176] · **Эпики:** E-1, E-4 · **Критерии приёмки:** AC-27, AC-37, AC-41,
AC-48 · **Фаза:** 5 из 10 · **Зависимости:** 013-4

## Use Case Connection

- **UC-12** — `pg-history` недоступен, `platform-explorer` отвечает непустым рядом. Успех плюс
  `missingSources`. Провал: вызов падает целиком или сигнал теряется молча.
- **UC-13** — оба участника недоступны. Явная ошибка. Провал: тихий пустой успех.
- **UC-14** — оба опрошены, окно реально пустое. Пустой успех. Провал: пустой ряд трактуется как
  отказ.
- **UC-19** — единственный опрошенный ответил пусто, второй не спрошен. `CapabilityUnavailableError`.
  Провал: «истории нет» вместо «источник не спрашивали».
- **UC-21** — участник опрошен и упал с HTTP 500. Успех из второго плюс `missingSources`. Провал:
  упавший участник не попадает ни в одну ветку.
- **UC-22** — участник побеждён дедлайном любой из двух дверей. `CapabilityDeadlineExceededError`.
  Провал: частичный слитый успех, отменяющий OD-4 незамеченно.

## Цель задачи

Дать слитому обходу терминальный контракт исходов, различающий три состояния участника, и сохранить
дедлайн предусловием этого контракта, а не пятой веткой.

Все якоря — в `packages/core/src/adapters/registry.ts`.

| Состояние                              | Строка  | Якорь                                                                                      |
| -------------------------------------- | ------- | ------------------------------------------------------------------------------------------ |
| «Ответил» — из кеша                    | `:1101` | `cached = await this.cache.get(adapter.id, capability, argsHash);`                         |
| «Ответил» — с сети                     | `:1162` | `raw = await adapter.fetch(capability, args, effectiveDeadlineAtMs);`                      |
| «Не спрошен» — нет адаптера            | `:1077` | `tried.push({ adapterId, reason: 'no adapter registered for this id' });`                  |

### Четыре ветки после цикла

- **(a)** все участники ответили → слитый успех, в том числе пустой.
- **(b)** хотя бы один ответил непусто и хотя бы один недостающий → успех из ответивших плюс
  `missingSources`.
- **(c)** ни один ответивший не дал точек и есть недостающий → `CapabilityUnavailableError` с
  полным `tried`, никогда пустой успех.
- **(d)** не ответил никто — названный частный случай (c), выделен ради UC-13.

### `missingSources`

Причина берётся из готовой записи `tried[]` для пяти путей — `:1077`, `:1094`, `:1112`, `:1165`,
`:1226` — той же формы. Пропуск по `chainSupport` (`:1082`) — исключение: `tried[]` намеренно не
несёт для него записи (там голый `continue`), поэтому `missingSources` синтезирует свою причину. На
обоих боевых маршрутах этот путь недостижим, но форма поля обязана его учитывать.

**013-4 оставил здесь долг, названный в его же роасте (F-7).** Причина участника сейчас
восстанавливается только из свободного текста `tried[].reason`, и участник, исключённый политикой
(`:1209`, `answered, but not with what was asked for`), от «спрошен, не ответил» отличается лишь
строкой. Если 013-5 будет разбирать `reason` строками — это связывание по тексту сообщения;
предпочтительно записать причину структурно там же, где она возникает.

### Дедлайн — предусловие

- `deadlineHit`, выставленный пре-чеком (`:1067`, `if (Date.now() >= effectiveDeadlineAtMs) {`) или
  пойманным `DeadlineExceededError`, отменяет все четыре ветки: вызов завершается
  `CapabilityDeadlineExceededError` независимо от того, сколько участников уже ответили.
- 🔴 **Второй двери на слитом пути СЕЙЧАС НЕТ, и это работа этой задачи.** `deadlineHit` в блоке
  слияния (`:905`–`:1260`) не выставляется ни разу; единственное упоминание — комментарий `:965`,
  которым 013-4 сознательно отложил обе записи флагов, потому что на его собственном пути их никто
  не читал (обход всегда возвращал успех). Единственный `if (error instanceof DeadlineExceededError)
deadlineHit = true;` живёт на `:1439` — это ОДИНОЧНЫЙ обход. Пока запись не добавлена, дверь 2
  на слитом пути не закрывается ничем, и TC-INT-07 обязан краснеть до неё.
- Третья точка того же класса — истёкший на входе `requestedDeadlineAtMs`: `:732`,
  `throw new CapabilityDeadlineExceededError({ capability, chain, tried });`, до обхода и до любого
  ветвления, с `tried: []`.
- **Терминальный дизъюнкт по часам сохраняется неизменным** — `:1554`,
  `if (deadlineHit || Date.now() >= effectiveDeadlineAtMs) {`. Он покрывает все двенадцать
  адаптеров, тогда как распутывание типов (WI-36) починило два. Реализация не имеет права его
  удалить. **Это цель мутационного протокола ниже; координата дважды за прогон указывала на
  комментарий, поэтому цель ищется по цитате.**
- `DeadlineWouldExceedError` (насыщенный бакет лимитера) `deadlineHit` не выставляет. Такой участник
  — «спрошен, не ответил», и распределяется ветками (b)/(c) общим правилом.
- Ветка (a), доставленная после `effectiveDeadlineAtMs` без единого побеждённого участника, несёт
  `deadlineOverrunMs` — поздний, но полный ответ, отличный от предусловия.

### `attempted`

- Участник, отданный из кеша, не входит ни в `attempted`, ни в `missingSources`.
- Участник «спрошен, не ответил» входит в оба одновременно: запись в `attempted` делается до входа в
  `fetch()` — `:1161`, `attempted.push(adapterId);` (на одиночном пути та же запись живёт на
  `:1407`; не перепутать).
- «Не спрошен» отсутствует в `attempted` целиком.

### Фазы

- **Фаза 1.** Классификация участников собирается в цикле; терминальный код возвращает ветку (a)
  всегда. Тесты (b)/(c)/(d) и дедлайна пишутся сразу и красные.
- **Фаза 2.** Ветвление, `missingSources`, предусловие, мутационный прогон дизъюнкта.
