## Главный результат: правки оркестратора чинились наполовину, три цикла подряд

`vdd-enhanced.md` §4.4 требует отдавать следующему циклу правки, внесённые оркестратором мимо
петли Developer → Reviewer, потому что они **не проходили ревью вообще**. Правило оправдалось
трижды, и каждый раз — одним и тем же способом.

| Цикл | Что заявил | Что было на самом деле | Кто нашёл |
| ---- | ---------- | ---------------------- | --------- |
| 1 | «`capability: CAPABILITY` во всех **одиннадцати** тулах» | девять; не тронуты `chain-tvl.ts` и `chain-supply.ts` — **та самая пара**, на перестановке которой дефект и демонстрировали | цикл 2, logic + slop |
| 1 | «девять докстрингов переписаны» | три модуля (`new-pairs`, `protocol-tvl`, `wallet-balances`) продолжали открываться «Registers `onchain_X`» | цикл 2, slop |
| 2 | «семнадцать файлов, не шестнадцать» — исправлено | исправлено **в одном** докстринге из трёх: `registry.ts:11` и `tool-inventory-docs.test.ts:61` остались с «sixteen» | цикл 3, slop + logic |
| 2 | «сам гейт называет **пять** тулов при пороге восемь» | **один**: число посчитано метрикой «все токены `onchain_*`», а гейт считает `namedTools()` — только зарегистрированные | цикл 3, обе линзы |
| 3 | утверждение про `reason` («выбранное сообщение, а не `.message`») исправлено | факт жил в **четырёх** местах; цикл 2 исправил `get-token.ts`, цикл 3 — `registry.ts` и `.AGENTS.md`, четвёртое (`system-architecture.md`, живой SoT) осталось | цикл 4, security + logic |
| 3 | `ADD_A_TOOL` переписан «пять каналов в порядке падения» | каналов **восемь** (измерено добавлением реального 14-го тула); пропущен гейт документов, падающий семь раз; и та же справка жила ещё в двух сообщениях, где говорила «четыре» и «три» | цикл 4, slop + logic |
| — | T-011 закрыл «README называют 8 тулов из 13» | закрыты **имена**; прописью в обоих README осталось **8**, по четыре места на язык, включая шаг быстрого старта «You should see 8 tools» | цикл 4, logic |

Строка про «пять тулов» — обоснование, сформулированное в терминах метрики и измеренное **другой**
метрикой. Решение при этом верное (1 < 8), неверен аудиторский след.

Последняя строка — самая существенная находка всего прогона: §1.2 самой задачи помечает оба README
🔴 «публичное лицо продукта», и половина этого дефекта пережила четыре цикла, потому что гейт
инвентаря сверяет только имена, а числовой гейт `docs-counts` смотрел исключительно в `docs/**`.

## Самые тяжёлые находки по циклам

**Цикл 1.** Исключение `eval/checks.mjs` из гейта документов было оправдано фразой «его ключи
сверяются с реестром в `eval-capability-coverage`». Тот тест `checks` не импортирует вовсе.
Исключение держалось на предложении, а не на гейте. Заведён `eval-checks-coverage.test.ts` на обе
стороны; осиротевшая запись не ловится больше ничем — `grade()` зовётся только для тулов, которые
eval решил позвать.

**Цикл 2.** Наименьшая привилегия закрывала один канал из двух. `needs` раздаёт контекст, но не
запрещает импорт: `createBudgetStore` — публичный экспорт core. Проверено мутацией — бесплатный
`onchain_ping` строит бюджетное хранилище, открывает SQLite, **274 теста зелёные**.

**Цикл 3.** Гейт «capability объявлена один раз», написанный в цикле 2 против этого класса, сам
пропускал этот класс: регексп без флага `g` брал **первое** совпадение по файлу, поэтому любая
более ранняя строка `capability: CAPABILITY` (естественная форма — константа `CacheMeta`)
позволяла полю спеки вернуться к литералу. Воспроизведено: старый регексп читает `CAPABILITY` и
пропускает, новый читает поле спеки и падает.

## Что доказано мутацией, а не чтением

Столбец «воспроизводимо сейчас» отвечает на вопрос, который задал цикл 4: часть строк — наблюдения
за прошлым состоянием дерева, и восстановить их по репозиторию нельзя. Помечено честно, потому что
таблица в файле про непроверяемые утверждения обязана различать эти два случая.

| Мутация | До правки | После | Воспроизводимо сейчас |
| ------- | --------- | ----- | --------------------- |
| `capability: CAPABILITY` → литерал в `chain-tvl.ts` | зелено | падает, называя файл | да — гейт в дереве |
| ранний `capability: CAPABILITY` + литерал в спеке | **зелено** (обход) | падает | да |
| `onchain_ping` импортирует `createBudgetStore` | **зелено** | падает | да |
| helper в `src/tools/helpers/` или `src/budget-fallback.ts` строит хранилище | **зелено** (гейт смотрел один каталог) | падает, называя путь | да |
| `cp README.md docs/out` | **зелено** (файл скрыт именем каталога) | падает, называя путь | да |
| файл >4 МиБ в `docs/` | молча выпадал из обхода | падает, называя путь | да |
| README говорит «8 tools» | **зелено** (числовой гейт не смотрел в корень) | падает, называя файл | да |
| переименование литерала в `eval/run.mjs` | зелено, сверка молча не запускается | падает, называя имя | да |
| лишний якорь `// Capability:` в `interfaces.md` | `expected 10 to be 11` | называет строку и id целиком | да |
| символьная ссылка на fifo и `/dev/zero` в `docs/` | зависание в `open(2)` | 380 мс, пропущено | частично — «зависание» относится к снятой версии предиката, наблюдение прошлого прогона |

## Инфраструктура прогона

Агенты вставали дважды: `task-reviewer` в цикле 1 и `critic-security` в цикле 3 — оба на 600 с
без прогресса. **WI-7 закрыт 2026-07-28 и был про устойчивость к перезапуску, а не про
предотвращение стойла**, поэтому ссылаться на него как на дом этих двух случаев неверно (замечание
цикла 4); рецидив заведён отдельно — см. «Отложено в бэклог». Полный `pnpm -r test` один раз дал три падения по таймауту в `core` —
это **WI-26** (тесты blockscout берут продовый синглтон-лимитер): изолированно `core` даёт 876/876
за 24 с против 780 с под контеншеном.
