**Signal.** Владелец выбрал для служебной задачи идентификатор `013a` — суффикс к номеру только что
сданной T-013, чтобы не отнимать `014`, зарезервированный в ROADMAP под этап «HTTP + токен +
периметр». Инструмент такой формы не принимает:

```
$ python3 .agent/tools/task_id_tool.py "live-eval-gate" --proposed-id "013a" --no-correction
{"filename": null, "used_id": null, "status": "error",
 "message": "Invalid ID format: '013a'. Must be a positive integer."}
```

Пришлось идти по **Option B — Manual Generation** из `skill-archive-task`: имя файла собрано руками,
конфликт проверен вручную (`task-013a-*`, `plan-013a-*` пусты; подзадачи `task-013-<цифры>-*` не
задеты, так как грамматика подзадачи требует цифру после номера).

**Why it matters.** Целочисленный ID — это допущение о том, что **последовательность задач и
последовательность этапов дорожной карты — одно и то же**. В этом репозитории они совпадают начиная
с 010 (`task-010`…`task-013` = `T-010`…`T-013`), а `T-014`/`T-015` уже расписаны с объёмом. Любая
внеплановая задача обязана либо отнять номер этапа и сдвинуть весь трек, либо выйти за грамматику
инструмента. Инструмент, который умеет выразить только первое, подталкивает к худшему из двух.

Цена невелика и признаётся: ручной путь документирован, конфликт-чек выполним глазами, всё
заняло одну минуту. Но Option B отключает и проверку конфликтов, и запись ID обратно — то есть
именно те гарантии, ради которых Option A назван предпочтительным.

**Generalized.** Правило без привязки к стеку: **генератор идентификаторов артефакта обязан
принимать ту же грамматику, которую допускает протокол архивирования.** Если протокол разрешает
человеку выбрать идентификатор (а `skill-archive-task` разрешает — Option B существует ровно для
этого), то валидатор, отвергающий выбор человека, превращает предпочтительный путь в
недоступный. Конкретная грамматика — свойство проекта, а не фреймворка: где-то это `12`, где-то
`12a`, где-то `RFC-12`. Инструмент должен валидировать **уникальность и разрешимость в имя файла**,
а не форму.

**Options.**

| # | Вариант | Стоимость | Компромисс |
|---|---------|-----------|------------|
| 1 | Разрешить суффикс `\d+[a-z]?` в `--proposed-id`, сортировку вести по числовой части | S | Закрывает случай; форма всё ещё фиксирована фреймворком |
| 2 | Валидировать не форму, а свойства: непусто, разрешимо в имя файла, не конфликтует | M | Снимает вопрос навсегда; требует пересмотра сортировки max+1 |
| 3 | Оставить как есть, дописать в `skill-archive-task`, что нецелочисленный ID — штатный Option B | S | Честно и дёшево, но предпочтительный путь остаётся недоступным для целого класса задач |

**Recommendation.** Вариант 1 как минимально приемлемый, вариант 2 как цель. Вариант 3 не
рекомендуется в одиночку: он документирует обход вместо того, чтобы убрать препятствие.

**Acceptance.** `task_id_tool.py --proposed-id "013a" --no-correction` возвращает
`status: "generated"` и корректное имя файла, а проверка конфликтов при этом продолжает работать —
то есть Option A доступен для внеплановой задачи, а не только для этапа дорожной карты.
