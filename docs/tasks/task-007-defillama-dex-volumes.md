## 1. Описание проблемы

Класс вопросов «дневной объём DEX по сети» основной прогон исследования объявил незакрываемым;
добивка это **опровергла** ([§В-9](dune-query-discovery/verification-corrections.md)): DefiLlama
отдаёт агрегаты объёмов **бесплатно и без ключа**, а у движка уже есть адаптер `defillama` и хост
`api.llama.fi` в SSRF-allowlist ([providers.config.ts:107-110](../packages/core/src/providers.config.ts#L107-L110)).
Сегодня движок на вопрос «сколько торгуют на Base за квартал» отвечает отказом — при том что ответ
стоит один keyless GET.

Задача закрывает этот класс, не открывая ни одного платного пути и не трогая трек B (Dune).

### 1.1. Три факта, найденных живым зондом, которых нет в задачнике

Задачник A-1 писался по отчёту; перед проектированием я перепроверил эндпоинт вживую. Три вещи
меняют дизайн и должны быть в требованиях, иначе задача будет сдана с дырой:

1. **Покрытие DEX-объёмов ≠ покрытие TVL.** В реестре `vendors.defillama` заполнен у **всех 458**
   сетей (он выведен из TVL-каталога `/v2/chains`), а DEX-объёмы вендор отдаёт по **287** сетям
   (`allChains` живого ответа), из которых в нашем реестре есть **274**. Наивный предикат
   `chain.vendors.defillama != null` переобещал бы capability на **184 сетях** — ровно дефект H-1
   из TASK-006 («покрытие расширили, транспорт нет»).
2. **Незнакомая сеть не даёт честной ошибки.** `GET /overview/dexs/dash` → **HTTP 500**
   `Internal server error` (не 404), а `…/litecoin` → **HTTP 200 с нулями** и `total24h: 0`. То есть
   «сеть не поддержана» приходит и как пятисотка, и как валидный пустой ответ. Гейт покрытия обязан
   стоять **до** вызова, а `normalize()` — сверять, что вендор вернул именно ту сеть, о которой
   спрашивали (в ответе есть эхо-поле `chain`).
3. **Кап размера ответа на этом эндпоинте не работает.** Ответ приходит **без `Content-Length`**
   (HTTP/2, `cf-cache-status`), а [safe-fetch.ts:147-154](../packages/core/src/net/safe-fetch.ts#L147-L154)
   при отсутствующем заголовке делает ранний `return` вовсе без проверки. Это известный
   [R-47(1)](BACKLOG.md) — здесь он становится блокирующим, потому что DoD задачника требует теста
   «усечение большого документа», а без счётчика байтов такой тест был бы вакуумным.

## 3. Use Cases

### UC-1. Агент спрашивает дневной объём DEX по сети за квартал

- **Актёры:** LLM-агент (через MCP), система (движок), DefiLlama (внешний источник).
- **Предусловия:** сервер запущен по stdio; сеть покрыта capability `dex.volume.history`;
  ключей не требуется (`.env` может быть пустым).
- **Основной сценарий:**
  1. Агент вызывает `onchain_dex_volume({chain: 'base', days: 92})`.
  2. Тул канонизирует `chain` против того же реестра, на котором гейтится `CapabilityRegistry`.
  3. `resolve('dex.volume.history', chain, args)` проходит гейт покрытия, промахивается мимо кэша.
  4. Адаптер берёт `vendors.defillama` (`Base`), строит
     `GET /overview/dexs/Base?excludeTotalDataChartBreakdown=true`, проходит throttle и `safeFetch`.
  5. `normalize()` сверяет эхо-поле `chain`, режет ряд по окну, переводит секунды в epoch-ms UTC,
     считает пропуски, возвращает канонический результат.
  6. Тул валидирует выход `safeParse` и отдаёт `structuredContent` + `_meta.cache = {status:'miss'}`.
- **Альтернативные сценарии:**
  - **A1. Повторный вызов в пределах TTL** → `_meta.cache.status = 'hit'`, ноль сетевых вызовов.
  - **A2. Сеть вне покрытия** (`dash`) → `CapabilityNotCoveredOnChainError` **до** HTTP-вызова,
    с перечнем сетей, где capability есть.
  - **A3. Вендор вернул HTTP 500** → адаптер бросает, `resolve` записывает `tried` и отдаёт
    `CapabilityUnavailableError`; **fetch-ошибка не негативно-кэшируется** (существующий контракт).
  - **A4. Вендор вернул другую сеть** (эхо-поле не совпало) → `normalize()` отказывает; отказ
    детерминирован, поэтому попадает в негативный кэш на `NEGATIVE_TTL_SECONDS`.
  - **A5. Тело больше капа** → `SafeFetchResponseTooLargeError` при чтении потока, соединение
    закрывается, тело в память не поднимается.
  - **A6. `days` больше максимума** → zod отказывает на входе тула, сетевого вызова нет.
- **Постусловия:** результат в кэше под `(defillama, dex.volume.history, argsHash)`; ноль кредитов
  списано ни у одного провайдера; состояние бюджета не тронуто.
- **Критерии приёмки:** см. §4 (AC-1…AC-6).

### UC-2. Агент выясняет, на каких сетях вопрос вообще имеет смысл

- **Актёры:** LLM-агент, система.
- **Предусловия:** сервер запущен; **сети не требуется вовсе** — тул сетевых вызовов не делает.
- **Основной сценарий:**
  1. Агент вызывает `onchain_list_chains({capability: 'dex.volume.history', limit: 50})`.
  2. Матрица покрытия отфильтровывает реестр по предикату `chainSupport` адаптера `defillama`.
  3. Ответ содержит `total` = число реально покрытых сетей и первую страницу, отранжированную по
     TVL снимка реестра.
- **Альтернативные сценарии:**
  - **B1. Сеть есть у вендора, но нет в реестре** (13 таких) → она **не** появляется в выдаче;
    расхождение фиксируется в raw-evidence, а не маскируется.
  - **B2. Сеть есть в реестре, но вендор не отдаёт по ней объёмы** (184 таких) → capability в её
    строке `capabilities[]` отсутствует.
- **Постусловия:** ноль сетевых вызовов, ноль записей кэша.
- **Критерии приёмки:** AC-4.

### UC-3. Оператор обновляет список сетей после дрейфа вендора

- **Актёры:** оператор (человек), dev-скрипт, git.
- **Предусловия:** рабочее дерево чистое; есть свежий raw-снимок ответа вендора.
- **Основной сценарий:**
  1. Оператор кладёт свежий `allChains` в `docs/onchain-analytics/raw/`.
  2. Запускает генератор; тот перезаписывает `dex-chains.ts`.
  3. Оператор читает git-diff: какие сети появились, какие исчезли.
  4. Коммит проходит только если тесты зелёные.
- **Альтернативные сценарии:**
  - **C1. Вендор прислал имя с кавычкой/переводом строки** → генератор **отказывается** эмитить
    (как `gen-nansen-coverage.ts`), а не экранирует молча.
  - **C2. Список пуст или подозрительно короткий** → генератор падает, а не выпускает пустое покрытие.
- **Постусловия:** снимок — build-артефакт в git, свежесть под ответственностью оператора (§4.2.1
  доктрины реестра), рантайм ничего не тянет на старте.
- **Критерии приёмки:** AC-5.

| **AC-1** | Контрактный тест на записанной фикстуре: успешный путь даёт ряд, где `date` — epoch-ms UTC, число точек равно длине окна, `gapDays === 0`                                     | `pnpm test` (core)        |

| **AC-5** | Генератор детерминирован: повторный запуск на том же входе даёт побайтово тот же файл; вендорское имя вне `[A-Za-z0-9 ._-]` роняет генератор                                  | `pnpm test` (core)        |
| **AC-6** | Непокрытая сеть отвергается `CapabilityNotCoveredOnChainError` **без** сетевого вызова (инжектированный `fetchImpl`, считающий обращения, вызван 0 раз)                       | `pnpm test` (core)        |
| **AC-7** | Полный прогон `pnpm test` зелёный; `typecheck`, `lint`, `format:check` зелёные; прогон без сети                                                                               | CI-эквивалент локально    |
| **AC-8** | TASK-007 не добавляет **ни одного** нового попадания `z.record\|passthrough()\|z.unknown()\|z.any()` в `packages/core/src` и `packages/mcp-server/src`                        | `rg`, см. примечание ниже |

> **Примечание к AC-8 (исправлено adversarial-циклом 1).** Формулировка «попаданий ровно ноль»,
> взятая из [T2 задачника](dune-query-discovery/dune-tasks.md), **уже была неверна до этой задачи**:
> `chain/registry-core.ts:139` содержит `z.record(z.string(), z.string().min(1).nullable())` со
> времён TASK-006. Это **типизированный** record с закрытой схемой значения и открытым множеством
> ключей (идентификаторы вендоров) в загрузчике файла реестра — не «произвольная табличка» в
> контракте тула, против которой правило написано.
>
> Почему этого никто не заметил: тот же файл содержал **литеральный байт NUL** (разделитель в
> `join(...)` был записан сырым байтом), а `grep`/`rg` считают такой файл **бинарным** и молча
> пропускают его без `-a`/`--text`. Гейт возвращал «ноль» не потому, что попаданий нет, а потому,
> что не видел файл — единственный, который валидирует per-chain SSRF-allowlist. Байт заменён на
> escape (поведение идентично), после чего гейт снова видит модуль.
