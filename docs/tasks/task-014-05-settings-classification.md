# Задача 014.05: классификация настроек по локусу и гейт на неё `[LOGIC]`

## Связь со сценариями

- UC-3 — оператор запускает локально

<!-- contract:goal -->

## Цель задачи

Разделить настройки на три класса по тому, где им разрешено жить, и ввести гейт, отвергающий
чтение секретной или загрузочной настройки из Postgres.

**Why.** Две разные причины оставить настройку на месте. Секреты — канон D10 и инвариант `ADR-002`
D1: ключи и стили авторизации никогда не попадают в правимое без релиза хранилище. Загрузочные — по
невозможности: настройку подключения к Postgres нельзя прочитать из Postgres.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `packages/mcp-server/src/settings-classification.ts` — реестр настроек с классом у каждой
- `packages/mcp-server/test/settings-classification-gate.test.ts` — гейт

**Why пакет `mcp-server`.** Реестр размечает поля `EnvSchema`, а она объявлена в
`packages/mcp-server/src/env.ts` (`deployment.md` §10.3). Гейт лежит рядом с гейтами
`settings-access.gate.test.ts` и `schema-qualification.gate.test.ts` того же каталога.

### Классы

Три класса объявлены в `deployment.md` §10.3.1; задача воспроизводит их состав.

| Класс       | Где живёт                                                             | Состав                                                                            |
| :---------- | :-------------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| секрет      | `.env` бессрочно                                                      | ключи вендоров, `ONCHAIN_TOKEN_HASH_SALT`                                         |
| загрузочная | `.env` бессрочно                                                      | `ONCHAIN_PG_URL`, `DATA_DIR`, порт, адрес привязки, разрешённые `Origin` и `Host` |
| сужающая    | носитель назван в §10.3.1; переезд в Postgres допустим позже (R-29.4) | `LOG_LEVEL`, потолки расхода Nansen, лимиты профиля, список тулов профиля         |

Ключи периметра — `ONCHAIN_ALLOWED_ORIGINS` и `ONCHAIN_ALLOWED_HOSTS` — имеют класс «загрузочная»
(R-29.3).

**Why периметр не выделен в свой класс.** Добавление значения `Origin` или `Host` допускает
вызывающего, которому до правки отказывали, а сужающий класс требует, чтобы каждое допустимое
значение только ограничивало. По этому тесту периметровые ключи попадают в загрузочные.

### Правило допуска в сужающий класс

Настройка сужающая, если её значение действует только на сужение. Это тест `ADR-002` §8.5.

**Why правило именно такое.** Сужающая настройка не может расширить право; ошибка в ней приводит к
отказу, а не к утечке. Расширяющая настройка в правимом без релиза хранилище — путь повышения
привилегий через запись в базу.

**Why классов три, а не четыре.** `deployment.md` §10.3.1 объявляет `secret`, `bootstrap` и
`narrowing`. Четвёртый класс в реестре задачи означал бы настройку, для которой гейт не знает
правила из архитектуры.

### Изменения в существующих файлах

**Файл `packages/mcp-server/src/env.ts`:**

- Пометить каждое поле схемы классом из реестра
- Поле без класса не собирается

## Тест-кейсы

### Модульные тесты

1. **TC-UNIT-01:** настройка класса «секрет» не читается из Postgres
   - Входные данные: попытка объявить `NANSEN_API_KEY` сужающей
   - Ожидаемый результат: гейт красный (AC-44)
2. **TC-UNIT-02:** настройка класса «загрузочная» не читается из Postgres
   - Входные данные: попытка объявить `ONCHAIN_PG_URL` сужающей
   - Ожидаемый результат: гейт красный
3. **TC-UNIT-03:** поле `EnvSchema` без объявленного класса роняет сборку реестра
4. **TC-UNIT-04:** обязательства правки без релиза объявлены только у сужающего класса
   - Входные данные: чтение трёх обязательств — валидация на публикации, журнал изменений,
     откат — у классов «секрет», «загрузочная» и «сужающая»
   - Ожидаемый результат: три обязательства объявлены у сужающего класса и не объявлены у двух
     остальных (R-29.5)
5. **TC-UNIT-05:** обязательство, приписанное несужающему классу, роняет сборку реестра
   - Входные данные: попытка объявить журнал изменений у класса «загрузочная»
   - Ожидаемый результат: гейт красный и называет класс (R-29.5)

## Примечания

Задача переноса значений в Postgres в T-014 не входит. T-014 объявляет, что относится к сужающему
классу, и гейтом запрещает переносить остальное.

Ключа окружения класса «сужающая» T-014 не добавляет: носитель каждого сужающего значения назван в
таблице §10.3.1 (задача 014-40).
