# В кэш кладётся 74% документа, которые мы контрактно не читаем

> **✅ ВЫПОЛНЕНО 2026-07-28.** `fetchDexDocument` проецирует ответ на семь объявленных полей
> **внутри** IIFE, до того как промис разрешится, — в кэш попадает только то, что адаптер читает.
>
> Пиковая память на `.json()` не изменилась; сократился **удерживаемый** набор, тот, который живёт
> час. И R-68e перестало быть дисциплиной: редактируемого третьей стороной текста нет в памяти
> вовсе, поэтому его не сможет выпустить наружу и будущая правка.
>
> **Тест:** документ с подложенной карточкой протокола (`IGNORE PREVIOUS INSTRUCTIONS`) —
> закэшированный объект содержит ровно семь ключей, а сериализованный вид не содержит payload.
> Проверяется не выход тула (это уже покрыто), а **то, что мы держим в памяти**.

**Источник:** adversarial-цикл 3 TASK-007, `critic-performance` M-1.

`fetchDexDocument` сохраняет `await response.json()` целиком. Из 250 КБ документа по одной сети
дневной график — ~79 КБ, а остальное это 151 карточка протоколов (`name`, `category`,
`methodology`, `logo`) плюс `allChains[287]`. В распарсенном виде это ~415 КБ на документ, ~13 МБ
при 32 слотах.

Отдельная ирония: интерфейс `DefillamaDexResponse` объявляет ровно семь полей, а докстринг рядом
гордо объясняет, что карточки протоколов «не читаются, поэтому не могут попасть к вызывающему».
Не читаются — но лежат в куче час.

## Как чинить

Спроецировать документ на семь объявленных полей **внутри** IIFE, до того как промис разрешится:

```ts
const b = (await response.json()) as DefillamaDexResponse;
return {
  chain: b.chain,
  totalDataChart: b.totalDataChart,
  total24h: b.total24h,
  total7d: b.total7d,
  total30d: b.total30d,
  total1y: b.total1y,
  totalAllTime: b.totalAllTime,
};
```

415 КБ → ~125 КБ на документ, 13 МБ → ~4 МБ при 32 слотах (×3.3). Пиковая память на `.json()` не
меняется — сокращается **удерживаемый** набор, тот самый, который живёт час.

Побочная выгода важнее арифметики: **R-68e перестаёт быть дисциплиной и становится фактом** —
редактируемого третьей стороной текста нет в памяти вовсе, значит его неоткуда утечь.

## Приёмка

- в закэшированном документе нет ключа `protocols`;
- поведение `normalize()` не меняется (те же фикстуры, те же результаты).
