## Test Cases

### Регрессионный прогон (в этом порядке)

```bash
pnpm typecheck        # strict + noUncheckedIndexedAccess
pnpm lint
pnpm format:check
pnpm test             # оба пакета
pnpm build
```

### Гейты, проверяемые отдельно

1. **TC-REG-01** (**AC-7**) — все пять команд выше зелёные.
2. **TC-REG-02** (**AC-7**) — прогон **без сети**: ни один тест не обращается к реальному хосту
   (тем же способом, каким это доказывалось в TASK-006 — заблокированные `fetch`/`http(s)`).
3. **TC-REG-03** (**AC-8**) — `grep -rnE 'z\.record|passthrough\(\)|z\.unknown\(\)|z\.any\(\)'`
   по `packages/core/src` и `packages/mcp-server/src` даёт **ноль** попаданий.
4. **TC-REG-04** — число тестов **выросло**, и ни один существующий тест не был ослаблен ради
   прохождения (проверяется чтением диффа по `test/`: удаление или смягчение ассерта требует
   письменного обоснования в этом файле).

## Notes

Пункт TC-REG-04 существует потому, что самый дешёвый способ сделать регрессию зелёной — ослабить
тест, который мешает. Требование письменного обоснования переводит это из «незаметно» в «видно в
диффе».
