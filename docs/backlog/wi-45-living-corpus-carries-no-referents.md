# WI-45 — Живой корпус не несёт референтов, и свои workflow'ы его не проверяют

Остаток [WI-43](wi-43-line-anchored-citations-in-docs-decay-silently.md) после её закрытия
переносом. Механизм существует и доступен здесь; невыполненными остались ровно два её критерия —
6 и 5, — и оба оставлены решением проекта намеренно (`agentic-development` TASK 103 D5, TASK 104
D6). Запись заведена, чтобы 182 ссылки не остались без ведущего их учёта.

## 1. Что уже работает без единой правки здесь

Через симлинк `.agent/skills/documentation-standards`:

```bash
python3 .agent/skills/documentation-standards/scripts/check_positional_refs.py \
  --all docs/TASK.md docs/PLAN.md docs/architectures/
```

Замер на `e95b909`, `docs/PLAN.md`: `3 with a referent, 27 without (not examined), 4 unresolvable`.
Четыре ревью-чек-листа уже требуют прогона и цитирования строки охвата, и уже запрещают ревьюеру
требовать референты там, где их нет.

## 2. Что остаётся

| Предмет | Объём |
| :--- | :--- |
| Аудит 26 съехавших ссылок | 19 чинятся механически (исходная строка дословно жива в файле), 4 требуют чтения по смыслу, 3 вручную |
| Простановка референтов | 116 стабильных автоматически, 26 по результату аудита |
| Пути от корня | 118 голых имён; 36 ссылок на `registry.ts` разводятся вручную между тремя файлами |
| Подключение своих workflow'ов | 7 шагов не приезжают симлинком: `.agent/workflows/` — каталог этого проекта |

Ручных решений — порядка 62. Остальное скриптуется.

## 3. Порядок, и почему обратный порядок вреден

1. **Аудит дрейфа** — отчёт по 26 съехавшим.
2. **Простановка референтов** — 116 стабильных автоматически, 26 после шага 1.
3. **Пути** — голые имена получают путь от корня.
4. **Подключение workflow'ов** — по образцу `agentic-development` TASK 104: семь шагов
   `--targets-changed`, `--fix` там, где workflow коммитит.

**Простановка референтов ДО аудита припечатывает текущие ошибки.** 26 ссылок уже указывают не туда;
авто-простановка привяжет к ним ту строку, на которую они попали случайно, и превратит сегодняшнюю
ошибку в вечную и формально верифицированную. Это тот же класс, что ложный зелёный
[WI-44](wi-44-typecheck-reads-stale-core-dist-so-cross-package-type-breakage-is-invisible.md).

## 4. Acceptance

1. `--all docs/TASK.md docs/PLAN.md docs/architectures/` печатает **0** `REFERENT_ABSENT` и
   `REFERENT_AMBIGUOUS`, а строка охвата показывает 0 unresolvable.
2. Ни одна из 26 съехавших не заякорена без чтения — каждая названа в коммите аудита.
3. Семь workflow'ов этого репозитория запускают резолвер; проверяется вставкой строк в
   `registry.ts` без правки `docs/` и красным прогоном до `--fix`.

Строка охвата — сама по себе метрика прогресса: доля `with a referent` растёт, и её можно
цитировать в ревью, не дожидаясь полного покрытия.

## 5. Что не закрывается и этой записью

**Семантика.** Референт доказывает, что цитата на месте, а не что утверждение о ней верно.
`system-architecture.md`, называющий прогрев кеша «сужением маршрутов `matching`», пройдёт гейт,
если процитирует ту строку. Только чтением.

**Правило свода** — «свод сообщает область поиска вместе с числом» — гейтом не заменяется. Второй
случай ущерба из WI-43 остаётся без механизма; резолвер применяет это правило только к собственному
выводу.
