# ПЛЕЙБУК: сложный ончейн-ответ из готовых запросов Dune

**As-of: 2026-07-27.** Все числа ниже взяты байт-в-байт из верификационных данных прогона. Там, где числа нет — стоит `unverified`, и это не фигура речи, а запрет подставлять оценку.

---

## Инвариант, который определяет всю маршрутизацию

**Готовые (сохранённые) запросы Dune нельзя исполнить без API-ключа.** В `https://api.dune.com/openapi.json` (HTTP 200, 200 145 B, забран 2026-07-27) расширение `x-payment-info` стоит ровно на **4 операциях из 47**. Все операции работы с сохранёнными запросами — `POST /v1/query/{query_id}/execute`, `GET /v1/query/{query_id}/results`, `/results/csv`, `GET /v1/queries`, `GET /v1/query/{queryId}`, `POST /v1/datasets/search`, `/v1/datasets*` — **без** `x-payment-info`, то есть безаккаунтный платёжный протокол (MPP) их не обслуживает.

Отсюда две непересекающиеся ветки, и агент обязан выбрать ветку на шаге 0:

| Ветка | Что доступно | Чем платим |
|---|---|---|
| **A. С API-ключом** | Все 47 операций: поиск запросов, чтение карточки запроса, исполнение сохранённого `query_id`, датасеты, usage | Кредиты плана. Data API включён во все планы, включая Free (2 500 кредитов/мес — *см. оговорку ниже*) |
| **B. Keyless (MPP)** | Только raw-SQL: `POST /v1/sql/execute` → `GET /v1/execution/{id}/status` → `GET /v1/execution/{id}/results` (+ `/results/csv`) | USDC.e ончейн на Tempo mainnet, `x-required-scope: Read` |

Оговорка по «2 500 кредитов/мес»: цифра проходит в профиле Dune MPP с confidence high, но в соседней строке прогона тот же тезис прошлого прогона (2 500 кредитов/мес, overage $5/100, ~55 rpm, `api.dune.com/mcp/v1`, OAuth2+PKCE, 26 тулов) помечен как **UNVERIFIED / не перепроверявшийся**. Считать его действующей квотой без собственной проверки нельзя.

Второй инвариант: **готовый чужой запрос в ветке B бесполезен как объект исполнения, но полезен как текст SQL.** Легальный обход — вытащить SQL из карточки запроса (нужен ключ на чтение) и прогнать его как raw-SQL через MPP. Без ключа даже прочитать карточку нечем.

## 1. Рецепт поиска

### Шаг 0. Классифицировать вопрос и решить, идти ли в Dune вообще
Прогнать вопрос через маршрутизатор §5. Если класс закрывается бесплатным не-Dune источником — выйти здесь. Dune стоит денег на каждом исполнении и на каждом мегабайте результата; бесплатные пути стоят 0.

### Шаг 1. Взять машинную спеку API, а не документацию
```
GET https://api.dune.com/openapi.json
```
200 145 B, 47 операций. Это первоисточник путей и прайса (`x-payment-info`). Документация `https://docs.dune.com/docs/agents/mpp` **доказанно расходится с продакшеном** в двух местах:
- таблица «Available Endpoints» обещает `GET /v1/execution/:execution_id/csv` → живой ответ **HTTP 404 `{"error":"URL not found"}`**; реальный путь `GET /v1/execution/{id}/results/csv` (отдаёт 402);
- `GET /v1/execution/{id}/status` в таблице отсутствует, хотя код Step 4 в той же доке его дёргает, и он MPP-обслуживается бесплатно.

Вывод для агента: любой путь, взятый из доки и не найденный в `openapi.json`, считать несуществующим до живой проверки.

### Шаг 2. Найти кандидатов-запросов (ветка A, нужен ключ)
Три ортогональных захода, а не один:
1. **По данным** — `POST /v1/datasets/search`: ищем не запрос, а таблицу/датасет, на котором вопрос физически решается. Если таблицы под вопрос нет — дальше искать нечего, никакой «готовый запрос» её не создаст.
2. **По запросам** — `GET /v1/queries`: перечень запросов, из которого отбираются кандидаты по названию/владельцу.
3. **По конкретике** — `GET /v1/query/{queryId}`: карточка кандидата с текстом SQL и параметрами. Это единственный способ увидеть, что запрос на самом деле считает.

Все три — без `x-payment-info`, то есть **платить за них воучером MPP нельзя, только ключом**.

### Шаг 3. Отсеять
Отсев делается по карточке из шага 2 и по чек-листу §2. Порядок отсева — от самого дешёвого признака к самому дорогому:
1. SQL читается? Нет текста SQL — кандидат выбывает, чёрный ящик не верифицируем.
2. Таблицы в `FROM`/`JOIN` резолвятся через `POST /v1/datasets/search`? Не резолвятся — выбывает.
3. Слой данных: curated/decoded против raw. Ручной разбор topic'ов из raw-логов внутри запроса — красный флаг (см. чек-лист п.6).
4. Параметры: есть ли обязательные, какие у них дефолты (п.5).
5. Свежесть последнего исполнения (п.3).
6. Автор (п.4).

### Шаг 4. Получить `query_id`
`query_id` — это идентификатор из карточки `GET /v1/query/{queryId}`. Зафиксировать его вместе со снимком SQL и списком параметров в артефакт прогона: без снимка SQL повторный прогон через месяц неверифицируем (владелец мог отредактировать запрос, id при этом не меняется).

### Шаг 5. Исполнить

**Ветка A (ключ):**
```
POST /v1/query/{query_id}/execute      → execution_id
GET  /v1/execution/{id}/status         → опрос до терминального состояния
GET  /v1/execution/{id}/results        → данные
```
`cancel` и `/v1/usage` доступны только здесь.

**Ветка B (keyless, MPP):** сохранённый запрос исполнить нельзя. Берём текст SQL и гоним как raw:
```
POST /v1/sql/execute                   → 402 challenge
GET  /v1/execution/{id}/status         → 402 с amount "0"
GET  /v1/execution/{id}/results        → 402 challenge
```
Механика 402: заголовок `WWW-Authenticate: Payment, method="tempo", intent="session"`, тело челленджа — base64-запрос. Проверенные живьём параметры (2026-07-27T16:06Z):

| Операция | `x-payment-info.description` | `amount` в челлендже | В долларах (`amount`/10^6) |
|---|---|---|---|
| `POST /v1/sql/execute` | «Reserves $5.00; actual cost based on execution compute.» | `4000000` | **$4.00** |
| `GET /v1/execution/{id}/results` | «$1.00 per MB of result data.» | `1024000000` | **$1024.00** |
| `GET /v1/execution/{id}/results/csv` | «$1.00 per MB of result data.» | `1024000000` | $1024.00 |
| `GET /v1/execution/{id}/status` | «Free status polling.» | `0` | **$0.00** |

`amount` — это **резерв (потолок воучера), а не факт-цена**. Доказательства: (1) слово «Reserves» в описании; (2) инвариантность к нагрузке — `SELECT 1`, `LIMIT 1000000` и пустое тело дают одинаковые `4000000`, а `?limit=1` и `?limit=10000` одинаково дают `1024000000`; (3) бесплатный `status` даёт `amount:"0"`. Резерв результата 1024 = 1024 МБ × $1.00/МБ — это **inference (medium)**, не заявление вендора.

Валюта подтверждена ончейн через `https://rpc.tempo.xyz`: `eth_chainId` = `0x1079` = `4217` (Tempo mainnet); на контракте `0x20c000000000000000000000b9537d11c60e8b50` — `symbol()` = `USDC.e`, `name()` = `Bridged USDC (Stargate)`, `decimals()` = `6`. Эскроу `0x33b901018174DDabE4841042ab76ba85D4e24f25` задеплоен (6046 байт кода), получатель `0xb25d77c967d412bbc10891c5254f4e56bb056f3d` держит 162.578266 USDC.e. `suggestedDeposit` = `"10000000"` = **$10.00**, что совпадает с `maxDeposit: "10"` из примера доки.

**Дефект первоисточника, который агент обязан логировать:** OpenAPI обещает резерв **$5.00** за execute, живой челлендж резервирует **$4.00**.

### Шаг 6. Если готового запроса нет
Не выдумывать. Два законных исхода: (а) написать собственный SQL и прогнать через ту же ветку (стоимость та же), (б) вернуть маршрут в §5 и закрыть вопрос бесплатным источником. Третьего («ответить по памяти») нет.

## 2. Чек-лист корректности

Формат каждого пункта: **что смотрим → чем проверяем → признак провала**.

**1. Текст SQL и его таблицы.**
Смотрим: полный текст запроса из `GET /v1/query/{queryId}`, все имена в `FROM`/`JOIN`/CTE.
Проверяем: каждое имя таблицы резолвим через `POST /v1/datasets/search`. Совпадение — по полному имени, не по подстроке.
Провал: имя не резолвится; в запросе есть подзапрос к таблице, которой нет в результатах поиска; SQL недоступен вовсе. → кандидат выбывает, не «примем на веру».

**2. Spellbook-происхождение (curated против самодельного).**
Смотрим: лежит ли запрос на кураторском (spellbook-подобном) слое или собирает метрику сам из сырья.
Проверяем: резолв каждой таблицы из п.1 показывает её слой; для кураторской таблицы существует опубликованное определение, для самодельного CTE — нет.
Провал: метрика собирается внутри запроса ad-hoc (ручные списки адресов пулов/фабрик, захардкоженные топики, вшитые курсы). Такой запрос — частное мнение автора, а не общепринятая метрика; его нельзя выдавать как «объём DEX» без оговорки об определении.
Важно: конкретные имена кураторских таблиц в этом прогоне **не верифицировались** — не подставляй их по памяти, резолви через `/v1/datasets/search`.

**3. Свежесть последнего исполнения.**
Смотрим: когда `execution_id`, чьи результаты мы читаем, реально считался.
Проверяем: `GET /v1/execution/{id}/status` — единственная операция, бесплатная и в MPP (`amount:"0"`, «Free status polling»), поэтому опрашивать статус можно без бюджета. Плюс сверка верхней границы данных с независимым тиком цепи: Blockscout `get_block_number` (живой пример: chain_id=1 → блок `25624655` @ `2026-07-27T14:10:47Z`) или `eth_blockNumber` через наш `rpc-evm` (`packages/core/src/providers.config.ts:121`, хосты `ethereum-rpc.publicnode.com` / `eth.drpc.org`).
Провал: верхняя граница данных отстаёт от тика цепи больше, чем допускает вопрос. Лечится только новым `execute` — а это деньги ($4.00 резерв в MPP). Молча отдать вчерашний результат за сегодняшний — дисквалификация ответа.

**4. Автор.**
Смотрим: владельца запроса из карточки.
Проверяем: сопоставляем автора с классом запроса — вендорский/протокольный аккаунт против одноразового форка.
Провал: автор неизвестен И запрос не резолвится на кураторский слой (п.2) — тогда доверия ноль по двум независимым осям сразу. Один слабый признак сам по себе не убивает кандидата; два — убивают.

**5. Дефолты параметров.**
Смотрим: список параметров и их значения по умолчанию в карточке.
Проверяем: прогоняем запрос с явно заданными параметрами, а не на дефолтах; сравниваем два прогона — на дефолтах и на своём окне.
Провал: результат меняется, а мы этого не заметили. Классика — дефолтное временнóе окно молча сужает выборку, и агент рапортует «объём за день», получив объём за час. Незаданный параметр = число без определения.

**6. Decoded против raw.**
Смотрим: работает ли запрос с декодированными сущностями или с сырыми логами/калдатой.
Проверяем: наличие в SQL ручного разбора байтов, срезов `topic`, хардкоженных сигнатур.
Провал: запрос декодирует руками. Такой путь ломается на любом нестандартном контракте/прокси и не переносится между сетями. Если сравниваем сети между собой (worked example 2), смешивать decoded-строки одной сети с raw-разбором другой запрещено — это разные определения одной колонки.

**7. Размер результата = деньги.**
Смотрим: сколько строк/мегабайт вернёт запрос.
Проверяем: агрегируем на стороне SQL (`GROUP BY`), а не тянем сырьё; ставим `LIMIT`; помним, что тариф — «$1.00 per MB of result data», а `amount` резерва инвариантен к `?limit=` (`?limit=1` и `?limit=10000` дали одинаковые `1024000000`), то есть резерв **не** защищает от дорогой выгрузки, он только потолок воучера.
Провал: план запроса тянет построчное сырьё под агрегат, который можно было посчитать в БД.

**8. Резерв против депозита.**
Смотрим: `amount` челленджа против баланса сессии.
Проверяем: `$1024.00` резерва на `/results` против `suggestedDeposit` `$10.00` / `maxDeposit "10"`.
Провал: воучер упирается в депозит (`amount-exceeds-deposit`), нужен `topUp`. Это **inference (medium)**, но закладывать обработку обязательно — дневной потолок, посчитанный в кредитах, этот отказ не поймает.

**9. Независимая сверка.**
Смотрим: воспроизводится ли число вне Dune.
Проверяем: сверка вторым кодовым путём. Эталонный образец такой сверки — из другого вендора, но метод переносится: `circulation` из `https://api.blockchair.com/bitcoin/stats` против `sum(generation)` из `https://api.blockchair.com/bitcoin/blocks?a=sum(generation)` — два **разных** кодовых пути (материализованная статистика против агрегата по таблице блоков) над одной величиной; расхождение = дефект вендора. В Dune аналог — посчитать ту же величину по двум разным таблицам/слоям.
Провал: единственный путь. Число из одного пути = `confidence` не выше medium, и это надо написать в ответе.

**10. Учёт расхода в budget-guard.**
Смотрим: попал ли расход в леджер.
Проверяем: наш guard спроектирован в кредитах — таблица `usage(provider, day, credits_used)`, тип `costOf(cap, args): CreditCost`, провайдер-агностичное хранилище `packages/core/src/cache/budget-store.ts:46-93`.
Провал: **MPP не отдаёт `credits_used` вообще** — единица учёта доллар/USDC.e, факт-списание приходит в `Payment-Receipt`/воучере, а не в теле ответа. Один вызов через MPP для guard'а невидим. До доработки guard'а с одной единицы (credits) до двух (credits | USD-onchain) любой MPP-трафик идёт мимо бюджета.

**11. Гигиена сессии и секретов.**
Смотрим: закрыта ли платёжная сессия и где лежит ключ.
Проверяем: `session.close()` в `finally`; MPP требует не API-ключ, а **горячий приватный ключ с живыми деньгами** (`PRIVATE_KEY` → `privateKeyToAccount`) и балансом USDC.e на Tempo, тогда как наш контур секретов — skill-local `.env` 0600 + zod.
Провал: незакрытая сессия держит депозит в эскроу до истечения канала; горячий кошелёк в общем `.env`-контуре — недопустимое расширение поверхности.

**12. Числа в отчёте.**
Смотрим: каждую цифру в тексте ответа.
Проверяем: байт-в-байт равенство с JSON-ответом API; никаких пересчётов и округлений в прозе.
Провал: цифра, которой нет в сыром ответе. Известный образец такого дефекта прямо в артефактах этого прогона: `mpp-challenge.json` содержит `currency: 0x20c0000000000000000000b9537d11c60e8b50` — **38 hex-символов, невалидный EVM-адрес** (настоящий, из base64 живого челленджа, — `0x20c000000000000000000000b9537d11c60e8b50`, 40 символов), а `amount: 10710` не воспроизводится ни на одном из 4 MPP-эндпоинтов (сегодня стабильно `4000000` / `1024000000` / `0`). Источник неизвестен → строку перепроверить либо пометить `unverified`.

## 3. Worked example: «сколько биткоина уже добыто»

### Есть ли данные в Dune
**unverified.** Ни одна проверка этого прогона не подтвердила наличие bitcoin-таблиц в Dune. Порядок действий, если всё-таки идти в Dune: сначала `POST /v1/datasets/search` (шаг 2.1), и только при резолве таблицы — искать готовый запрос. Тратить $4.00 резерва на execute до подтверждения существования таблицы — сжигание денег.

### Самый дешёвый корректный путь: не Dune
```
GET https://api.blockchair.com/bitcoin/stats  →  data.circulation   (в сатоши)
```
Стоимость — **1 request point** (в таблице Quick endpoint reference `/{:btc_chain}/stats` = 1). Живой замер 2026-07-27: `circulation = 2006198979155096` сат, `blocks = 959846`, `context.request_cost = 1`, `context.api.version = "2.0.95-ie"`. Против $1.00/МБ + $4.00 резерва в Dune это на порядки дешевле.

**Жёсткая оговорка по доступу.** Безключевой режим Blockchair практически мёртв: вендор дословно — «Last week we had to enforce blocking all API requests that didn't use an API key» (Blockchair.Support issue #1652, 2025-07-15). Живая репродукция 2026-07-27: ровно **2** успешных keyless-запроса, затем сплошной **HTTP 430** на весь IP, включая ранее работавший `/bitcoin/stats`, и бан держался **>15 минут**. Документированные 1440 req/day и 30 req/min связывающими **не являются**. Значит: путь надёжен только с платным ключом, и в любом случае — только как кэшируемый фоновый, никогда в горячем пути.

### Чем сверяем независимо (три пути, не один)
1. **Внутри вендора, другим кодовым путём:** `GET https://api.blockchair.com/bitcoin/blocks?a=sum(generation)` — канонический пример самой доки, ответ вида `{"sum(generation)":1800957104497237}`. Стоимость 2 points. Живьём в этом прогоне **не получен** — HTTP 430.
2. **Закрытой формулой:** эмиссия пересчитывается из высоты блока (`context.state`) по расписанию халвингов и сверяется с обоими числами.
3. **Вне вендора:** `bitcoin-cli gettxoutsetinfo`, поле `total_amount`, на собственной ноде.

Blockscout для этой задачи **непригоден в принципе**: среди 100 сетей нет ни Bitcoin, ни Solana (покрытие чисто EVM: 53 мейннета + 47 тестнетов, не-EVM = 0).

### Что считается «сошлось»
Эталон из живой проверки: `circulation` = `2006201166655096` сат = **20 062 011.67 BTC** против расчётной эмиссии на блоке `959853` = **20 062 043.75 BTC**. Дельта — **32.08 BTC**, то есть **0.00016 %**. Это и есть допуск: расхождение такого порядка — норма, а не дефект.

Второй эталон — про дрейф во времени: величина из подсказки `2 006 195 229 155 096` против живого замера `2 006 198 979 155 096` отличается на `3 750 000 000` сат = ровно `12` блоков × `3.125` BTC. Это **не ошибка**, а более ранний замер того же дня. Правило: сравнивать два замера supply можно только при равной `context.state`; иначе разница обязана раскладываться в целое число блоков × текущую награду.

### Ловушки
- **Emitted ≠ circulating.** `circulation` ≈ эмиссия **минус недобранные coinbase-награды**; именно этот класс и даёт дельту 32.08 BTC против формулы. Формула даёт «сколько положено по расписанию», API — «сколько реально начислено».
- **Потерянные монеты не вычитаются нигде.** Ни `circulation`, ни формула, ни `gettxoutsetinfo` не знают о потерянных ключах. Если вопрос был про «доступное предложение» — ни один из трёх путей на него не отвечает; это отдельный класс, и ответ на него — `unverified`.
- **UTXO-сет — третья величина.** `gettxoutsetinfo.total_amount` — сумма непотраченных выходов, а не эмиссия; непотратимые выходы и недобранные награды разводят эти числа. Использовать как независимую сверку — можно, приравнивать — нельзя.
- **Premine:** отдельно не верифицировался → `unverified`, в ответ не выносить.
- **Имя поля ломает код на EVM.** Формулировка «`GET /{chain}/stats` возвращает поле `circulation`» верна для bitcoin/ripple/stellar/monero/cardano, но **для ethereum поле называется `circulation_approximate` и это СТРОКА в wei**. Бланкетный парсер упадёт.
- **Единицы.** `circulation` — в сатоши. Любой перевод в BTC в прозе отчёта — это пересчёт, и он должен либо совпадать с уже верифицированной парой (`2006201166655096` ↔ `20 062 011.67`), либо не делаться вовсе.

### Итог по кейсу
Вопрос закрывается **одним GET за 1 point вне Dune**, с тройной независимой сверкой и известным допуском 0.00016 %. Идти за ним в Dune — архитектурная ошибка.

## 4. Worked example 2: сложный in-chain агрегат

### Вариант «дневной объём DEX по сетям» — единственный класс, где Dune незаменим

Обе бесплатные альтернативы **доказанно не отвечают**, и это проверено грепом, а не мнением:
- **Blockchair:** во всех `447 723` байтах документации `\bdex\b` = **0** совпадений, `swap` = 0, `uniswap` = 0, `liquidity` = 0, `amm` = 0. Эксплорер базового слоя, DEX-данных нет как класса — при любом тарифе.
- **Blockscout:** каталог `/stats-service/api/v1/lines` содержит **37** метрик (accounts, transactions, gas, contracts, user_ops…), из них DEX/swap/volume — **ноль**; в индексе API нет ни одного dex/swap/liquidity-эндпоинта. Плюс сервер вообще не считает агрегатов: «произвольных агрегатов/SQL нет».

Значит, маршрут — Dune, и только Dune.

**Путь.** Ветка A предпочтительна: `POST /v1/datasets/search` → `GET /v1/queries` → `GET /v1/query/{queryId}` → `POST /v1/query/{query_id}/execute`. Ветка B (keyless) требует собственного SQL, потому что чужой сохранённый запрос через MPP не исполняется.

**Корректность — сверх общего чек-листа:**
- Агрегировать на стороне SQL по (сеть × сутки). Дневная кросс-чейн сводка — это десятки строк, то есть доли мегабайта при тарифе «$1.00 per MB»; тянуть сделки построчно и суммировать у себя — прямой перерасход.
- Границу суток задать явно в UTC и одинаково для всех сетей; иначе «дневной объём» у каждой сети свой день (п.5 чек-листа — дефолты параметров).
- Определение объёма должно быть одно на все сети (п.6, decoded vs raw). Смешивать кураторский слой одной сети с самодельным разбором другой — значит сравнивать разные величины под одной шапкой.
- Двойной счёт: маршрутизаторы/агрегаторы порождают вложенные свопы. Признак провала — сумма по протоколам заметно выше суммы по пулам; если запрос это не оговаривает, определение неизвестно.

**Независимая сверка.** Бесплатного внешнего источника DEX-объёмов в этом прогоне **нет** (см. два грепа выше). Единственная доступная сверка — внутри Dune, вторым кодовым путём: тот же день и та же сеть, посчитанные по другой таблице/слою (метод из п.9 чек-листа). Следствие: **`confidence` для DEX-ответа не может быть `high`** — потолок medium, и это надо написать прямым текстом, а не умолчать.

**Деньги.** Резерв `$4.00` за execute + `$1024.00` за results при `suggestedDeposit` `$10.00` → сценарий `amount-exceeds-deposit` и `topUp` (inference, medium). Фактическая цена execute — **unverified**: Dune явно пишет, что не публикует единой per-query формулы.

### Вариант «распределение холдеров» — наоборот, из Dune уходим
Этот класс закрывается **бесплатно**: Blockscout `direct_api_call` с `endpoint_path = /api/v2/tokens/<addr>/holders`, живо проверен на USDC (`0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48`, `total_supply "50100656020032927"`, `circulating_market_cap "72452991023.6439"`), возвращает `items[]` с `address`/`value` и курсорную пагинацию `pagination.next_call`. Цена по `endpoint_pricing` (живой `https://api.blockscout.com/api/json/config`, 44 записи, значения {20,25,30,40,50,100,120,150,1000}) — `default` = **20** кредитов; Free-план даёт **100K credits/day · 5 RPS · All chains**.

Ограничения, которые обязаны попасть в ответ: агрегатов сервер не считает — суммы и доли собираем у себя постранично, при **5 RPS** длинный список холдеров медленный и кредитоёмкий; покрытие — **100** сетей, все EVM (53 мейннета, 47 тестнетов, 0 не-EVM). И: rich list по **нативной** монете (Blockchair `/{btc_chain}/addresses`, 10 UTXO-сетей + ethereum, сортировка `balance DESC`) — это **другой класс**, выдавать его за распределение холдеров ERC-20 запрещено.

## 5. Когда НЕ идти в Dune — правило маршрутизации

Идти в Dune **только** при выполнении всех трёх условий одновременно:
1. вопрос — агрегат / `GROUP BY` / временной ряд над декодированными данными (а не построчный факт);
2. он кросс-протокольный или кросс-сетевой;
3. класс доказанно отсутствует в обоих бесплатных источниках — доказанно означает грепом/каталогом, как в §4, а не «мне кажется».

Иначе — по таблице:

**Экономическое обоснование правила (числа проверены):** MPP по деньгам ≡ ровно Free-тариф Dune. Тождество: MPP `$1.00`/МБ ≡ Free `20 кредитов/МБ × $5.00/100 кредитов` = **$1.00/МБ (1.00×)**. Против Analyst `10 × $1.875/100` = `$0.1875`/МБ → MPP в **5.33×** дороже. Против Plus `2 × $1.596/100` = `$0.03192`/МБ → в **31.3×** дороже. То есть keyless-путь не только уже по функциям (4 операции из 47), но и самый дорогой за мегабайт. Он оправдан ровно одним: отсутствием аккаунта, ключа и карты.

**Чего MPP НЕ снимает:** `x-required-scope: Read` — это скоуп ключа, не план. Engine-гейт (на Free доступны не все классы движка) и rate-limit-гейт остаются. Какой engine-класс и какой rate-limit применяются к безаккаунтному MPP-трафику — **unverified**; документирован только IP-лимит **1000 rps**.

**Отдельно про Blockscout как бесплатный слой — два ограничения, влияющие на маршрут:**
- Анонс: «Starting July 20, 2026, all requests to the official public Blockscout MCP server will require a PRO API key for authorization» (issue #425). На 2026-07-27 принуждение не включено, но keyless — закрывающееся окно, а не контракт. Заводить бесплатный `proapi_`-ключ надо сразу.
- Битый ключ **не** откатывается на серверный: `proapi_bogus_test` → `401 Unauthorized`. Значит ошибка в конфиге = полный отказ capability, а не деградация.

## 6. Failure-режимы

### HTTP 402 — это не ошибка, а рукопожатие
Нормальный шаг протокола MPP. Алгоритм:
1. Прочитать `WWW-Authenticate: Payment, method="tempo", intent="session"` и base64-тело челленджа.
2. Сверить `amount` с ожидаемым (`4000000` / `1024000000` / `0`). Неожиданное значение — стоп и логирование, а не автоплатёж. Прецедент есть: `amount: 10710` из артефакта прогона сегодня не воспроизводится ни на одном из 4 эндпоинтов.
3. Сверить `currency` на длину **40** hex-символов. Прецедент дефекта: `0x20c0000000000000000000b9537d11c60e8b50` — 38 символов, невалидный адрес; правильный — `0x20c000000000000000000000b9537d11c60e8b50`.
4. Сравнить `amount` с депозитом. `$1024.00` резерва против `suggestedDeposit` `$10.00` → готовить `topUp`, иначе `amount-exceeds-deposit` (inference, medium).
5. `session.close()` в `finally` — иначе депозит заперт в эскроу до истечения канала.
6. Записать факт-списание из `Payment-Receipt`/воучера в отдельный USD-леджер: `usage(provider, day, credits_used)` этого расхода **не увидит**.

### HTTP 429 / 430 / 435 — троттлинг и баны, у каждого вендора свой характер
- **Dune:** документирован только IP-лимит **1000 rps**. Rate-limit конкретно для MPP-трафика — **unverified**. Поведение: экспоненциальный backoff, single-flight на одинаковый SQL, негативный кэш.
- **Blockscout:** Free — **5 RPS**. Keyless-трафик делит **один** серверный ключ оператора: живьём 3×`HTTP 429` из 12 параллельных `GET /v1/get_block_number?chain_id=1`, и 3×429 + 7×200 из 10. То есть без своего ключа троттлинг зависит от чужой нагрузки. Лечение — свой бесплатный `proapi_`-ключ, тогда 5 RPS становится персональным; `rateLimit: { capacity: 5, refillPerSec: 5 }` в существующий токен-бакет (`packages/core/src/net/rate-limit.ts:102-140`).
- **Blockchair:** код **430** «temporary blacklisted». Документированные 30 req/min и 5 req/s (ошибка 435) **не связывающие** — бан наступает после ~2 запросов, накрывает весь IP, включая cost-1 эндпоинты, и держится **>10 минут** (наблюдалось **>15**, верхняя граница не установлена → `unverified`). Лечение: долгий TTL (`packages/core/src/cache/ttl.ts:21` уже держит `'token.holders': 3600`), single-flight, негативный кэш на 430, обязательный fallback-провайдер и **алерт** — молчаливая деградация здесь самый вероятный режим отказа.
- Общее правило: **429/430 никогда не превращать в «данных нет»**. Это отказ доступа, а не отсутствие факта; в ответ идёт `unverified` + причина, не ноль.

### Пустой результат
Ноль строк — это гипотеза, а не ответ. Разделить три причины **до** публикации:
1. **Дефолт параметра сузил окно** — перепрогнать с явными параметрами (чек-лист п.5).
2. **Граница свежести** — верхняя граница данных ниже запрошенного диапазона; проверяется бесплатным `GET /v1/execution/{id}/status` и сверкой с тиком цепи (Blockscout `get_block_number`, `eth_blockNumber`).
3. **Не та таблица/слой** — перерезолвить через `POST /v1/datasets/search` (п.1–2).

Обязателен **контрольный зонд**: тот же запрос на заведомо непустом окне/сущности. Не прошёл зонд — дефект запроса, а не данных. Публиковать `0` без пройденного зонда запрещено.

### Устаревший запрос
Признаки: (а) последнее исполнение старое по `status`; (б) верхняя граница данных отстаёт от тика цепи; (в) SQL ссылается на слой/таблицу, которая больше не резолвится через `/v1/datasets/search`; (г) карточка запроса изменилась относительно нашего снимка при том же `query_id`.
Действия: **не** читать `GET /v1/query/{query_id}/results` как свежие данные — они вернут старый прогон. Нужен новый `execute`, и это платно ($4.00 резерв в MPP). Если бюджета нет — ответ помечается датой последнего исполнения и `confidence` понижается; выдавать старый прогон за текущий — дисквалификация.
Отдельно: сравнивая два прогона, требовать одинаковой точки привязки. Образец правильной сверки — расхождение supply, разложенное в `3 750 000 000` сат = `12` блоков × `3.125` BTC: разница объяснена, а не замазана.

### Ключа нет
1. **Сохранённые запросы недоступны, точка.** 43 из 47 операций не оплачиваются воучером; поиск (`/v1/queries`, `/v1/query/{queryId}`, `/v1/datasets/search`), materialized-views, uploads/CSV, dashboards, visualizations, pipelines, custom endpoints, `/v1/usage`, `cancel` — все вне MPP.
2. Остаётся **raw-SQL через MPP** — но это горячий приватный ключ с живыми деньгами (`PRIVATE_KEY` → `privateKeyToAccount`) и баланс USDC.e на Tempo. Цена приёма: расширить budget-guard с одной единицы учёта до двух, вынести кошелёк из общего `.env`-контура (наш стандарт — skill-local `.env` 0600 + zod), гарантировать `session.close()`.
3. Либо **уйти в §5** и закрыть вопрос бесплатно.
4. Либо **честно отказать**: «класс не покрывается доступными источниками». Подменять запрошенную метрику соседней (rich list вместо холдеров ERC-20, `circulation` вместо «доступного предложения») — запрещено: это ложь в матрице покрытия.

### Ловушки путей (проверенные 404/расхождения)
- `GET /v1/execution/:execution_id/csv` из доки → **HTTP 404 `{"error":"URL not found"}`**. Реальный путь — `/results/csv`.
- OpenAPI обещает резерв **$5.00** за execute — живой челлендж даёт **$4.00**.
- `GET /v1/execution/{id}/status` отсутствует в таблице доки, но существует и бесплатен.
- Общее правило: путь берём из `https://api.dune.com/openapi.json`, не из доки; при расхождении верим живому ответу и логируем расхождение как дефект вендора.

### Что помечено `unverified` и не подлежит домысливанию
`cost_per_execute_usd` (Dune явно не публикует единой per-query формулы), `mpp_rate_limit`, `mpp_engine_class`, `origin_of_amount_10710`, `results_reserve_semantics_1024MB` (inference, medium), наличие bitcoin-данных в Dune, действующая безключевая квота Blockchair, точная длительность бана 430, цены Premium Blockchair (`https://blockchair.com/api/plans` → HTTP 401 + QRATOR), фактическая дата принуждения ключа Blockscout, гашение Dune Sim (`https://dune.com/blog/sunsetting-sim` → HTTP 404, официальным постом claim не подтверждён).
