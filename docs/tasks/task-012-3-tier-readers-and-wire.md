# Задача 012-3 — четыре классификации платности становятся читателями `tier`; `tier`/`trust` не выходят на провод

**Эпики:** E-5 (`tier`, D8), E-6 (`trust`) · **Требования:** R-151, R-152, R-155 ·
**Критерии приёмки:** AC-14, AC-16 · **Фаза:** 3 из 10 · **Зависимости:** 012-2

## Use Case Connection

- **UC-9** — оператор читает `_meta.budget` платного тула: поле содержит `{provider,
creditsUsedToday}`, как и сегодня; `tier` не появляется в ответе нигде. Провал, который надо
  исключить: внутренняя классификация просачивается в проводной контракт, «потому что это же просто
  ещё одно поле».

<!-- contract:goal -->

## Цель задачи

Превратить четыре независимые классификации платности в **читателей одного поля** и доказать, что
ни `tier`, ни `trust` не пересекают границу проводного контракта.

Четыре места (§1.1 TASK.md, адреса проверены):

| Что                                               | Где                                                               |
| ------------------------------------------------- | ----------------------------------------------------------------- |
| `PAID_PROVIDER_IDS = new Set(['dune','nansen'])`  | `packages/core/src/cache/sqlite-store.ts:48`                      |
| bootstrap пишет всем `kind: 'unknown'`            | `packages/core/src/cache/budget-store.ts:263-272`, вставка `:266` |
| `BudgetMeta.provider: 'nansen'` — литеральный тип | `packages/mcp-server/src/tools/budget-meta.ts:9`                  |
| `costOf()` как де-факто сигнал платности          | каждый адаптер                                                    |

## Описание изменений

### Правки в существующих файлах

#### `packages/core/src/cache/sqlite-store.ts`

- Удалить `PAID_PROVIDER_IDS` (`:48`) вместе с его комментарием — комментарий объясняет
  существование множества, а множества больше нет.
- `bootstrapProviders` пишет `registration.tier` напрямую.
- **Четвёртый устаревший счётчик, того же коммита:** докстринг **этого самого метода** (`:147`)
  говорит «bootstrap from ALL **9** `adapterRegistrations`» — их **12**. Правится здесь, потому что
  здесь переписывается тело метода, который он описывает. (Три остальных — `providers.config.ts:125`
  и `mcp-server/src/index.ts:69`/`:74` — в 012-2.)

#### `packages/core/src/cache/budget-store.ts`

- `bootstrapProviders` (`:263-272`) перестаёт писать литеральный `'unknown'` (вставка `:266`) и
  пишет `registration.tier`.
- **Второе предложение того же докстринга (`:138-140`) — НЕ мусор, а описанный анти-клоббер,
  и снимается оно С ОБЪЯСНЕНИЕМ.** Сегодня там сказано: `DO NOTHING` (в отличие от
  `SqliteCacheStore`) стоит затем, чтобы бюджет-сторож, сконструированный поверх файла, который
  кеш-сторож уже классифицировал верно, **не затёр** классификацию значением `'unknown'`. После
  этой задачи основание исчезает: **оба писателя выводят одно и то же значение из одной и той же
  регистрации**, затирать нечем. Формулировку про anti-clobber пометить **упразднённой, с причиной**,
  а не просто удалить — иначе диф читается как снятие защиты.
- **И одновременно меняется пункт конфликта — иначе правка не достигает ни одной существующей
  строки.** Сегодня это `ON CONFLICT (id) DO NOTHING` (`:267`). Кеш-стор (`sqlite-store.ts:152-153`)
  пишет `ON CONFLICT (id) DO UPDATE SET kind = excluded.kind, notes = excluded.notes`.
  С сохранённым `DO NOTHING` каждая **уже существующая** строка `providers` остаётся `'unknown'`
  навсегда, а тесты на свежей `:memory:` БД проходят. Такая проверка не падает ни на одном входе,
  тогда как пункт плана 3.5 требует доказанного падения на временном нарушении. Форма приводится к форме
  кеш-стора: `ON CONFLICT (id) DO UPDATE SET kind = excluded.kind`.
- Комментарий класса «Why this bootstrap upsert writes `kind: 'unknown'`» (и ссылающийся на него
  докстринг метода) удаляется **вместе с кодом**: его основание — «нельзя было хардкодить `'nansen'`
  в этом файле» — исчезло. Комментарий, оставшийся без своей причины, описывает поведение, которого
  в коде уже нет.
- Оба стораджа теперь пишут **одно и то же** значение из **одной и той же** регистрации; сегодня
  они пишут разное и не могут этого обнаружить. Добавить тест на согласие двух писателей.

#### `packages/mcp-server/src/tools/budget-meta.ts` — точка внедрения №2 (§0.3)

**Проблема, найденная ревью Архитектуры:** `budgetMeta(budgetStore, now)` (`:34-37`) **не принимает
провайдера** и хардкодит `getUsage('nansen')` / `provider: 'nansen'`. Рантайм-assert «значение
принадлежит множеству платных id» на такой функции не падает ни на одном входе: проверяемое
значение — константа `'nansen'`, и она принадлежит множеству при любой реализации.

**Решение задачи — протянуть отвечавшего провайдера:**

```ts
export interface BudgetMeta {
  provider: string; // id платного адаптера, который РЕАЛЬНО ответил
  creditsUsedToday: number;
}

export async function budgetMeta(
  budgetStore: BudgetStore | undefined,
  now: () => number,
  providerId: string,
): Promise<BudgetMeta | undefined>;
```

- Значение уже есть у всех трёх вызывающих — `outcome.cache.provider`:
  `smart-money-flows.ts:116`, `token-risk.ts:108`, `entity-label.ts:170`.
- Проверка: `providerId` обязан принадлежать
  `adapterRegistrations.filter(r => r.tier === 'paid').map(r => r.id)`. **Не принадлежит →
  `undefined`**, а не бросок: та же доктрина «видимость никогда не роняет успешный вызов», что уже
  действует для двух существующих путей деградации (`budgetStore` не инжектирован; `getUsage()`
  бросил). Проверка перестаёт быть тавтологией — она может провалиться на свободном адаптере,
  ответившем по будущему маршруту с фолбэком.
- `getUsage('nansen', …)` → `getUsage(providerId, …)`.
- **Тип `provider` расширяется до `string`, а не до union'а по платным id.** Причина названа
  архитектурой (M6): `adapterRegistrations` экспортируется как обычный мутабельный
  `AdapterRegistration[]`, и TypeScript расширяет `id` до `string`. Вывод литерального union'а
  потребовал бы перетипизации самого массива (`as const satisfies …`). Радиус этой перетипизации —
  `SqliteBudgetStoreOptions.providers`, сиблинг у `SqliteCacheStore`, все обобщённые потребители —
  эта задача его не берёт. ADR-002 D8 называет дефектом **сам факт** литерального типа
  («классификация протекла в систему типов») — производный, но всё ещё литеральный union перенёс бы
  протечку, а не убрал её.
- **Проводная форма не меняется:** `{provider: 'nansen', creditsUsedToday: N}` сериализуется
  идентично. `e2e.inprocess.test.ts` (`:738`, `:770`, `:796`, `:817`) проходит без правок.

#### `packages/core/test/budget-velocity.test.ts` — **новый объём, найденный ревью плана**

Три фикстуры регистраций — `:33`, `:137`, `:394` — написаны как

```ts
[{ id: PROVIDER, hosts: ['api.nansen.ai'], rateLimit: { rps: 1 } }] as never;
```

**Каст `as never` глушит компилятор**, поэтому обязательный `tier` из 012-2 их **не ломает на
сборке**. Поломка приезжает **сюда, в рантайм**: как только `bootstrapProviders` начинает биндить
`registration.tier` в `providers.kind` — а колонка объявлена `TEXT NOT NULL` (`cache/ddl.ts:51`) —
better-sqlite3 отказывается биндить `undefined`.

- Фикстурам даются настоящие значения: `id` здесь nansen ⇒ `tier: 'paid'`, `trust: 'authoritative'`.
- **`as never` удаляется**, а не сохраняется с дописанными полями: именно каст спрятал поломку на
  задачу вперёд, и оставить его — значит оставить механизм, который спрячет следующую.
- **`registration.tier ?? 'free'` в `bootstrapProviders` ЗАПРЕЩЁН.** Отсутствующий `tier` обязан
  быть **ошибкой фикстуры**, а не значением, подставленным без диагностики.

  **Why.** Этот способ делает прогон зелёным и возвращает домысленное умолчание, против которого
  написаны R-150(c) («`tier` не выводится и не угадывается») и UC-8.

#### `costOf()` каждого адаптера — **не трогается**

Четвёртое место закрывается не правкой `costOf`, а тем, что **ничто больше не выводит платность из
его значения**. `costOf` остаётся механизмом цены.

### Grep-гейты (по образцу существующих doc-гейтов)

1. **Второй классификации платности не осталось** (R-151e). Гейт сканирует `packages/core/src` и
   `packages/mcp-server/src`.
   **Предикат — «множество/массив/проверка вхождения по id провайдера, решающая ПЛАТНОСТЬ»,
   а НЕ «строка `'nansen'`».** Гейт ищет: `new Set([...ids])` / массив id / `.includes(id)` /
   `id === '…'`, чей результат ведёт к `kind`/`tier`/`paid`. Падение называет файл и строку.

   **Why.** Первая редакция гейта запрещала литерал `'nansen'` вне аллоу-листа и падала бы на
   корректном коде. После 012-3 литерал законно остаётся в пяти местах: `providers.config.ts:80`,
   `:93`, `:106` (маршруты — `adapterIds: ['nansen']`), `:270` (`id:` самой регистрации) и
   `mcp-server/src/index.ts:102` (ключ карты адаптеров). Ни одно из пяти не классифицирует
   платность — это **имена в маршрутизации**. Аллоу-лист по путям не нужен: `budget-gate.ts` лежит
   **внутри** `adapters/nansen/` и покрыт любым каталожным исключением, а перечисление путей вместо
   предиката снова ловило бы имена.

2. **`.trust` читается ровно в одном месте** (R-155d) — валидаторе из 012-2. Регекс `\.trust\b`;
   литералы `trust: '…'` под него не попадают, поэтому 12 регистраций гейт не задевают.
   **Корни скана — только `packages/core/src` и `packages/mcp-server/src`, БЕЗ `test`.**

   **Why.** Соседний гейт на `nonEmpty` (012-6) сканирует **и** `src`, **и** `test`, а TC-UNIT-05
   из 012-2 читает `.trust` **по замыслу**: при скане тестов гейт упал бы на собственном тесте
   задачи. R-155(d) говорит про потребителей в продовом коде, поэтому границу фиксируем здесь, а не
   наследуем от соседа.

### Структурный тест по 13 тулам (R-152b)

- Обход **ключей** на любой глубине вложенности: входные и выходные схемы всех 13 тулов (источник —
  реестр `toolSpecs` либо замороженный `test/fixtures/tools-list.snapshot.json`) плюс зафиксированные
  ответы `e2e.inprocess`, включая `_meta.cache` и `_meta.budget`.
- **Сканируются КЛЮЧИ, а не подстроки текста.**

  **Why.** Слово «tier» законно встречается в прозе описаний (например, ярусы цены
  `entity.labels`). Подстрочный скан упал бы на таком тексте, а починка свелась бы к
  переписыванию описания — то есть гейт правил бы контракт вместо того, чтобы его охранять.

- Запрещённые ключи: `tier`, `trust`. Точное совпадение.

### Фазы

- **Фаза 1:** структурный тест и оба grep-гейта написаны и прогнаны на **нетронутом** `src/`.
  Структурный обязан быть **зелёным** уже сейчас: полей на проводе нет. Grep на `.trust` обязан

  **красным**: `PAID_PROVIDER_IDS` жив. Красный гейт и есть предмет Фазы 2.
- **Фаза 2:** четыре места становятся читателями; все гейты зелёные.

## Тест-кейсы

### Юнит

- **TC-UNIT-01** — `SqliteCacheStore.bootstrapProviders` пишет `kind = 'paid'` для `nansen`/`dune` и
  `'free'` для остальных десяти, читая `registration.tier`, а не собственный список.
- **TC-UNIT-02** — `SqliteBudgetStore.bootstrapProviders` пишет то же самое; ни одна строка
  `providers.kind` не остаётся `'unknown'`.
- **TC-UNIT-02a** — про МИГРАЦИЮ существующей строки, а не про пустую таблицу. Механика прописана
  пошагово.

  **Why.** На `:memory:` каждое соединение получает **свою** пустую БД, поэтому засев до
  конструирования недостижим. На файловой БД таблицы `providers` не существует, пока какой-нибудь
  конструктор не выполнил `CACHE_DDL`.

  Порядок:
  1. временный файл БД по уже используемому в этом же файле паттерну
     (`mkdtempSync(path.join(tmpdir(), …))` — `budget-velocity.test.ts:132-137`);
  2. создать таблицы — прогнать **`CACHE_DDL` напрямую** на этом файле. **Не «сконструировать
     первый сторож»:** конструктор `SqliteBudgetStore` выполняет `db.exec(CACHE_DDL)` (`:178`) **и
     сразу** `bootstrapProviders(...)` (`:180`), поэтому строка `nansen` уже существует, и обычный
     `INSERT` на шаге 3 упадёт на `TEXT PRIMARY KEY`. Либо DDL напрямую, либо засев через
     `ON CONFLICT (id) DO UPDATE`;
  3. **засеять** через отдельное соединение `better-sqlite3`:
     `INSERT INTO providers (id, kind, notes) VALUES ('nansen','unknown',NULL)` и такую же строку
     для свободного адаптера; закрыть соединение;
  4. сконструировать `SqliteBudgetStore` под тестом — `kind` обязан стать `'paid'`/`'free'`.

  С сохранённым `ON CONFLICT … DO NOTHING` тест падает. Засев обязателен: на свежей БД TC-UNIT-02
  проходит при **любом** пункте конфликта.

- **TC-UNIT-03** — два писателя согласны: на одном и том же массиве регистраций оба стораджа дают
  идентичное содержимое `providers.kind` — **включая случай уже существующих строк** (тот же засев).
- **TC-UNIT-03a** — `budget-velocity.test.ts` конструирует сторож с настоящими `tier`/`trust`
  без `as never`; ни одного `undefined` не доходит до биндинга `TEXT NOT NULL`.
- **TC-UNIT-04** — `budgetMeta(store, now, 'nansen')` → `{provider: 'nansen', creditsUsedToday: N}`.
- **TC-UNIT-05** — `budgetMeta(store, now, 'blockscout')` → `undefined` (свободный адаптер), и
  `getUsage` **не вызывался**. Это тот случай, который делает проверку нетавтологичной.
- **TC-UNIT-06** — оба существующих пути деградации по-прежнему дают `undefined`: сторадж не
  инжектирован; `getUsage()` бросил.

## Критерии приёмки

- [ ] `PAID_PROVIDER_IDS` удалён; оба `bootstrapProviders` читают `registration.tier`; комментарий
      про `'unknown'` удалён вместе с кодом, который он объяснял
- [ ] Пункт конфликта бюджет-стора приведён к форме кеш-стора
      (`ON CONFLICT (id) DO UPDATE SET kind = excluded.kind`); TC-UNIT-02a **засевает** строку
      `'unknown'` до конструирования и доказывает, что она мигрирует — а не проверяет пустую таблицу
- [ ] Три фикстуры `budget-velocity.test.ts` несут настоящие `tier`/`trust`, **`as never`
      удалён**; в `bootstrapProviders` **нет** `?? 'free'` и никакого иного умолчания для `tier`
- [ ] `budgetMeta()` принимает отвечавшего провайдера; проверка членства в платном множестве может
      провалиться (доказано TC-UNIT-05); не-платный провайдер даёт `undefined`, а не бросок
- [ ] `BudgetMeta.provider: string`; проводная форма `{provider, creditsUsedToday}` не изменилась
- [ ] `costOf()` не тронут ни в одном адаптере
- [ ] Оба grep-гейта и структурный тест зелёные; каждый **проверен на падение** (временное нарушение →
      красный → откат), а не только на зелёный
- [ ] Полный набор гейтов §0.5 плана зелёный; диф снимка тулов пуст

## Заметки

- **Линия разреза, если цикл затянется** (задача выросла на пункт плана 3.2a): пункты плана **3.1–3.2a**
  (оба стораджа + фикстуры `budget-velocity`) отделяются от пунктов плана **3.3–3.6** (`budgetMeta` + гейты).
  Разрез проходит по границе пакетов: первая половина трогает только `packages/core/src/cache/*`
  и его тесты, вторая — только `mcp-server` и сторожа; ни одна не оставляет вторую красной.
- Расширение `provider` до `string` — не послабление: ADR-002 D8 называет дефектом сам литеральный
  тип. Точность возвращается рантайм-проверкой на границе, где значение впервые становится
  известным, а не типом, который пришлось бы поддерживать перетипизацией всего массива регистраций.
- `trust` в этой задаче **не приобретает потребителя** — задача, наоборот, ставит сторожа, который
  падает, если он появится.
