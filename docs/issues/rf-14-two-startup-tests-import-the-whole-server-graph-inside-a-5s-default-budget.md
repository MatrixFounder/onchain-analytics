# RF-14 — два стартовых теста импортируют весь граф сервера внутри дефолтного бюджета 5 с, и один раз это кончилось таймаутом

**Что.** `TC-INT-01` и `TC-INT-05` — единственные два теста репозитория, которые вызывают
`await import('../src/index.js')` внутри тела теста. Импорт тянет трансформацию всего графа
`packages/mcp-server/src` плюс `@onchain-intel/core`, и делает это внутри дефолтного
`testTimeout` vitest, равного 5000 мс: своего `testTimeout` в конфигурации нет.

**Наблюдено один раз, 2026-08-26.** Оба теста упали по таймауту в прогоне с
`transform 59.34 s / import 99.86 s` — против `transform 12.02 s / import 41.38 s` в нормальном.
Сьют показал `2 failed | 916 passed`, и ни одна строка падения не относилась к предмету теста:
оба сообщения были `Test timed out in 5000ms`. В обычном полном прогоне каждый из этих тестов
занимает **394 мс**, то есть запас к бюджету двенадцатикратный.

**Причина НЕ установлена.** Первая редакция этой записи объясняла падение нагрузкой на машину.
Объяснение не выдержало собственной проверки и заменено перечнем того, что удалось исключить.

| Попытка воспроизведения                       | Результат                                  |
| :-------------------------------------------- | :----------------------------------------- |
| изолированный прогон двух файлов              | 530 мс, зелено                             |
| холодный кэш трансформации                    | `transform 17.60 s`, зелено                |
| холодный кэш плюс двенадцать процессов `yes`  | `import 59.28 s`, зелено                   |
| полный корневой `pnpm test`, дважды           | зелено                                     |
| **восемь ядер, занятых на 100 %**             | **зелено** — см. ниже                      |

Последняя строка выяснилась постфактум и весит больше остальных. Попытка воспроизведения через
восемь busy-loop'ов оставила их работать: `kill $LOADPIDS` не сработал, потому что `LOADPIDS`
собирался как `$(jobs -p)` — в подоболочке, у которой нет таблицы заданий родителя. Восемь
процессов крутились на 100 % CPU три часа десять минут при `load average` около 15, и **все
прогоны сьюта этого периода, включая гейты этапа 1, прошли зелёными**. То есть машина с восемью
занятыми ядрами эти два теста не роняет.

**Что остаётся верным.** Бюджет 5000 мс — дефолт vitest, выбранный под тест, который что-то
считает. Здесь он покрывает трансформацию всего графа сервера, и стоимость этой трансформации
не зависит от предмета теста. Запас двенадцатикратный, но взят наощупь, а не измерением. На CI
кэш трансформации холодный всегда, а раннеры делятся между задачами.

**Почему запись остаётся открытой при неизвестной причине.** Падение было настоящим и красило
сьют на два теста, чьи утверждения к падению отношения не имели. Гейт, краснеющий по причине,
которую никто не может назвать, дальше перезапускают вместо того, чтобы читать, — это стоило
проекту RF-3 и RF-11. Развилка ниже закрывает следствие независимо от того, будет ли когда-нибудь
названа причина.

**Область.** Развилка, решать при исполнении:

1. Объявить этим двум тестам собственный `testTimeout` (порядка 30 с) — стоимость нулевая,
   зелёный прогон не замедляется, потому что таймаут не тратится, когда тест укладывается.
2. Прогревать граф один раз в `beforeAll` вне бюджета теста — точнее, но требует, чтобы
   `vi.resetModules()` в `beforeEach` не сбрасывал прогрев, а он сбрасывает.

Первая дешевле и не трогает то, что тесты проверяют. Выбор — за исполнителем, с записанным
обоснованием.

**Чего запись НЕ утверждает.** Что тесты неверны: оба ловят свои мутанты и в изоляции проходят
за 530 мс на двоих. Дефект в бюджете, а не в утверждениях.

**Приёмка.** Полный `pnpm test`, запущенный одновременно с посторонней нагрузкой, сравнимой с
измеренной здесь (`import` порядка 100 с), проходит зелёным; или у обоих тестов есть
объявленный бюджет, размер которого обоснован измерением, а не дефолтом.
