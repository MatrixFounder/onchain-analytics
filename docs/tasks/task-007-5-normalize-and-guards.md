## Task Goal

Превратить вендорский документ в канонический результат — и отказать **до записи в кэш** всюду, где

## Changes Description

### Изменения в существующих файлах

#### `packages/core/src/adapters/defillama/index.ts`

Экспортируемый интерфейс результата:

```ts
export interface DexVolumeResult {
  chain: string; // НАШ слаг
  name: string; // НАШЕ отображаемое имя из реестра
  window: { fromMs: number; toMs: number; days: number };
  series: { ts: number; volumeUsd: number }[]; // ts — epoch-ms UTC
  points: number;
  gapDays: number;
  totals: {
    h24: number | null;
    d7: number | null;
    d30: number | null;
    d1y: number | null;
    allTime: number | null;
  };
  truncated: { series: boolean; reason: string };
  source: string; // 'defillama'
  fetchedAt: number; // возраст ДОКУМЕНТА (из 007-4)
}
```

**Порядок проверок в `normalizeDexVolume` — он же порядок важности:**

1. **Эхо-сверка (R-68a).** `body.chain` должно строго равняться запрошенному
   `chain.vendors['defillama']`. Не равно → бросить с обоими значениями в сообщении.
   Без этой проверки «вендор отдал другую сеть» и «на этой сети нет объёмов» — одно и то же
   наблюдение: путь name-толерантен, незнакомая сеть даёт **HTTP 500**, а сеть вне активного набора —
   **HTTP 200 с нулями**.
2. **Окно.** `toMs` = последняя точка ряда, приведённая к epoch-ms; `fromMs = toMs - (days-1)*86_400_000`.
   Точки вне окна отбрасываются — это **не** усечение (см. п. 6).
3. **Единицы времени (R-67b).** Вендор даёт `date` в **unix-секундах** → `ts = date * 1000`
   (DB-SCHEMA §1.2: время только epoch-ms UTC). Не-целое, отрицательное или заведомо нереальное
   (до 2009-01-03 либо больше `fetchedAt + сутки`) → отбраковка **всей** точки, а не её починка.
4. **Значения (R-68b).** `volumeUsd` не-конечное или отрицательное → бросить **до** `cache.set`.
   Иначе кэш запомнит сломанное значение, а схема тула отвергнет его уже после записи — ровно то,
   что `defillama.normalize` уже предотвращает для `tvlUsd`.
5. **Разрывы (R-67c).** `gapDays` = число суточных шагов, отсутствующих **внутри** окна.
   Ряд не сшивается и не интерполируется: пропуск — измерение, а не дефект рендера.
6. **Усечение (R-67d).** `truncated.series = true` **только** если сработал жёсткий кап
   `MAX_SERIES_POINTS = 1825`, а не когда окно просто короче ряда. Флаг обязан значить «вы получили
   не то, что просили», иначе он превращается в украшение, которое всегда `true`.
7. **Агрегаты (OQ-1).** `total24h/7d/30d/1y/AllTime` → `totals.*`, каждый `number | null`.
   Отсутствующий ключ — `null`, **никогда** `0`: у сети вне активного набора часть ключей просто
   отсутствует, и `0` был бы выдуманным числом вместо отсутствующего.
8. **Вендорский текст (R-68e).** В результат не попадает **ни одна** вендорская строка: `chain`/`name`
   берутся из **нашего** реестра, `source` — литерал. Карточки `protocols` (`name`, `category`,
   `methodology`, `logo` — редактируемый третьей стороной текст) не читаются вовсе.

## Test Cases

### Unit-тесты (`packages/core/test/defillama-dex-volume.test.ts` — расширить)

1. **TC-UNIT-01** (**AC-1**) — фикстура + `days: 92` → `points === 92`, `gapDays === 0`, каждый `ts`
   кратен 86 400 000 и делится нацело, соседние точки отстоят ровно на сутки.
2. **TC-UNIT-02** — `ts` первой точки равен `date * 1000` из фикстуры (секунды → миллисекунды
   действительно применены, а не просто скопированы).
3. **TC-UNIT-03** (**R-68a**) — документ с `chain: "Solana"` при запросе `Base` → отказ; сообщение
   содержит **оба** имени.
4. **TC-UNIT-04** — фикстура `dexs-empty-chain` (узкий набор ключей) → `totals.d1y === null`,
   а не `0`; вызов не падает.
5. **TC-UNIT-05** — точка с отрицательным `volumeUsd` → отказ **до** кэша.
6. **TC-UNIT-06** — точка с `NaN`/`Infinity` → отказ.
7. **TC-UNIT-07** — точка с не-целой/нереальной датой отбрасывается, остальные сохраняются.
8. **TC-UNIT-08** — ряд с выколотыми сутками в середине окна → `gapDays === 1`, точек на одну меньше,
   ряд **не** сшит.
9. **TC-UNIT-09** — окно короче ряда → `truncated.series === false` (обычная нарезка усечением не является).
10. **TC-UNIT-10** — ряд длиннее `MAX_SERIES_POINTS` → `truncated.series === true` и непустой `reason`.
11. **TC-UNIT-11** (**R-68e**) — в JSON результата нет ни одной строки из карточек `protocols`
    фикстуры (проверяется поиском по сериализованному результату).
12. **TC-UNIT-12** — отказ `normalize` негативно кэшируется (детерминированный отказ), а отказ
    `fetch` — нет. Существующий контракт `registry.ts`; тест фиксирует, что новая capability ему следует.
