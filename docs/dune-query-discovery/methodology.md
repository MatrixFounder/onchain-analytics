## §1. Что считалось кандидатом

**Кандидат = СПОСОБ ДОСТУПА, а не компания.** «Dune» — не одна строка, а минимум пять:
исполнить чужой запрос · прочитать закешированный результат чужого запроса · создать/форкнуть свой ·
найти нужный запрос · взять готовое знание о данных (Spellbook/каталог). У каждого своя цена, своё
плановое гейтирование и свой вердикт. Семейства (`family`): `dune-access` · `dune-discovery` ·
`dune-authoring` · `dune-catalog` · `dune-sdk` · `alt-free`.

## §4. Отбор в профилирование: квоты по семействам

Профилируется top-K **внутри каждого семейства**, а не глобально:

```
QUOTA = { 'dune-access': 16 (= args.maxCandidates), 'dune-discovery': 4,
          'dune-authoring': 3, 'dune-catalog': 3, 'dune-sdk': 3, 'alt-free': 6 }
```

Порядок внутри семейства: `seed_priority` (убыв.) → имя (по алфавиту, для устойчивости).
Всё, что не влезло, логируется поимённо через `log()` и перечислено в отчёте.
**Это поправка №2, внесённая В ПРОГОНЕ** — см. §7, дефект Д-2.

## §5. Формула ранжирования (аддитивная; считает КОД, не агент)

```
fit = access(0–3) + free_fit(0–3) + coverage(0–2) + verifiability(0–2) + integration(0–2)   → 0..12
```

| Под-скор | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| `access` | только web-UI / скрапинг | community-обёртка | документировано, но гейтится планом | официальный API/MCP на free |
| `free_fit` | платно-только | маргинально (<30 вопросов/мес) | достаточно (≥100/мес) | полностью бесплатно/keyless |
| `coverage` | одна метрика | узкий, но глубокий класс | произвольные агрегаты по многим сетям | — |
| `verifiability` | чёрный ящик | метод описан, не воспроизводим | метод/SQL читается и сверяется независимо | — |
| `integration` | нужна новая подсистема | умеренная новая машинерия | ложится на существующие адаптер/кэш/бюджет | — |

**Жёсткие оверрайды — в КОДЕ, поверх сырого скора** (`applyVerify()` в скрипте воркфлоу):

1. `is_scrape` ⇒ `reject`.
2. `lifecycle ∈ {sunset:*, archived, deprecated}` ⇒ вердикт не выше `reference` + строка в
   «Мёртвое/гаснущее».
3. `plan_gate == paid-only` или `free_fit == 0` ⇒ не выше `reference`.
4. Нет `primary_url` ⇒ не выше `reference`, `confidence ≤ medium`.
5. `refuted == true` ⇒ не выше `reference`.
6. Пустой `kill_shot` ⇒ строка `UNVERIFIED`, в рекомендации не идёт.

Каждое сработавшее понижение записано в `code_overrides` строки и напечатано в отчёте.

## §6. Adversarial-протокол

- **Разделение ролей:** профиль пишет один агент, убивает — другой, с прямой задачей опровергнуть.
- **Контракт данных, а не «настрой»:** `refutation_attempted`, непустой `kill_shot`, `refuted`.
  Из 46 строк: `CONFIRMED` — 40, `REFUTED` — 6, `UNVERIFIED` (пустой kill-shot) — 0. Непустой kill-shot у 46/46 строк.
- **Два доказательства** на каждый не-reject кандидат: позитивное (где первоисточник заявляет
  возможность) и дисквалификатор (доказательство отсутствия анти-паттерна) — разные проверки.
- **Строгость составного утверждения:** скептик раскладывает вывод строки на под-утверждения
  (`subclaims`) и метит каждое CONFIRMED/REFUTED/UNVERIFIED; составное CONFIRMED только если все
  материальные под-утверждения подтверждены. Именно это правило поймало ключевую поправку прогона
  (см. `verification-corrections.md`, В-1).
- **Loop-until-dry:** `dryRounds = 2` подряд пустых раундов, потолок `maxRounds = 3`.
  Дедуп против множества `seen` (всё встреченное, включая отклонённое), не против `confirmed`.
  **Остановка произошла по потолку раундов, а не по сухости** (`dry_rounds_at_stop = 0`) — поле не
  исчерпано, третий раунд принёс ещё 163 просмотренных кандидата.
- **Completeness-critic** перед синтезом: покрытие по каждому Q1–Q11, пропущенные кандидаты,
  непроверенные решающие ячейки, biases.
- **Follow-up:** потолок `maxFollowups = 3`; критик предложил 3, выполнено **2** — третья остановлена
  классификатором безопасности (предлагала регистрацию аккаунта Dune, см. §7 Д-5).
- **Дополнительный слой — оркестратор.** Три решающих первоисточника перепроверены вручную вне
  агентского контура (инвентарь MCP, гейт `execute-query`, доставка `dune.com/pricing`) — результаты
  в `verification-corrections.md` §О.

## §8. Как собран отчёт (детерминированно)

Агенты пишут **только прозу** (`_prose/*.md`). Мастер-таблицу, таблицу «мёртвое/гаснущее»,
reject-лог, приложение, раздел источников и KNOWN LOSSES собирает КОД из `table.json`:

```
node docs/dune-query-discovery/build-report.mjs
```

Числа в markdown поэтому байт-в-байт равны JSON — они из него и берутся. Обрезается **только
проекция** (пороги: ячейка таблицы 150 символов, поле-эссе 700, блок приложения 6500); каждая
обрезка посчитана и агрегирована в §10 отчёта.

## §9. Смещения и границы применимости

1. **По Dune не сделано ни одного живого вызова** — в окружении нет `DUNE_API_KEY`, а заводить
   аккаунт агентам запрещено. Вся Dune-часть — доковая. Это главное ограничение.
2. **`dune.com/pricing` и `dune.com/blog/*` не отдаются краулеру** (JS-рендер/антибот) ⇒ часть
   тарифных чисел взята из `docs.dune.com/learning/how-tos/pricing-faqs`, а не со страницы цен.
3. **Первоисточник Dune противоречит сам себе** по плановому гейту Query-эндпоинтов
   («Analyst plan or higher» против «Available on Plus and Enterprise plans») — противоречие
   зафиксировано, не разрешено.
4. **Вендор отказывается публиковать формулу стоимости кредита** дословно ⇒ бюджет free-контура
   принципиально не моделируется до первого живого замера.
5. **Перекос в сторону Dune по построению**: квота `dune-access` 16 против 6 у `alt-free`, что
   отражает постановку («исследование про Dune»), но недооценивает ширину бесплатной обоймы.
   Частично компенсировано добивочным прогоном.
6. **Числа дрейфуют.** Дата актуальности — 2026-07-27. Тарифы, лимиты и состав тулов вендора
   меняются; перепроверять перед любой тратой.

## §10. Каденция и инварианты сравнения

- **Перепроверять раз в квартал** либо немедленно при изменении тарифов/планов Dune.
- **Инварианты для сравнимости прогонов:** оси свипов (§2), `args.date`, формула fit и пороги (§5),
  набор вопросов Q1–Q11, ключ дедупа, квоты семейств. Сравнивать только по пересечению строк.
- **Что должно измениться в следующем прогоне:** ключ дедупа нормализует эндпоинт (Д-3);
  `lifecycle`/`plan_gate` принудительно приводятся к enum на уровне схемы (Д-7); при наличии
  `DUNE_API_KEY` включается режим живых зондов, и все `unverified`-ячейки Dune становятся
  проверяемыми.
