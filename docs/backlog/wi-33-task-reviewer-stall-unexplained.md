# WI-33 — Стойло `task-reviewer` на 600 с осталось без объяснения

> Отщеплено при закрытии [[wi-29-600-bash]]. Это **не** дубликат: у WI-29 механизм доказан и
> починен, здесь механизма нет.

**Сигнал.** В прогоне `/vdd` по T-011 (2026-08-02) встали два субагента по 600 с: `critic-security`
в цикле 3 и **`task-reviewer` в цикле 1**. Оба лечились перезапуском.

**Что установлено при закрытии WI-29.** Для `critic-security` причина найдена и закрыта: read-only
роль, скилл требует сканер, а контракт execution-evidence отсутствовал на пути `/vdd` →
`vdd-adversarial`. Для `task-reviewer` та же гипотеза **не подходит**:

- `System/Agents/03_task_reviewer_prompt.md` не предписывает запуск ни одного скрипта;
- оба его TIER-1 скилла (`skill-requirements-analysis`, `skill-task-review-checklist`) — тоже;
- греп по `python3` во всех одиннадцати ролях без Bash не даёт ничего, адресованного этой роли.

То есть наблюдаемая половина сигнала объяснена, вторая — нет.

**Почему это стоит держать открытым.** Закрытая карточка не собирает рецидивы. Ровно этот довод
записан в теле WI-29 против того, чтобы селить оба случая в уже закрытой WI-7 — и он применим к
самой WI-29 в отношении второго случая.

**Направление 1 — ПОДТВЕРЖДЕНО в инструкциях (состязательный цикл, 2026-08-03).**
Гипотеза «TIER-0 `skill-session-state` предписывает скрипт роли без Bash» проверена и верна:
`.agent/skills/skill-session-state/SKILL.md` §3 говорит «**WHENEVER** … you **MUST** immediately
follow it with a call to the `update_state.py` script» и приводит команду `python3 …`, а
`skill-safe-commands` перечисляет её как безопасную к запуску. `03_task_reviewer_prompt.md` §2
грузит этот скилл как ALWAYS ACTIVE, при том что `.claude/agents/task-reviewer.md` объявляет
`tools: Read, Grep, Glob`. Это в точности механизм из `skill-parallel-orchestration` §2.4 — тот же,
что доказан для `critic-security`, только инструмент другой.

**Почему запись всё равно остаётся открытой.** Подтверждено *присутствие противоречия в
инструкциях*, а не *воспроизведение стойла*. Правка уже внесена во фреймворк (в §3 добавлена
развилка «а можешь ли ты вообще исполнять», трём враппер-ревьюерам дописана строка про read-only),
но пока не было прогона, который показал бы, что `task-reviewer` больше не встаёт. Пока такого
прогона нет, закрывать нечего.

**Что при проверке НЕ подтвердилось.** Вторая половина той же находки — «промпт велит роли записать
файл `docs/reviews/task-{ID}-review.md`, а Write у неё нет» — снята: каждый
`.claude/agents/*-reviewer.md` уже переопределяет это («Do NOT write … yourself — the orchestrator
persists if needed»). Правка не требовалась.

**Остаётся непроверенным.** Стойло могло быть не связано с инструментами вовсе (длинный вход, обрыв
на стороне рантайма) — тогда это вопрос устойчивости, смежный с закрытой WI-7 (resume), но не
тождественный ей. Два объяснения не исключают друг друга.

**Acceptance.** Прогон `/vdd`, в котором `task-reviewer` отрабатывает без стойла **после** внесённой
правки — с указанием, сколько прогонов это подтвердили. Либо, если встанет снова, — воспроизведение
с диагностикой, показывающей, на чём именно.
