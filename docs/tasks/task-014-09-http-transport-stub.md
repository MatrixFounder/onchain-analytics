# Задача 014.09: второй транспорт в `index.ts` `[STUB]`

## Связь со сценариями
- UC-1 — n8n вызывает способность по сети

<!-- contract:goal -->

## Цель задачи

Добавить Streamable HTTP как второй транспорт, сохранив stdio без единой правки в его пути.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `packages/mcp-server/src/transport/http.ts` — поднятие транспорта, стаб сессий
- `packages/mcp-server/test/e2e.http.test.ts` — сквозной тест по HTTP

### Изменения в существующих файлах

**Файл `packages/mcp-server/src/index.ts`:**
- Выбрать транспорт по настройке; умолчание — stdio
- Не менять сигнатуру `createServer`
- Оставить stdio-режим запускающимся без поднятого HTTP-сервера

**Файл `packages/mcp-server/src/server.ts`:**
- Сигнатуру `createServer` не менять

**Why сигнатура не меняется.** Она — точка, через которую собираются все зависимости, и её правка
задевает каждый вызывающий. Транспорт выбирается снаружи неё.

<!-- contract:tests -->

## Тест-кейсы

### Сквозные тесты
1. **TC-E2E-01:** вызов тула по HTTP возвращает тот же ответ, что по stdio
   - Входные данные: `onchain_ping` и `onchain_list_chains` с равными аргументами
   - Ожидаемый результат: ответы совпадают (AC-1)
2. **TC-E2E-02:** `e2e.stdio.test.ts` проходит без правок (AC-2)

### Модульные тесты
1. **TC-UNIT-01:** stdio-режим не поднимает слушателя порта
2. **TC-UNIT-02:** снимок `tools/list` не изменился

### Регрессионные тесты
- Полная сьюта; правка снимка `tools/list` требует обоснования в коммите

<!-- contract:acceptance -->

## Критерии приёмки
- [ ] AC-1: ответы по HTTP и stdio совпадают при равных аргументах
- [ ] AC-2: `e2e.stdio.test.ts` и снимок `tools/list` без правок
- [ ] stdio-режим запускается без поднятого HTTP-сервера
- [ ] `createServer` сохранил сигнатуру

## Примечания

Аутентификация, периметр и сессии на этой задаче ещё стабы. Слушатель принимает соединение без
проверки токена. Задача 014-12 закрывает этот путь, и до неё сетевой профиль не запускается вне
теста.

Тесты `e2e.http.test.ts`, написанные здесь, описывают путь без проверки токена. После 014-12 такого
пути нет, поэтому AC-1 и AC-2 переутверждаются там на аутентифицированном пути. Обязательство
записано в задаче 014-12.
