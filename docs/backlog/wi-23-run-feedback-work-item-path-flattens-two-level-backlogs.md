# WI-23 — путь `work-item` в `run-feedback` несовместим с двухуровневым бэклогом

> **✅ ВЫПОЛНЕНО 2026-07-30 правкой в `agentic-development` (TASK 091).** Принят **вариант 1**, с
> вариантом 2 как гарантией на легаси-пути. Сверено по `git diff` в том репозитории, а не по тексту
> предложения.
>
> **Что именно легло.** `feedback_lib/ledger_backlog.py` переписан: новая `file_work_item()` пишет
> **файл записи** `docs/backlog/<slug>.md` (frontmatter контракта + тело **дословно**) и **одну**
> строку-указатель после якоря — лочкстеп с откатом, create-only, ID `WI-<n>` = max+1 по каталогу
> записей (терпим к «грязным» вида `WI-8X`). Якорь резолвится **до** любой записи, поэтому
> бэклог без якоря даёт exit 4 и **ноль** записанных файлов. Отсутствующий `BACKLOG.md`
> засеивается из нового шаблона (якорь сохраняется). `--dry-run` показывает ID, путь записи и
> точную строку индекса.
>
> **Вариант 2 сохранён там, где он и нужен** — `backlog_layout: "flat"` (явный opt-in для
> однофайлового бэклога) теперь **отказывается** от тела, которое пришлось бы схлопнуть
> (>1 непустой строки или >300 символов), вместо тихого схлопывания. Вариант 3 (документировать
> ручное заведение) **не** принят.
>
> **Конфиг этого репозитория править не понадобилось.** Схема осталась `v1`; новые ключи
> (`backlog_dir: docs/backlog`, `backlog_prefix: WI`, `backlog_layout: index+files`) аддитивны, и их
> значения по умолчанию совпадают с раскладкой, которую здесь и так вели руками. Проверено живьём:
> `doctor` → `ready: true`, `backlog_layout: index+files`, `backlog_dir_exists: true`; пробный
> `file --as work-item --dry-run` в этом репозитории показал `WI-24`,
> `docs/backlog/wi-24-…md` и однострочный указатель — тело с таблицей в индекс не попало.
>
> **Заодно устранён источник расхождения, а не только его следствие.** Дублировался не реестр, а
> механика формата: `known-issues-format` (v1.0 → **2.0**) теперь описывает механику тонкого
> индекса **один раз** и параметризует её по реестру (defects / work-items), а
> `check_contract_sync.py` сверяет с ней **оба** шаблона — расхождение стало exit 1, а не надеждой
> на ревью. Реестры при этом остались **разными файлами**: `KNOWN_ISSUES.md` читает Analysis-фаза
> каждого прогона и `/heal-issues`, словари статусов разные, а сам триаж построен на различении
> defect/work-item.
>
> **Гейты:** 138 unit-тестов (было 116) + E2E green, 45/45 валидация скиллов, contract-sync 0 (и 1
> на внесённом дрейфе). Фреймворк догфудит контракт: его собственный плоский `docs/BACKLOG.md`
> переведён в индекс + `docs/backlog/wi-1-*.md`.

> **Изменение поведения общего фреймворка — на рассмотрение владельцу**, не готовая правка.
> Скилл живёт в репозитории `agentic-development`; закрывается правкой ТАМ
> (`resolved_by: framework edit (agentic-development)`), а не здесь.

**Что наблюдалось.** В ретро TASK-009 три work-item'а пришлось завести руками:
`feedback_lib/ledger_backlog.py` умеет только `append_work_item` — дописать буллет в индекс — и
**никогда не создаёт файл записи**. Содержимое `--body-file` при этом **схлопывается в одну строку**
и вливается в индекс целиком: `--dry-run` показал буллет на ~1 800 символов с таблицей, свёрнутой в
строку.

**Почему это дефект, а не особенность.** `docs/BACKLOG.md` этого проекта документирует ровно
противоположное — индекс плюс `docs/backlog/wi-N-slug.md` на запись — и объясняет, **почему**: одна
запись однажды выросла до 7 849 символов в одном буллете, и её «нельзя было ни прочитать, ни
отдиффать, ни закрыть по частям». То есть скрипт производит ровно ту форму, ради устранения которой
конвенция и появилась. Соседний путь того же скилла — issues — двухуровневость уже реализует
(`known-issues-format`: индекс + `docs/issues/<id>-slug.md`, лочкстеп enforced). Расходятся два пути
одного скилла.

**Обобщённо, без привязки к этому стеку:** если целевой реестр — это ИНДЕКС над файлами записей, то
аппендер, пишущий только строку индекса, для него не механизм заведения. Он либо теряет тело, либо
делает индекс нечитаемым, и в обоих случаях молча.

**Варианты:**

1. Научить путь `work-item` тому же лочкстепу, что уже есть у пути issues: `--body-file` → файл
   записи, а в индекс — короткая строка-указатель.
2. Дать конфигу распознавать двухуровневую раскладку и **отказываться** вместо тихого схлопывания —
   отказ честнее, чем испорченный индекс.
3. Ничего: документировать, что для двухуровневых бэклогов work-item заводится руками (то, что
   пришлось сделать здесь).

**Рекомендация — вариант 1**, с вариантом 2 как минимумом: сегодня единственный сигнал о
несовместимости — это `--dry-run`, который **надо догадаться прочитать целиком**. Красный флаг
самого скилла «сначала всегда `--dry-run`» здесь и спас, и это стоит отметить: механизм сработал.

**Связано:** [RF-2](../issues/rf-2-m2-evidence-records-drifted-from-the-shipped-commit.md) — не
дубликат (там дрейф evidence), совпадение по общим словам в заголовке.

## Закрыто 2026-07-30 владельцем фреймворка — сверено по репозиторию, а не по памяти о предложении

Правка приземлилась в `agentic-development` (TASK 091, v3.21.4/v3.21.5, коммит `4b2a65e`, далее
ужесточена в `a5afe1b`/`f116252`). **Приняты оба варианта, а не один:**

- **вариант 1** — `ledger_backlog.py` переписан на тот же лочкстеп, что у пути issues: запись-файл +
  строка-указатель, create-only, откат при сбое, якорь резолвится до первой записи;
- **вариант 2** — плоская раскладка теперь **отказывается** принимать тело, которое пришлось бы
  схлопнуть, вместо тихого схлопывания. В докстринге модуля назван и повод: одна вписанная запись
  однажды достигла 7 849 символов в одном буллете;
- сверх предложенного: `known-issues-format` поднят до **v2.0** и параметризован на два реестра
  (defects / work-items) с единым описанием механики «индекс над записями», плюс
  `check_contract_sync.py` гейтит расхождение по каждому реестру.

**Обобщение, которое просила запись, принято дословно:** «аппендер, пишущий только строку индекса,
не является механизмом заведения для реестра-индекса над записями».

**Чего в предложении не было и что оказалось важнее.** Правка прошла два раунда адверсариального
ревью с **четырьмя воспроизведёнными эксплойтами** (инъекция во frontmatter, подделывающая
`auto_fixable`; инъекция строки индекса, вклинивающая поддельный указатель; переход по симлинку
через `exists()` на висячей ссылке; побег конфигурации, нацеливающий реестр на `CLAUDE.md`). Второй
раунд нашёл, что первый закрыл **протестированные полезные нагрузки, а не классы**. То есть
исходная запись описывала потерю данных, а реальная поверхность включала запись не туда, куда
сказано, — этого я не увидел.

**Конфигурацию здесь править не понадобилось** — новые ключи аддитивны и по умолчанию совпадают с
нашей раскладкой (формулировка владельца в индексе).

**Проверено в этом репозитории 2026-07-30:** `doctor` сообщает `backlog_layout: index+files`,
`--dry-run` показывает корректный файл записи с frontmatter, и следующий id выделен как **WI-24** —
то есть новый инструмент прочитал наши рукописные WI-20…WI-23 и совместим с ними. Переоформлять
заведённые вручную записи не требуется.
